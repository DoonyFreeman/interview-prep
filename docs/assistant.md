# Чат по урокам

В `/assistant` можно открыть диалог, задать вопрос по урокам или попросить
подобрать темы из очереди повторения. Из урока можно сразу открыть чат с
его контекстом. Под ответом отображаются ссылки на найденные разделы.
История слева показывает название и последнее сообщение пользователя.
На телефоне панель открывается кнопкой в заголовке чата. Поиск работает по
названиям и коротким фрагментам. Из истории можно переименовать или удалить чат.
Ассистент продолжает отвечать, если в это время открыть другой диалог.
В чате видно, когда помощник ищет урок, читает раздел или формирует ответ.
Текст поступает частями от GigaChat. Ответ со ссылками появляется в истории
после сохранения.

Чтобы задать предпочтение для новых диалогов, напиши «Запомни: отвечай коротко,
с примером». Новая заметка заменяет предыдущую. Команды «Что ты обо мне
помнишь?» и «Забудь всё обо мне» показывают и удаляют эту заметку.

## Локальная настройка

1. Установи зависимости из `backend/requirements.txt` в окружение проекта.
2. Из корня репозитория скачай зафиксированную версию токенизатора и INT8-модели
   и собери индекс одной командой:

   ```sh
   PYTHONPATH=backend backend/.venv/bin/python scripts/assistant_prepare_index.py
   ```

   Скрипт проверяет размер и SHA-256 каждого файла. Уже проверенные файлы
   используются повторно. Если файлы скачаны заранее, передай `--source-dir`
   с `tokenizer.json` и `onnx/model_int8.onnx`.

3. Заполни `GIGACHAT_CREDENTIALS` в конфигурации backend и включи `ASSISTANT_ENABLED=true`.
   `GIGACHAT_CA_FILE` принимает путь к доверенному CA-файлу, если API требует
   сертификаты Минцифры. Проверка TLS включена. При наличии `BRAVE_SEARCH_API_KEY`
   в чате появляется переключатель веб-поиска.
4. Из корня репозитория открой два терминала. В одном запусти backend командой
   `cd backend && .venv/bin/uvicorn app.main:app`. В другом запусти
   `cd frontend && npm ci && npm run dev`. Войди в тестовый аккаунт и открой
   [чат](http://localhost:5173/assistant).

Для VPS готовые `lessons.sqlite3`, `tokenizer.json` и `onnx/model_int8.onnx`
размещаются в каталоге `assistant` на существующем томе `app-data`. Индекс и
модель можно подготовить на Mac. При обновлении уроков сначала пересобери
индекс из того же `content/`. Поиск проверяет совпадение версий материалов и
файлов модели. Backend загружает ONNX при первом поиске и использует один поток
для инференса. Одновременно выполняется один ход агента на процесс backend.
На аккаунт отводится до 10 новых запросов за пять минут. Повтор доставки уже
сохранённого ответа не расходует лимит.

LangGraph хранит контрольные точки в `langgraph.sqlite3` рядом с индексом.
Путь можно переопределить через `ASSISTANT_PERSISTENCE_PATH`. Заметка аккаунта
хранится в основной базе SQLite и доступна во всех его диалогах.

## Оценка поиска и ответов

```sh
PYTHONPATH=backend backend/.venv/bin/python scripts/assistant_retrieval_eval.py \
  --index backend/data/assistant/lessons.sqlite3 \
  --model-dir backend/data/assistant/e5 --split dev \
  --output /tmp/iprep-assistant-dev.json
```

Отчёт сопоставляет BM25, E5 и RRF при 20 и 40 кандидатах и `k=10,30,60`.
Начальная конфигурация использует 40 кандидатов BM25, 20 кандидатов E5 и
`k=10`. После слияния выбираются пять разных разделов. Цель для поиска —
Recall@5 от 0,80 на отложенных вопросах. Сначала сравни варианты на `dev`,
зафиксируй параметры и запусти `--split test --rrf 40 20 10` для этого варианта.

Предварительный локальный прогон с официальными весами E5 в FP32 дал Recall@5
0,8333 на `dev` и 0,7963 на повторном прогоне `test`. В `test` сравнение
показало 0,6481 у BM25 и 0,7963 у E5. Гибрид нашёл 0,9630 нужных разделов
в объединении кандидатов до отсечения топ-5. Целевой замер запускается с тем
же ONNX INT8, который будет использовать сервер.

Для проверки ответов доступны только публичные вопросы из
[набора оценки](../backend/tests/fixtures/assistant_retrieval_eval.json).
Перед запуском задай `GIGACHAT_CREDENTIALS` и `EVAL_GEMINI_API_KEY` в окружении
терминала. Оценщик использует отдельную модель Gemini и получает публичные
фрагменты уроков, которые агент действительно видел при генерации. Чтобы
проверить подключение на одном вопросе, используй `--split dev --limit 1`.
Полный тестовый прогон:

```sh
PYTHONPATH=backend backend/.venv/bin/python scripts/assistant_answer_eval.py \
  --index backend/data/assistant/lessons.sqlite3 \
  --model-dir backend/data/assistant/e5 --split test \
  --output /tmp/iprep-assistant-answers.json
```

Для GigaChat с отдельным доверенным CA передай `--ca-file`. Для нового отчёта
указывай свободный путь в `--output`.

Faithfulness — доля утверждений, подтверждаемых увиденными фрагментами.
Фактическая правильность — F1 по фактам эталона, с учётом лишних и пропущенных
утверждений. Цель для обеих метрик — от 0,80. Случаи без источников, где от
агента ожидается отказ от ответа, и сбои провайдеров считаются отдельно.

## Какие данные обрабатываются

- SQLite хранит историю, ссылки и список выполненных инструментов. Диалог
  доступен только владельцу. Удаление диалога удаляет сообщения и контрольные
  точки из рабочих баз. Резервные копии SQLite могут содержать более раннюю
  историю. При входе по старому токену чат попросит заново авторизоваться.
- GigaChat получает текущий вопрос, ограниченный контекст того же диалога и
  найденные отрывки. Если ты сохранил заметку, GigaChat получает её как
  контекст для ответа. При явном вопросе о том, что повторить, ответ
  инструмента содержит названия тем из очереди текущего пользователя.
- В индекс входят тексты уроков. Приватные ответы HR и закрытые блоки решений
  исключены. Сервис поиска работает с готовым индексом и локальной моделью E5.
- Brave получает поисковую фразу из текущего сообщения при включённом для
  этого сообщения переключателе. История и очередь повторения в поисковый
  запрос не добавляются.
