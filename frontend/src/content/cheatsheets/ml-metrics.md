## Матрица ошибок

**Классификация** выбирает категорию; **регрессия** предсказывает число с размером ошибки. Macro/micro/weighted F1 — про классы; MAE/MSE/RMSE/R² — про числовые прогнозы. Score срочности ещё не делает классификатор регрессией.

Строки — **Fact (факт)**, столбцы — **Pred (предсказание модели)**. Positive (класс 1) — срочная заявка:

| Fact / Pred | Срочная: Pred = 1 | Обычная: Pred = 0 |
|---|---:|---:|
| Срочная | TP = 8 | FN = 2 |
| Обычная | FP = 4 | TN = 86 |

TP — нашли срочную; FP — обычную ошибочно назвали срочной; FN — срочную пропустили; TN — обычную верно оставили обычной.

**Проверка:** TP + FP + FN + TN = 100 заявок. Настоящих срочных: TP + FN = 10. Обычных: FP + TN = 90. Поэтому **TN = 90 - FP = 86**, а не количество пропущенных срочных.

**Fact не меняется при выборе порога.** Меняется Pred: кого модель назовёт срочным. Проверяйте подписи осей: в другой таблице их могут поменять местами.

## Accuracy, Precision, Recall и F1

N - всего заявок; P - precision; R - recall. Все четыре метрики: **больше - лучше, 1 = 100%** (но полезность зависит от цены ошибок).

| Метрика | Формула | Пример | Вопрос |
|---|---|---:|---|
| Accuracy | (TP + TN) / N | 94% | Как часто правы вообще? |
| Precision | TP / (TP + FP) | 8/12 ≈ 66,7% | Доверять тревогам? |
| Recall | TP / (TP + FN) | 8/10 = 80% | Сколько срочных нашли? |
| F1 | 2PR / (P + R) | 72,7% | Каков их баланс? |

**Precision:** среди названных срочными сколько настоящих? Берём **столбец Pred = 1**, включая FP. **Recall:** среди всех настоящих срочных сколько нашли? Берём **строку Fact = 1**, включая FN. Precision = 100% означает FP = 0; Recall = 100% означает FN = 0, если знаменатели ненулевые.

**F1 = 2TP / (2TP + FP + FN)** — гармоническое среднее: слабую составляющую трудно скрыть сильной. F1 не учитывает TN и цену ошибок. При редком классе «всегда обычная» даёт высокий Accuracy и нулевой Recall. Нулевой знаменатель требует явного соглашения.

## Порог и цена ошибки

Правило: **positive, если score ≥ t**. Score не обязательно калиброванная вероятность. На фиксированных scores снижение порога расширяет положительные предсказания: TP и FP не убывают, FN уменьшается или остаётся прежним. Recall не убывает; Precision может меняться в обе стороны.

**Порог и ранжирование — разные вещи.** При прежних scores смена t меняет TP/FP/FN/TN и Precision/Recall, но **не ROC-AUC и AP**: выбираем другую точку на прежних кривых. Срочная со score 0,8 выше обычной с 0,2; при t=0,9 обе будут обычными, при t=0,5 срочную найдём. Порядок верный в обоих случаях.

Цена = FP × цена ложной тревоги + FN × цена пропуска. При ценах 1 и 20 наш ущерб: 4 + 40 = 44. Порог выбирают по цене или ограничению, например Recall ≥ 90%, на **validation**; **test** оставляют для финальной оценки.

**Как посчитать нагрузку.** Из 1 000 заявок 20 срочных, значит обычных 1 000 - 20 = 980. Пусть TPR = 0,8, FPR = 0,05. TPR умножаем на срочные, FPR - на обычные.

TP = 20 × 0,8 = 16; FN = 20 - 16 = 4. FP = 980 × 0,05 = 49; TN = 980 - 49 = 931. Очередь = TP + FP = 65 уведомлений. Precision = 16/65 ≈ 24,6%. Требование «recall ≥ 0,8 и не более 50 уведомлений» не выполнено: полнота подходит, бюджет превышен. Всегда проверяйте оба условия.

**AP: простой пример перед PR-кривой (§05).** Оценивает, насколько рано находим настоящие positive в списке по убыванию score. Без одинаковых scores: складываем Precision при каждой находке positive и делим на число всех настоящих positive.

**Простой пример:** срочная → обычная → обычная → срочная. Находки на местах 1 и 4: Precision = 1/1 и 2/4. **AP = (1 + 0,5)/2 = 0,75.** Обычные учитываются в знаменателе следующей находки. Каждая находка даёт прирост Recall = 1/2, поэтому общая формула даёт то же: (1/2)×1 + (1/2)×0,5 = 0,75.

**ROC-AUC сравнивает пары; AP учитывает Precision при находках.** При редком positive высокая ROC-AUC не гарантирует мало ложных тревог: смотрите PR/AP.

## ROC и ROC-AUC

**Меняем порог t, а не scores.** Если score ≥ t, предсказываем 1. Одна точка - один порог; левее и выше лучше.

**Пример из видео:** 9 объектов — 6 срочных, 3 обычных. Scores и классы показаны на графике; правило score ≥ t.

![Оценки девяти объектов: фиолетовый - настоящий класс 1, оранжевый - класс 0; линия порога 0,54. Ниже ROC по тем же данным с отмеченными отсечками.](/cheatsheet-media/ml-roc-thresholds.svg#500x380)

**X = FPR = FP/3; Y = TPR = Recall = TP/6.** Делим FP на 3 настоящих negative, TP - на 6 настоящих positive.

| t | TP | FP | FPR | TPR |
|---:|---:|---:|---:|---:|
| > 1 | 0 | 0 | 0 | 0 |
| 1 | 1 | 0 | 0 | 1/6 |
| 0,84 | 4 | 0 | 0 | 4/6 |
| 0,54 | 4 | 1 | 1/3 | 4/6 |
| 0 | 6 | 3 | 1 | 1 |

**t=0,54:** TP=4, FP=1, FN=2, TN=2; точка (1/3; 4/6). Нулевые scores включаем вместе при t=0. На кривой - все уникальные scores, в таблице - выбранные пороги.

**ROC-AUC - площадь под ROC; тоже можно считать трапециями.** Здесь (12 побед + 4 равенства × 0,5)/18 пар = **7/9 ≈ 0,778**. Сравниваем score срочной и обычной: 1 - идеальный порядок, 0,5 - случайный в ожидании. Не Accuracy; нужны оба класса.

## Precision-Recall и Average Precision

**Те же данные, те же пороги; другие оси. X = Recall = TP/(TP+FN); Y = Precision = TP/(TP+FP).** Recall - какую долю класса 1 нашли; Precision - какая доля наших тревог верна.

![PR-кривая для тех же девяти объектов: Recall по X, Precision по Y, точки соответствуют порогам 1, 0,84, 0,54 и 0; стартовая точка 0,1 техническая.](/cheatsheet-media/ml-pr-thresholds.svg#500x300)

| t | Recall | Precision |
|---:|---:|---:|
| > 1 | 0 | Не определена* |
| 1 | 1/6 | 1/1 |
| 0,84 | 4/6 | 4/4 |
| 0,54 | 4/6 | 4/5 |
| 0 | 6/6 | 6/9 |

**t=0,54:** точка (Recall; Precision) = (2/3; 0,8). При t=0: Recall=1, Precision=2/3 — нашли всех, но треть тревог ложная.

***Без тревог Precision не определена:** знаменатель 0. Точка (Recall=0; Precision=1) добавлена только для начала графика, а не как оценка качества.

**Общая формула: AP = Σ (Recallᵢ - Recallᵢ₋₁) × Precisionᵢ.** Σ — сложить шаги; умножаем прирост Recall на Precision после шага. Равные scores включаем группой. Для девяти объектов выше: **AP = (4/6)×1 + (2/6)×(6/9) = 8/9 ≈ 0,889**.

**PR-AUC по трапециям:** ширина по Recall × средняя высота Precision; вертикали дают 0. Здесь **41/45 ≈ 0,911**, а AP ≈ 0,889: разные способы расчёта. Указывайте метод; это не процент верных ответов.

Пунктир — доля positive: 6/9. Сравнивайте PR/AP на одних данных: доля классов влияет на оценку.

## Micro, macro и weighted

**Где применяют.** В бинарной классификации два класса (спам / не спам); в многоклассовой - три и больше (кошка / собака / птица). Усреднение применимо в обоих случаях: каждый класс рассматривают как «этот класс против остальных». В многометочной задаче у объекта несколько меток - усреднять тоже можно.

**Когда усреднение не нужно.** В бинарной задаче часто важен один positive, например спам: считают его Precision, Recall и F1 отдельно, без усреднения с «не спамом».

Пусть F1ᵢ - F1 класса i, nᵢ - число его настоящих объектов (**support**), K - число классов, N - сумма nᵢ. **Σ означает «сложить по всем классам».**

| Способ | Формула для F1 | Когда выбирать |
|---|---|---|
| Macro | Σ F1ᵢ / K | Каждый класс одинаково важен, включая редкий |
| Weighted | Σ (nᵢ × F1ᵢ) / N | Нужно учесть реальную частоту классов; редкий может скрыться |
| Micro | 2ΣTP / (2ΣTP + ΣFP + ΣFN) | Нужен общий итог по решениям; сначала складываем счётчики |

**Пример.** Из 6 кошек все найдены; из 4 собак две названы кошками. Для кошек TP=6, FP=2, FN=0; F1=12/14≈0,857. Для собак TP=2, FP=0, FN=2; F1=4/6≈0,667.

Macro = (0,857 + 0,667)/2 ≈ **76,2%**. Weighted = (6 × 0,857 + 4 × 0,667)/10 ≈ **78,1%**. Micro: сумма TP=8, FP=2, FN=2; 16/(16+2+2) = **80%**.

**Запомнить:** macro - классы поровну; weighted - по численности; micro - общие счётчики. Macro-F1 усредняет готовые F1, а не средние P и R. Только при **одной метке на объект и учёте всех классов** micro-P = micro-R = micro-F1 = Accuracy. Для нескольких меток или части классов равенство не гарантируется.

## MAE, MSE и RMSE

**Регрессия предсказывает число**, например время в минутах. **Размер промаха** - разница между прогнозом и фактом без минуса. Например, прогноз 18, факт 20: промах 2 минуты. Прогноз 22 при факте 20 - тоже промах 2 минуты.

**MAE = сумма размеров промахов / число заявок.** Показывает, на сколько минут в среднем ошиблись по модулю.

**MSE = сумма квадратов промахов / число заявок.** Сначала квадрат каждой ошибки, затем среднее. Большие промахи влияют сильнее. Единицы - минуты².

**RMSE = √MSE.** Берём квадратный корень из MSE, чтобы результат снова был в минутах. Большие промахи по-прежнему влияют сильнее.

Для всех трёх **меньше - лучше; 0 - идеально**. Разницу со знаком просто усреднять нельзя: +2 и -2 дадут 0, хотя в обоих случаях прогноз неточен.

**Пример по шагам:** факт [10, 20, 30], прогноз [12, 18, 40]. Всего 3 заявки.

| Факт | Прогноз | Размер промаха | Квадрат промаха |
|---:|---:|---:|---:|
| 10 | 12 | 2 | 2² = 4 |
| 20 | 18 | 2 | 2² = 4 |
| 30 | 40 | 10 | 10² = 100 |

**MAE = (2 + 2 + 10) / 3 = 14/3 ≈ 4,67 мин.**

**MSE = (2² + 2² + 10²) / 3 = (4 + 4 + 100) / 3 = 36 мин².**

**RMSE = √36 = 6 мин.**

Если один промах вырос с 2 до 20, его размер вырос в 10 раз, а квадрат - с 4 до 400, в 100 раз. Это изменение одного слагаемого, а не множитель всей метрики: остальные промахи тоже участвуют в расчёте. При одинаковых данных и весах RMSE ≥ MAE.

Эти метрики одинаково оценивают промах на 2 минуты вверх и вниз. Если недооценка дороже переоценки, отдельно проверяйте направление ошибок.

## R² и базовый прогноз

**R² сравнивает модель с прогнозом «всем среднее» по квадратам промахов.** 1 - идеально; **0 - не лучше прогноза средним**, ниже 0 - хуже. Это не доля верных прогнозов и не минуты.

**R² = 1 - (сумма квадратов промахов модели / сумма квадратов промахов прогноза средним).** Для краткости первую сумму называют SSE, вторую - SST.

**Среднее фактов = сумма фактических значений / число заявок.** Базовый прогноз выдаёт всем это среднее.

**Шаг 1. Среднее фактов:** (10 + 20 + 30) / 3 = 20. Базовый прогноз: [20, 20, 20].

**Шаг 2. С чем сравниваем?** Ошибки простого способа: 20 - 10 = 10; 20 - 20 = 0; 20 - 30 = -10. Их квадраты: 100, 0, 100. **SST = 100 + 0 + 100 = 200.**

**Шаг 3. Ошибки модели.** Для прогноза [12, 18, 40] выше получены квадраты 4, 4, 100. **SSE = 4 + 4 + 100 = 108.** В формуле сравниваются суммы, без деления на число заявок.

**Шаг 4. Не забыть «1 -»:** 108/200 = 0,54 — оставшаяся доля ошибки. **R² = 1 - 0,54 = 0,46** — сумма квадратов ошибок уменьшилась на 46% относительно среднего. Не «46% прогнозов верны».

**R² = 0,8 не гарантирует приемлемую ошибку.** Если MAE = 30 минут при допустимых средних 5, модель не подходит. R² — сравнение со средним; MAE/RMSE — размер ошибки. Для требования «ни один промах не больше 5» одного MAE недостаточно.

**R² = -0,3:** сумма квадратов ошибок на 30% больше, чем у прогноза средним. Отрицательной ошибки в минутах здесь нет. R² разных наборов напрямую не сравнивайте: меняется разброс фактов.

При постоянной цели SST = 0, обычная формула не определена; библиотечная подстановка - отдельное соглашение. Среднее оцениваемых фактов нужно для расчёта R². Реальный прогноз для новых заявок строят по train, без знания будущих ответов.

## Как выбрать метрику

**Сначала определите тип ответа модели.**

| Задача / требование | Что смотреть |
|---|---|
| Категория; доверять тревогам | Precision |
| Категория; меньше пропусков | Recall |
| Баланс Precision и Recall | F1; цену ошибок проверить отдельно |
| Каждый класс одинаково важен | Macro F1 |
| F1 с учётом частоты классов | Weighted F1 |
| Общие TP, FP и FN классов | Micro F1 |
| Качество списка по score | ROC-AUC и PR/AP; не выбранный порог |
| Число; средний размер ошибки | MAE в рублях, минутах и т. п. |
| Число; большие ошибки особенно нежелательны | RMSE в исходных единицах; MSE в квадратных |
| Число; лучше ли прогноза средним | R² вместе с MAE/RMSE |

**Сначала ограничения, потом лучший результат.** Если команда проверяет максимум 50 тревог, вариант с 100 не подходит даже при лучшем Recall. Выберите максимальный Recall среди допустимых порогов.

**Ответ ментору:** тип задачи → positive и ошибки → знаменатель метрики → ограничение → числовой пример. В наборе из 99 обычных и 1 срочной заявки высокий Accuracy ещё не означает пользу. Ошибка 2 → 20 увеличивает вклад в MSE в 100 раз, в MAE — в 10 раз. Модель и порог подбирайте на validation, затем проверяйте на отложенном test без утечки.
