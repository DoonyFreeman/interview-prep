# Dunder-методы: протоколы Python

> Цель урока: понять, что «магические» методы (`__repr__`, `__eq__`, `__len__`,
> `__iter__`, …) — это **протоколы**, через которые ваши объекты встраиваются в
> синтаксис языка. Знание ключевых dunder'ов и разницы `__repr__`/`__str__` —
> признак того, что человек умеет писать «питоничные» классы.

## __repr__ и __str__

Два метода строкового представления, и их постоянно путают:

- **`__repr__`** — **однозначное, для разработчика** представление; в идеале
  такое, что `eval(repr(obj))` воссоздаст объект. Показывается в REPL, отладчике,
  при печати контейнеров. Должен быть **всегда**.
- **`__str__`** — **читаемое, для пользователя** представление (для `print`,
  `str()`). Если не задан, используется `__repr__`.

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"   # однозначно, для отладки
    def __str__(self):
        return f"({self.x}, {self.y})"            # красиво, для пользователя

p = Point(1, 2)
str(p)        # "(1, 2)"          — __str__
repr(p)       # "Point(x=1, y=2)" — __repr__
[p]           # [Point(x=1, y=2)] — контейнеры используют __repr__
```

Правило: если пишете только один — пишите **`__repr__`** (он покрывает и отладку,
и fallback для `str`). Хороший `__repr__` экономит часы отладки.

**Аналогия.** `__repr__` — это технический паспорт детали (точные характеристики,
по которым её можно заказать заново); `__str__` — этикетка для покупателя (понятно
и кратко).

## Равенство и хэш: __eq__ и __hash__

По умолчанию объекты сравниваются **по идентичности** (по `id`), то есть два
«одинаковых» объекта не равны. Чтобы сравнивать **по значению**, определяют
`__eq__`:

```python
class Money:
    def __init__(self, amount, currency):
        self.amount, self.currency = amount, currency
    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)
    def __hash__(self):
        return hash((self.amount, self.currency))   # согласован с __eq__
```

**Критичный контракт**: если определили `__eq__`, нужно определить и `__hash__`
**согласованно** (равные объекты → равный хэш), иначе объект сломается как ключ
словаря/элемент множества. При этом если определить только `__eq__`, Python
**сбрасывает `__hash__` в None** (объект становится нехэшируемым) — это защита от
рассогласования. Возврат `NotImplemented` (а не `False`) при несравнимых типах
позволяет Python попробовать обратную операцию.

**Аналогия.** `__eq__` — правило «когда два билета считаются одинаковыми»;
`__hash__` — номер ячейки для билета. Если «одинаковые» билеты кладут в разные
ячейки (рассогласование) — система их теряет.

## Перегрузка операторов и __call__

Dunder-методы позволяют объектам участвовать в **операторах и встроенных
функциях** — это «перегрузка операторов»:

- Арифметика: `__add__` (`+`), `__sub__`, `__mul__`, `__truediv__`.
- Сравнения: `__lt__` (`<`), `__le__`, `__gt__`, `__ge__`.
- `__call__` — делает объект **вызываемым** как функция (`obj()`).

```python
class Vector:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, o): return Vector(self.x + o.x, self.y + o.y)

class Multiplier:
    def __init__(self, factor): self.factor = factor
    def __call__(self, n): return n * self.factor   # объект как функция

Vector(1, 2) + Vector(3, 4)     # Vector(4, 6)
double = Multiplier(2); double(10)   # 20 — объект вызвали как функцию
```

`@functools.total_ordering` достроит остальные сравнения из `__eq__` и одного из
`__lt__`/`__gt__`. `__call__` лежит в основе функторов, декораторов-классов,
фабрик.

**Аналогия.** Dunder'ы — это «розетки» стандарта Python: реализовав нужную розетку
(`__add__`, `__len__`), ваш объект подключается к синтаксису языка (`+`, `len()`),
как прибор к электросети.

## Протоколы контейнеров и контекста

Группы dunder'ов задают **протоколы** — наборы методов, делающие объект
последовательностью, итерируемым, контекст-менеджером:

- **Контейнер/последовательность**: `__len__` (`len()`), `__getitem__`
  (`obj[i]`), `__contains__` (`in`). Часто `__getitem__` + `__len__` уже дают
  индексирование и итерацию.
- **Итерация**: `__iter__` + `__next__` (см. курс про итераторы).
- **Контекст-менеджер**: `__enter__` / `__exit__` (для `with`).

```python
class Deck:
    def __init__(self, cards): self._cards = cards
    def __len__(self): return len(self._cards)          # len(deck)
    def __getitem__(self, i): return self._cards[i]     # deck[0], срезы, for, in

deck = Deck(["A", "K", "Q"])
len(deck); deck[0]; "A" in deck; [c for c in deck]      # всё работает «бесплатно»
```

Реализовав протокол, объект **бесшовно встраивается** в язык: его можно перебирать
в `for`, проверять `in`, использовать в `with`. Это и есть «duck typing» на
уровне синтаксиса — Python не требует наследования, важно лишь наличие нужных
методов.

**Аналогия.** Протокол — как требования к розетке определённого стандарта: если
прибор им соответствует (есть `__len__`, `__getitem__`), он работает в «сети»
языка, неважно, какого он «производителя» (класса).

## Памятка для собеседования

- `__repr__` — однозначно, для разработчика (REPL, отладка, контейнеры),
  определять всегда; `__str__` — читаемо, для пользователя (`print`), fallback на
  `__repr__`.
- `__eq__` — сравнение по значению; при его определении нужен согласованный
  `__hash__` (равные → равный хэш), иначе объект «ломается» как ключ. Только
  `__eq__` → `__hash__` сбрасывается в None.
- Перегрузка операторов: `__add__`, `__lt__` и т.д.; `__call__` делает объект
  вызываемым. `@total_ordering` достроит сравнения.
- **Протоколы**: `__len__`/`__getitem__`/`__contains__` (контейнер),
  `__iter__`/`__next__` (итерация), `__enter__`/`__exit__` (контекст). Реализуешь
  протокол — объект встраивается в синтаксис языка.

## Частые ошибки в ответах

- Путать `__repr__` и `__str__` или не определять `__repr__` (теряется отладочная
  информация).
- Определить `__eq__` без согласованного `__hash__` — объект становится
  нехэшируемым или ведёт себя непредсказуемо как ключ.
- Возвращать `False` вместо `NotImplemented` при сравнении с чужим типом.
- Не знать, что `__getitem__` + `__len__` уже дают итерацию/индексирование (duck
  typing протоколов).
