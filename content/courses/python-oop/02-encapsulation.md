# Инкапсуляция: _x, __x и property

> Цель урока: понять, что в Python инкапсуляция — это **соглашение, а не
> принуждение**, как работает name mangling (`__x`) и зачем нужен `@property`.
> Любимый вопрос: «есть ли в Python приватные поля?» — и правильный ответ
> показывает понимание философии языка «мы все взрослые люди».

## Соглашение об одном подчёркивании

В Python **нет настоящих private/protected** как в Java/C++. Вместо принуждения —
**соглашения**:

- **`_x`** (одно подчёркивание) — «**внутреннее**, не трогай извне». Это сигнал
  другим разработчикам, но технически доступ не запрещён. Философия: «we're all
  consenting adults» — язык доверяет программисту, а не запрещает.
- **`x`** (без подчёркивания) — публичный API.

```python
class Account:
    def __init__(self, balance):
        self.balance = balance      # публичный
        self._pin = "0000"          # «внутренний» — по соглашению

a = Account(100)
a._pin                              # технически доступно, но так делать не принято
```

Это осознанный дизайн: меньше церемоний, больше гибкости (для отладки,
тестирования, монки-патчинга). Ответственность за «не лезть во внутренности» — на
разработчике.

**Аналогия.** `_x` — это табличка «служебное помещение». Дверь не заперта, но
заходить без надобности не стоит. Python не ставит замок, а полагается на культуру.

## Name mangling: двойное подчёркивание

**`__x`** (два подчёркивания в начале, без двух в конце) запускает **name
mangling**: Python переименовывает атрибут в `_ClassName__x`. Это **не приватность**,
а механизм **избежать случайного конфликта имён при наследовании**.

```python
class Base:
    def __init__(self):
        self.__id = 1               # станет _Base__id

class Child(Base):
    def __init__(self):
        super().__init__()
        self.__id = 2               # станет _Child__id — НЕ перезатрёт родителя

obj = Child()
obj._Base__id, obj._Child__id       # (1, 2) — два разных атрибута
```

То есть `__x` нужен, чтобы подкласс случайно не перезаписал «приватное» поле
базового класса. Доступ всё ещё возможен через `_ClassName__x`, так что это не
защита от злого умысла, а защита от коллизий. Двойное подчёркивание с обеих сторон
(`__init__`) — это **dunder**, никакого mangling там нет.

**Аналогия.** Name mangling — как добавлять фамилию к имени, чтобы два «Саши» в
команде (родитель и потомок) не путались: «Саша Иванов» и «Саша Петров» — разные
люди, хотя имя одно.

## property: управляемый доступ

`@property` превращает метод в **вычисляемый атрибут**: снаружи это выглядит как
обычное поле (`obj.area`), но за чтением/записью стоит код. Это питонический способ
добавить геттеры/сеттеры **без изменения интерфейса** — начинаете с простого
атрибута, а когда понадобилась валидация или вычисление, оборачиваете в property,
**не ломая код пользователей**.

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):                # геттер: доступ как obj.radius
        return self._radius

    @radius.setter
    def radius(self, value):         # сеттер: валидация при obj.radius = ...
        if value <= 0:
            raise ValueError("radius must be positive")
        self._radius = value

    @property
    def area(self):                  # вычисляемое read-only свойство
        return 3.14159 * self._radius ** 2

c = Circle(5)
c.radius = 10                        # вызовет сеттер с проверкой
c.area                               # вычислится на лету, присвоить нельзя
```

Это и есть **главное преимущество перед явными геттерами Java-стиля**: в Python не
пишут `get_radius()`/`set_radius()` заранее «на всякий случай» — начинают с
публичного атрибута и вводят property только при необходимости, сохраняя
синтаксис `obj.radius`.

**Аналогия.** Property — это турникет вместо открытого прохода: снаружи человек
просто «проходит» (`obj.x`), но на входе можно незаметно поставить проверку
билета (валидацию), не меняя того, как люди подходят к двери.

## Памятка для собеседования

- В Python **нет настоящих private**; есть соглашения: `_x` — «внутреннее, не
  трогай» (доступ технически открыт). Философия «we're all consenting adults».
- `__x` (только в начале) → **name mangling** в `_ClassName__x`; цель — избежать
  **конфликта имён при наследовании**, а не приватность. `__dunder__` —
  не mangling.
- `@property` — вычисляемый атрибут с геттером/сеттером; позволяет добавить
  валидацию/вычисление **без смены интерфейса** (`obj.x` остаётся).
- Не пишут `get_/set_` заранее: начинают с публичного атрибута, вводят property
  при необходимости.

## Частые ошибки в ответах

- Утверждать, что `__x` делает поле «приватным/защищённым» — это лишь mangling от
  коллизий, доступ остаётся через `_Class__x`.
- Путать `_x` (соглашение) и `__x` (mangling) и `__dunder__` (спецметоды).
- Писать Java-стиль `get_x()/set_x()` вместо `@property`.
- Считать, что Python запрещает доступ к «приватным» полям (он полагается на
  соглашения).
