# classmethod, staticmethod и __slots__

> Цель урока: разобраться, чем `classmethod` и `staticmethod` отличаются от
> обычного метода и когда какой нужен, а также понять `__slots__` — оптимизацию
> памяти, о которой спрашивают «как уменьшить расход памяти на миллионы
> объектов». Это прикладные мелочи, на которых видно опыт.

## Обычный метод, classmethod, staticmethod

Три вида методов отличаются тем, **что приходит первым аргументом**:

- **Обычный метод** — получает **`self`** (экземпляр). Работает с данными
  конкретного объекта.
- **`@classmethod`** — получает **`cls`** (класс, а не экземпляр). Работает с
  классом; главное применение — **альтернативные конструкторы** (фабрики).
- **`@staticmethod`** — **не получает ни `self`, ни `cls`**. Это просто функция в
  пространстве имён класса; группирует логически связанный код.

```python
class Pizza:
    def __init__(self, ingredients):
        self.ingredients = ingredients

    @classmethod
    def margherita(cls):                 # фабрика: возвращает cls(...)
        return cls(["tomato", "mozzarella"])

    @staticmethod
    def is_valid_size(size):             # утилита, не трогает класс/объект
        return size in {"S", "M", "L"}

Pizza.margherita()          # альтернативный конструктор
Pizza.is_valid_size("M")    # True — вызывается без экземпляра
```

Почему `classmethod` для фабрик лучше, чем хардкод имени класса: он использует
`cls`, поэтому **корректно работает с наследованием** — `Subclass.margherita()`
вернёт `Subclass`, а не `Pizza`. `staticmethod` берут, когда метод не использует ни
состояние объекта, ни класс, но логически принадлежит классу.

**Аналогия.** Обычный метод — действие конкретного сотрудника («я делаю»);
`classmethod` — действие от лица всего отдела/фабрики («отдел выпускает новый
экземпляр»); `staticmethod` — справочная функция, висящая на стене отдела, но не
зависящая ни от сотрудника, ни от отдела.

## __slots__: экономия памяти

По умолчанию каждый экземпляр хранит атрибуты в **словаре `__dict__`**, что гибко
(можно добавить любой атрибут на лету), но затратно по памяти. **`__slots__`**
объявляет **фиксированный набор** атрибутов и убирает `__dict__`, храня атрибуты в
компактной структуре (как поля C-структуры):

```python
class Point:
    __slots__ = ("x", "y")       # только эти атрибуты, без __dict__
    def __init__(self, x, y):
        self.x, self.y = x, y

p = Point(1, 2)
p.z = 3          # AttributeError — новых атрибутов нет (нет __dict__)
```

Выигрыш — заметная экономия памяти (часто 40–50%) и небольшое ускорение доступа,
что критично при **миллионах мелких объектов** (узлы графа, записи, точки).
Цена — ограничения: нельзя добавлять атрибуты вне списка, нет `__dict__` и
`__weakref__` (если не добавить явно), нюансы с наследованием и множественным
наследованием.

**Аналогия.** Без `__slots__` каждый объект носит с собой растягивающуюся сумку
(`__dict__`), куда можно докинуть что угодно, но сумка тяжёлая. `__slots__` — это
жёсткий органайзер с фиксированными ячейками: легче и быстрее, но новые отделения
не добавить.

## Когда что применять

Короткий гид по выбору:

- **Обычный метод** — по умолчанию, когда нужен доступ к данным экземпляра.
- **`classmethod`** — альтернативные конструкторы (`from_json`, `from_string`),
  методы, работающие с классом в целом, фабрики, учитывающие наследование.
- **`staticmethod`** — чистые утилиты, связанные с классом по смыслу, но не
  использующие его состояние (можно было бы вынести в функцию, но в классе
  читаемее).
- **`__slots__`** — только когда есть **реальная проблема памяти** при огромном
  числе экземпляров; не как «преждевременная оптимизация» для каждого класса.

**Аналогия.** Это как выбирать инструмент: `classmethod` — конвейер по выпуску
готовых конфигураций объекта, `staticmethod` — отвёртка в ящике с надписью класса,
`__slots__` — режим «налегке» для массового производства.

## Памятка для собеседования

- Различие по первому аргументу: метод → `self` (экземпляр); `@classmethod` →
  `cls` (класс); `@staticmethod` → ничего.
- `classmethod` — **альтернативные конструкторы/фабрики**, корректно работают с
  наследованием (через `cls`). `staticmethod` — утилита, не трогающая
  состояние/класс.
- `__slots__` — фиксированный набор атрибутов, **убирает `__dict__`**: экономия
  памяти (~40–50%) и чуть быстрее доступ; нельзя добавлять атрибуты вне списка.
- `__slots__` применять при **реальной** проблеме памяти (миллионы объектов), не
  везде подряд.

## Частые ошибки в ответах

- Путать `classmethod` и `staticmethod` (первый получает `cls`, второй — ничего).
- Хардкодить имя класса в фабрике вместо `cls` (ломается наследование).
- Считать `__slots__` универсальной оптимизацией без учёта ограничений (нет
  `__dict__`, проблемы с наследованием/weakref).
- Не уметь назвать практический смысл `classmethod` (альтернативный конструктор).
