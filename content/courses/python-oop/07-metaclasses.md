# Метаклассы

> Цель урока: понять, что классы в Python — это **тоже объекты**, которые кто-то
> создаёт, и этот «кто-то» — метакласс. Тема пугает, но на собесе ценится умение
> объяснить её просто и сказать, что в 99% случаев метакласс не нужен (есть более
> простые инструменты). «Что такое метакласс» — вопрос на сеньорство.

## type: класс классов

Ключевая идея: раз **всё в Python — объект**, то и **класс — это объект**. А
объекты кто-то создаёт. Класс создаётся **метаклассом**, и по умолчанию это
**`type`**.

```python
class Foo: pass
type(Foo)          # <class 'type'> — класс Foo создан метаклассом type
type(Foo())        # <class 'Foo'>  — экземпляр создан классом Foo
isinstance(Foo, type)   # True — Foo является экземпляром type
```

То есть выстраивается цепочка: экземпляр — это экземпляр класса; класс — это
экземпляр метакласса (`type`). `type` умеет и **создавать классы динамически**:
`type(name, bases, namespace)` — то же, что `class`-определение, но в рантайме.

```python
# эквивалентно: class Dog: sound = "Woof"
Dog = type("Dog", (), {"sound": "Woof"})
```

**Аналогия.** Если класс — это форма для отливки экземпляров, то метакласс — это
**станок, который изготавливает сами формы**. Обычно станок один стандартный
(`type`), и о нём не думают.

## Свой метакласс и зачем он

**Метакласс** — это класс, наследующий `type` и переопределяющий, **как создаётся
класс** (через `__new__`/`__init__` метакласса). Указывается через
`class X(metaclass=Meta)`. Метакласс срабатывает в момент **определения** класса —
можно вмешаться в его конструкцию: добавить методы, зарегистрировать класс,
проверить структуру.

```python
class RegistryMeta(type):
    registry = {}
    def __new__(mcs, name, bases, ns):
        cls = super().__new__(mcs, name, bases, ns)
        if bases:                       # не регистрируем базовый
            RegistryMeta.registry[name] = cls
        return cls

class Plugin(metaclass=RegistryMeta): pass
class PluginA(Plugin): pass             # автоматически попал в registry
```

Реальные применения метаклассов: **ORM** (SQLAlchemy/Django собирают поля модели и
строят маппинг в SQL при определении класса), **ABC** (`ABCMeta`), **авто-реестры
плагинов**, фреймворки сериализации. Но это инструмент тяжёлый.

**Аналогия.** Свой метакласс — это переоснастить станок, делающий формы, чтобы
каждая новая форма выходила со встроенной маркировкой или проверкой. Мощно, но
менять станок ради мелочи — overkill.

## Когда метакласс НЕ нужен

Главный практический вывод (и его ждут на собесе): **метаклассы нужны очень
редко**, и почти всегда есть более простой инструмент:

- Нужно **поведение при создании подкласса** (регистрация, проверка) →
  **`__init_subclass__`** (Python 3.6+) — хук в обычном классе, без метакласса.
- Нужно **узнать имя атрибута** в дескрипторе → **`__set_name__`**.
- Нужно **изменить класс после создания** → **декоратор класса** (проще
  метакласса).
- Нужен **интерфейс/абстракция** → **ABC** или **Protocol**.

```python
class Base:
    registry = {}
    def __init_subclass__(cls, **kw):    # вместо метакласса-реестра
        super().__init_subclass__(**kw)
        Base.registry[cls.__name__] = cls
```

Цитата Тима Питерса: «метаклассы — это глубокая магия, о которой 99% пользователей
не должны даже думать; если вы сомневаетесь, нужны ли они вам, — не нужны».
Сильный ответ: знаю, что это, понимаю механизм, но в прикладном коде выбираю
`__init_subclass__`/декоратор/ABC.

**Аналогия.** Метакласс — кувалда. Иногда нужна (ORM-фреймворк), но забивать гвоздь
(зарегистрировать подкласс) лучше молотком (`__init_subclass__`).

## Памятка для собеседования

- Класс — это **объект**; его создаёт **метакласс**, по умолчанию **`type`**.
  Экземпляр ← класс ← метакласс. `type(name, bases, ns)` создаёт класс динамически.
- **Свой метакласс** (наследник `type`, `metaclass=`) вмешивается в **создание
  класса**: реестры, проверки, добавление методов. Применяется в ORM, ABC,
  фреймворках.
- В 99% случаев метакласс **не нужен**: для подклассов — `__init_subclass__`, для
  имени атрибута — `__set_name__`, для модификации — декоратор класса, для
  интерфейса — ABC/Protocol.

## Частые ошибки в ответах

- Не знать, что класс сам является объектом (экземпляром `type`).
- Путать метакласс (создаёт класс) и базовый класс (от которого наследуются).
- Предлагать метакласс там, где достаточно `__init_subclass__` или декоратора.
- Не уметь привести реальный пример (ORM, ABCMeta, авто-реестр).
