# ABC и протоколы: duck typing и интерфейсы

> Цель урока: понять, как в Python задают «интерфейсы» — через абстрактные базовые
> классы (`ABC`) и через структурную типизацию (`Protocol`), и как это связано с
> duck typing. Вопрос «как сделать интерфейс в Python, где нет `interface`» —
> частый, и в нём проверяют знание ABC vs Protocol.

## Duck typing

**Duck typing** — философия Python: «если что-то крякает как утка и плавает как
утка — это утка». Важна **не принадлежность к типу/классу, а наличие нужных
методов и поведения**. Функции не проверяют тип аргумента — они просто вызывают
нужные методы, и работает всё, что их поддерживает.

```python
def total_length(items):
    return sum(len(x) for x in items)    # работает с чем угодно, где есть len()

total_length(["abc", [1, 2], (3, 4, 5)])  # 3 + 2 + 3 = 8 — разные типы, всем ок
```

Плюс — гибкость и слабая связанность: код работает с любым объектом «правильной
формы», не требуя общего базового класса. Минус — ошибки «нет такого метода»
всплывают **в рантайме**, а не при проверке типов. ABC и Protocol — два способа
сделать ожидания **явными**, не теряя дух duck typing.

**Аналогия.** Duck typing — нанимать по умениям, а не по диплому: можешь делать
работу (есть методы) — берём, неважно, какой у тебя «класс».

## Абстрактные базовые классы (ABC)

**ABC (Abstract Base Class)** задаёт интерфейс через **наследование**: базовый
класс объявляет абстрактные методы, которые подкласс **обязан** реализовать, иначе
его нельзя инстанцировать. Используется `abc.ABC` и декоратор `@abstractmethod`:

```python
from abc import ABC, abstractmethod

class Storage(ABC):
    @abstractmethod
    def save(self, key, value): ...
    @abstractmethod
    def load(self, key): ...

class MemoryStorage(Storage):
    def save(self, key, value): self._d[key] = value
    def load(self, key): return self._d[key]

Storage()          # TypeError: нельзя создать абстрактный класс
# если не реализовать оба метода — тоже TypeError при создании подкласса
```

ABC — это **номинальная** типизация: связь устанавливается явным наследованием
(`class X(Storage)`). Стандартная библиотека built на ABC: `collections.abc`
(`Iterable`, `Sequence`, `Mapping`…) задаёт протоколы коллекций. ABC хорош, когда
вы контролируете иерархию и хотите гарантировать контракт + дать общую реализацию.

**Аналогия.** ABC — это официальный профсоюз: чтобы стать его членом (подклассом),
надо подписать устав (реализовать абстрактные методы) и явно вступить
(наследоваться). Без подписи не примут (TypeError).

## Protocol: структурная типизация

**`Protocol`** (`typing`, Python 3.8+) задаёт интерфейс **структурно**: класс
соответствует протоколу, если у него **есть нужные методы**, — **без явного
наследования**. Это «статический duck typing», проверяемый mypy:

```python
from typing import Protocol

class SupportsClose(Protocol):
    def close(self) -> None: ...

def shutdown(resource: SupportsClose) -> None:
    resource.close()

class File:
    def close(self) -> None: ...     # НЕ наследует SupportsClose

shutdown(File())     # mypy доволен: у File есть close() нужной формы
```

Разница с ABC: **ABC требует наследования** (номинально), **Protocol — только
совпадения структуры** (структурно), и связь проверяется типчекером, а не в
рантайме. Protocol идеален, когда вы **не контролируете** классы (сторонние
библиотеки) или хотите типизировать duck typing, не навязывая иерархию. Можно
сделать `@runtime_checkable` для `isinstance`-проверок (по наличию методов).

**Аналогия.** Protocol — это «требуется человек, умеющий водить» в объявлении:
неважно, где ты учился и в каком ты «классе», — умеешь нужное (есть метод),
подходишь. Никаких формальных вступлений.

## Памятка для собеседования

- **Duck typing**: важна форма (наличие методов), а не тип; гибко, но ошибки — в
  рантайме.
- **ABC** — интерфейс через **наследование** (`abc.ABC` + `@abstractmethod`):
  подкласс обязан реализовать абстрактные методы, иначе не инстанцируется
  (номинальная типизация). `collections.abc` — встроенные протоколы коллекций.
- **Protocol** (`typing`) — **структурная** типизация: соответствие по наличию
  методов **без наследования**; «статический duck typing», проверяется mypy;
  хорош для чужих классов. `@runtime_checkable` для isinstance.
- ABC — когда контролируешь иерархию и нужна общая реализация; Protocol — когда
  типизируешь duck typing/сторонние типы.

## Частые ошибки в ответах

- Говорить «в Python нет интерфейсов» — есть ABC и Protocol.
- Путать ABC (наследование, номинально) и Protocol (структурно, без наследования).
- Не связывать Protocol с duck typing/статической проверкой mypy.
- Забывать, что абстрактный класс с нереализованными методами нельзя
  инстанцировать.
