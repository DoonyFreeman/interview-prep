# Dataclasses и аналоги

> Цель урока: понять, что делает `@dataclass`, какие методы он генерирует, и когда
> брать его, а когда `NamedTuple`, `attrs` или Pydantic. На собесе спрашивают, как
> сократить «классы-болванки» с кучей повторяющегося кода в `__init__`, и ждут
> упоминания dataclasses с пониманием нюансов (`frozen`, изменяемые дефолты).

## Зачем нужны dataclasses

Классы, которые в основном **хранят данные**, требуют много шаблонного кода:
`__init__`, `__repr__`, `__eq__`. `@dataclass` (с Python 3.7) **генерирует их
автоматически** из аннотаций полей:

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int = 0                  # значение по умолчанию

p = Point(1, 2)
p                                # Point(x=1, y=2)  — __repr__ сгенерирован
Point(1, 2) == Point(1, 2)       # True            — __eq__ сгенерирован
```

Без dataclass пришлось бы вручную писать `__init__`, присваивать каждое поле,
дублировать имена в `__repr__` и `__eq__`. Dataclass убирает этот шум, оставляя
только объявление полей с типами. Это **не новый вид класса**, а декоратор,
дописывающий методы в обычный класс.

**Аналогия.** Dataclass — это конструктор мебели с уже просверленными отверстиями:
вы указываете, какие детали (поля) нужны, а крепёж (`__init__`, `__repr__`,
`__eq__`) идёт в комплекте, не нужно вытачивать вручную.

## Параметры: frozen, order, field

`@dataclass` настраивается параметрами:

- **`frozen=True`** — делает экземпляры **неизменяемыми** (присваивание полю →
  ошибка) и **хэшируемыми** (генерирует `__hash__`). Аналог «immutable value
  object».
- **`order=True`** — генерирует `__lt__`, `__le__`, `__gt__`, `__ge__` (сравнение
  по кортежу полей), чтобы объекты можно было сортировать.
- **`field(...)`** — тонкая настройка поля: `default_factory` для изменяемых
  значений, `compare=False` (исключить из сравнения), `repr=False`.

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, order=True)
class Version:
    major: int
    minor: int
    tags: list = field(default_factory=list)   # изменяемый дефолт — ТОЛЬКО так!

sorted([Version(2, 0), Version(1, 5)])         # работает благодаря order=True
```

**Критичный нюанс**: изменяемое значение по умолчанию (`tags: list = []`) запрещено
— dataclass бросит ошибку, потому что это та же ловушка общего изменяемого дефолта.
Нужно `field(default_factory=list)`. Метод `__post_init__` позволяет дописать
логику после авто-`__init__` (валидация, вычисляемые поля).

**Аналогия.** `frozen=True` — это запечатать собранную деталь (нельзя переставить
части, зато можно использовать как ключ-штамп). `default_factory` — «каждому
новому экземпляру свой чистый ящик», а не один общий на всех.

## NamedTuple, attrs, Pydantic

Dataclass — не единственный вариант; выбор зависит от задачи:

- **`typing.NamedTuple`** — неизменяемая запись на основе кортежа, с полями и
  типами. Легче dataclass, но это **кортеж** (распаковывается, сравнивается как
  tuple, неизменяем). Хорош для простых неизменяемых значений.
- **`@dataclass`** — стандарт для изменяемых/неизменяемых записей с методами и
  гибкостью; без внешних зависимостей.
- **`attrs`** — сторонняя библиотека, прародитель dataclasses; мощнее (валидаторы,
  конвертеры), нужна, если функций dataclass не хватает.
- **Pydantic-модель** — когда нужна **валидация и парсинг данных** (из JSON, из
  API): проверяет и приводит типы в рантайме. Это основа FastAPI. Дороже по
  скорости, но даёт строгую валидацию входных данных.

Правило выбора: простая неизменяемая запись → `NamedTuple`; внутренняя модель
данных → `@dataclass`; **данные с границы системы (запросы, конфиги), которые надо
валидировать** → **Pydantic**.

**Аналогия.** NamedTuple — компактная запечатанная карточка; dataclass —
универсальная папка с документами; Pydantic — папка с контролёром на входе,
который проверяет каждый вложенный документ на соответствие правилам.

## Памятка для собеседования

- `@dataclass` генерирует `__init__`, `__repr__`, `__eq__` из аннотаций полей —
  убирает шаблон классов-хранилищ данных.
- `frozen=True` — неизменяемость + хэшируемость; `order=True` — методы сравнения
  для сортировки; `field(default_factory=...)` — для изменяемых дефолтов.
- Изменяемый дефолт напрямую (`x: list = []`) **запрещён** — только
  `default_factory`. `__post_init__` — логика после авто-init.
- Выбор: `NamedTuple` (простая неизменяемая запись) · `@dataclass` (модель данных)
  · `attrs` (больше возможностей) · **Pydantic** (валидация данных с границы
  системы).

## Частые ошибки в ответах

- Не знать, какие именно методы генерирует dataclass.
- Писать изменяемый дефолт `x: list = []` вместо `field(default_factory=list)`.
- Считать dataclass «особым типом класса» — это обычный класс с дописанными
  методами.
- Использовать dataclass для валидации внешних данных вместо Pydantic (dataclass
  типы в рантайме не проверяет).
