# Наследование и MRO

> Цель урока: понять, как Python ищет методы при наследовании, что на самом деле
> делает `super()`, и как множественное наследование разрешает «ромбовидную
> проблему» через C3-линеаризацию (MRO). Вопрос про MRO и `super()` — маркер
> зрелого понимания ООП.

## Одиночное и множественное наследование

Наследование позволяет классу-потомку **переиспользовать и расширять** поведение
родителя. Python поддерживает и **множественное наследование** — класс может
наследоваться от нескольких родителей сразу:

```python
class Animal:
    def speak(self): return "..."

class Dog(Animal):                       # одиночное
    def speak(self): return "Woof"

class Mixin1: ...
class Mixin2: ...
class Combined(Mixin1, Mixin2, Animal):  # множественное
    ...
```

При обращении к `obj.method()` Python ищет метод по цепочке наследования в строго
определённом порядке — **MRO (Method Resolution Order)**. Множественное
наследование мощно, но усложняет эту цепочку, и тут возникает «ромбовидная
проблема».

**Аналогия.** Наследование — как наследовать черты родителей: потомок берёт их
методы, но может что-то переопределить «по-своему». Множественное наследование —
двое родителей, и нужно правило, чьи черты применять, если оба что-то задают.

## Ромбовидная проблема и C3-линеаризация

**Ромбовидная проблема (diamond problem)**: класс D наследует от B и C, а оба — от
общего A. Если все определяют один метод, **в каком порядке** их искать и не
вызвать ли A дважды?

Python решает это алгоритмом **C3-линеаризации**, которая строит **MRO** —
линейный, однозначный порядок классов. Правила C3: потомок идёт раньше родителей;
порядок родителей в объявлении сохраняется; общий предок (A) встаёт **один раз и
после** всех, кто от него наследуется.

```python
class A:
    def whoami(self): return "A"
class B(A): pass
class C(A):
    def whoami(self): return "C"
class D(B, C): pass

D.__mro__          # (D, B, C, A, object) — A один раз, в конце
D().whoami()       # "C" — нашли в C раньше A
print([c.__name__ for c in D.mro()])   # ['D','B','C','A','object']
```

MRO виден через `Class.__mro__` или `Class.mro()`. Если корректный порядок
построить нельзя (противоречивые требования), Python бросит `TypeError` при
определении класса. Понимание MRO объясняет, какой именно метод вызовется при
сложном наследовании.

**Аналогия.** MRO — это очередь приоритета: при запросе «кто умеет whoami?» обходят
строй классов в фиксированном порядке и берут первого умеющего. C3 гарантирует, что
строй один и тот же, без дубликатов и противоречий.

## super(): кооперативный вызов

`super()` вызывает метод **следующего класса в MRO**, а не «родителя» в наивном
смысле. Это ключевая тонкость: при множественном наследовании `super()` идёт не
к буквальному родителю, а к следующему по цепочке MRO, обеспечивая
**кооперативное** наследование, где каждый класс вызывается ровно один раз.

```python
class Base:
    def __init__(self):
        print("Base")

class A(Base):
    def __init__(self):
        super().__init__()       # вызовет следующий по MRO, не обязательно Base
        print("A")

class B(Base):
    def __init__(self):
        super().__init__()
        print("B")

class C(A, B):
    def __init__(self):
        super().__init__()       # запустит цепочку A → B → Base ровно по разу
        print("C")

C()      # Base, B, A, C — каждый __init__ ровно один раз
```

Поэтому в кооперативных иерархиях **всегда вызывают `super().__init__()`**, а не
`Base.__init__(self)` напрямую — иначе цепочка MRO нарушится и какой-то класс
вызовется дважды или пропустится. `super()` без аргументов (Python 3) сам знает
текущий класс и экземпляр.

**Аналогия.** `super()` — это не «позвать папу», а «передать эстафету следующему
бегуну в заранее расставленной команде (MRO)». Если кто-то вместо эстафеты побежит
напрямую к финишу (`Base.__init__`), он собьёт порядок и кто-то пробежит дважды.

## Памятка для собеседования

- Python поддерживает **множественное наследование**; поиск метода идёт по
  **MRO** (Method Resolution Order).
- **Ромбовидная проблема** решается **C3-линеаризацией**: потомок раньше
  родителей, порядок объявления сохраняется, общий предок — один раз и в конце.
  Смотреть `Class.__mro__`.
- `super()` вызывает **следующий класс по MRO**, а не буквального родителя; это
  даёт **кооперативное** наследование, где каждый класс вызывается ровно один раз.
- Всегда `super().__init__()`, не `Base.__init__(self)` — иначе цепочка MRO
  ломается.

## Частые ошибки в ответах

- Считать, что `super()` всегда вызывает «родительский» класс (он вызывает
  следующий по MRO).
- Не знать про MRO/C3 и не уметь объяснить порядок при множественном наследовании.
- Вызывать `Base.__init__(self)` в кооперативной иерархии (двойные/пропущенные
  вызовы).
- Думать, что общий предок в ромбе вызовется дважды (C3 ставит его один раз).
