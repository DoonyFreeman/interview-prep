# Дескрипторы

> Цель урока: понять механизм, который лежит в основе `@property`, методов,
> `classmethod`, `staticmethod` и ORM-полей — **дескрипторы**. Это «продвинутая»
> тема, но именно она объясняет, *как* Python вообще управляет доступом к
> атрибутам. Сильный кандидат может объяснить, что property — это просто
> дескриптор.

## Что такое дескриптор

**Дескриптор** — это объект, у которого определён хотя бы один из методов
`__get__`, `__set__`, `__delete__`. Если такой объект положить **как атрибут
класса**, он перехватывает доступ к этому атрибуту у экземпляров. То есть
дескриптор позволяет вынести логику «что происходит при чтении/записи поля» в
отдельный переиспользуемый объект.

```python
class Positive:                          # дескриптор: валидирует, что > 0
    def __set_name__(self, owner, name):
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        if obj is None: return self
        return getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError("must be positive")
        setattr(obj, self.name, value)

class Account:
    balance = Positive()                 # дескриптор как атрибут класса

a = Account()
a.balance = 100      # вызовет Positive.__set__ с проверкой
a.balance = -5       # ValueError
```

Здесь логика валидации описана **один раз** в `Positive` и переиспользуется для
любого поля любого класса. `__set_name__` (Python 3.6+) автоматически узнаёт имя
атрибута.

**Аналогия.** Дескриптор — это «умная розетка», вмонтированная в стену (класс):
кто бы ни втыкал вилку (читал/писал атрибут), срабатывает встроенная логика
(проверка, логирование, вычисление). Розетку сделали один раз, а пользуются все.

## Data vs non-data дескрипторы

Разделение важно, потому что оно определяет **приоритет** дескриптора над
`__dict__` экземпляра:

- **Data-дескриптор** — определяет `__set__` (и/или `__delete__`). Имеет
  **приоритет над атрибутом экземпляра**: даже если в `obj.__dict__` есть поле с
  тем же именем, обращение пойдёт через дескриптор.
- **Non-data дескриптор** — определяет только `__get__`. **Атрибут экземпляра
  его перекрывает** (если в `__dict__` есть значение, берётся оно).

Это объясняет тонкое поведение: `@property` (data-дескриптор) нельзя «перезатереть»
через `obj.x = ...` — сработает сеттер; а обычный метод (non-data дескриптор) можно
заслонить, присвоив атрибут экземпляра с тем же именем.

```python
# property — data-дескриптор: всегда идёт через геттер/сеттер
# метод — non-data дескриптор: obj.method = lambda: ... заслонит его в этом объекте
```

**Аналогия.** Data-дескриптор — начальник с правом вето: что бы ни лежало «на
столе экземпляра», решает он. Non-data — советник: если на столе уже есть готовое
значение, берут его, а к советнику не обращаются.

## Что построено на дескрипторах

Дескрипторы — не экзотика, а **механизм, на котором держится язык**:

- **`@property`** — это data-дескриптор, оборачивающий геттер/сеттер.
- **Методы** — функции являются non-data дескрипторами; именно их `__get__`
  превращает функцию в **связанный метод**, подставляя `self`.
- **`classmethod` и `staticmethod`** — дескрипторы, меняющие, что передаётся
  первым аргументом (класс / ничего).
- **ORM-поля** (SQLAlchemy `Column`, Django-поля) — дескрипторы, перехватывающие
  доступ к полям модели для трансляции в SQL.

То есть, когда вы пишете `obj.method()` или `obj.some_field`, под капотом
почти всегда работает протокол дескрипторов. Поэтому понимание дескрипторов даёт
ключ к тому, **как Python реализует ООП-механику** — и позволяет писать свои
переиспользуемые «умные атрибуты» (валидация, ленивые вычисления, типизированные
поля).

**Аналогия.** Дескрипторы — это «электропроводка» дома: обычно её не видно, но
именно через неё работают розетки (`property`), выключатели (методы) и техника
(ORM). Понять проводку — понять, почему всё включается так, как включается.

## Памятка для собеседования

- **Дескриптор** — объект с `__get__`/`__set__`/`__delete__`, положенный как
  **атрибут класса**; перехватывает доступ к полю у экземпляров. Логика «что при
  чтении/записи» выносится в переиспользуемый объект.
- **Data-дескриптор** (`__set__`) имеет **приоритет над `__dict__` экземпляра**;
  **non-data** (только `__get__`) перекрывается атрибутом экземпляра.
- На дескрипторах построены: **`@property`** (data), **методы** (non-data, дают
  bound-метод через `__get__`), **`classmethod`/`staticmethod`**, **ORM-поля**.
- `__set_name__` автоматически сообщает дескриптору имя атрибута.

## Частые ошибки в ответах

- Не знать, что `property` и методы — это дескрипторы (считать их «встроенной
  магией»).
- Путать data и non-data дескрипторы и их приоритет относительно `__dict__`.
- Думать, что дескриптор кладётся в экземпляр (он работает как атрибут **класса**).
- Не уметь объяснить, как функция становится связанным методом (через `__get__`).
