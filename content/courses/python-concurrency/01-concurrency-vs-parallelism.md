# Конкурентность против параллелизма

> Цель урока: раз и навсегда развести два понятия, которые путают почти все, и
> связать их с GIL и выбором инструмента (потоки / процессы / asyncio). Это
> фундамент всей темы многозадачности и любимый «отсеивающий» вопрос
> собеседований.

## Два разных понятия

- **Конкурентность (concurrency)** — это про **структуру**: умение системы
  *управлять несколькими задачами*, которые продвигаются, чередуясь. Задачи могут
  выполняться не одновременно, а **по очереди маленькими кусочками**, создавая
  впечатление одновременности. Это про «жонглирование» задачами.
- **Параллелизм (parallelism)** — это про **исполнение**: несколько задач реально
  выполняются **в один и тот же момент** на разных ядрах процессора. Это про
  «делать несколько дел физически одновременно».

Ключевое: **конкурентность — не обязательно параллелизм**. Один повар, который
жонглирует тремя блюдами (помешал одно, пока второе варится), — конкурентен, но не
параллелен. Три повара, готовящие три блюда одновременно, — параллельны.

```text
Конкурентность (1 ядро):  A-B-A-B-A-B   (чередование, видимость одновременности)
Параллелизм   (2 ядра):   A-A-A
                          B-B-B          (реально одновременно)
```

**Аналогия.** Конкурентность — один кассир, обслуживающий несколько очередей,
переключаясь между ними. Параллелизм — несколько кассиров, каждый на своей
очереди. Первое — про умение переключаться, второе — про физически
одновременную работу.

## Связь с GIL

Именно здесь всё сходится с GIL (см. курс Python Core). **GIL запрещает
параллелизм байткода** в одном процессе CPython (одновременно байткод исполняет
только один поток), но **не запрещает конкурентность**.

Поэтому:

- **Потоки** в Python дают **конкурентность**, но не параллелизм для CPU-задач:
  они чередуются под одним GIL.
- На **IO-bound** задачах потоки всё равно полезны — поток отпускает GIL во время
  ожидания, и другой работает (конкурентность с пользой).
- **Настоящий параллелизм** CPU-bound кода даёт только **многопроцессность**
  (у каждого процесса свой GIL) или нативный код, отпускающий GIL.

То есть GIL бьёт по параллелизму, а конкурентность (чередование, в т.ч. ожидающих
IO) остаётся доступной.

**Аналогия.** GIL — это один микрофон на сцене (процесс): говорить может только
один (параллелизма речи нет), но участники могут быстро передавать микрофон по
кругу (конкурентность есть). Чтобы говорили реально одновременно, нужно несколько
сцен (процессов).

## CPU-bound против IO-bound

Тип задачи определяет, какой инструмент даст выигрыш:

- **CPU-bound** — упирается в вычисления (перемножение матриц, парсинг, сжатие,
  хэширование). Почти всё время держит процессор/GIL. Ускорение — только
  **параллелизмом** (процессы, нативные библиотеки).
- **IO-bound** — упирается в **ожидание** (сеть, диск, БД, API). Процессор
  простаивает, пока идёт ввод-вывод. Ускорение — **конкурентностью** (потоки или
  asyncio): пока одна задача ждёт ответа, другая работает.

```python
# CPU-bound: считает, держит ядро → нужны процессы
def crunch(n): return sum(i*i for i in range(n))

# IO-bound: ждёт сеть → подходят потоки или asyncio
def fetch(url): return requests.get(url).text
```

Правило выбора (его ждут на собесе): **IO-bound → потоки или asyncio; CPU-bound →
процессы (или нативный код)**. Перепутать — типичная ошибка: процессы для IO дадут
лишние накладные расходы, потоки для CPU не ускорят из-за GIL.

**Аналогия.** CPU-bound — колоть дрова: нужны несколько дровосеков (процессов),
чтобы успеть. IO-bound — ждать, пока закипит несколько чайников: один человек
вполне справится, переключаясь между ними (конкурентность), нанимать бригаду
бессмысленно.

## Памятка для собеседования

- **Конкурентность** — структура/управление задачами через чередование (не
  обязательно одновременно); **параллелизм** — физически одновременное исполнение
  на разных ядрах.
- Конкурентность ≠ параллелизм: можно жонглировать задачами на одном ядре.
- **GIL** запрещает параллелизм байткода в процессе, но не конкурентность: потоки
  чередуются; настоящий параллелизм CPU — только процессы/нативный код.
- **CPU-bound** (вычисления) → параллелизм (процессы); **IO-bound** (ожидание) →
  конкурентность (потоки/asyncio).

## Частые ошибки в ответах

- Использовать «конкурентность» и «параллелизм» как синонимы.
- Думать, что потоки в Python дают параллелизм для вычислений (мешает GIL).
- Брать процессы для IO-bound (лишние накладные расходы) или потоки для CPU-bound
  (нет ускорения).
- Не связывать выбор инструмента с типом задачи (CPU vs IO).
