# multiprocessing: настоящий параллелизм

> Цель урока: понять, как обойти GIL для CPU-bound задач через процессы, какой
> ценой это даётся (изоляция памяти, сериализация) и почему `if __name__ ==
> "__main__"` тут критичен. Вопрос «как в Python распараллелить тяжёлые
> вычисления» ждёт ответа про multiprocessing с пониманием накладных расходов.

## Процессы вместо потоков

`multiprocessing` запускает **отдельные процессы**, у каждого — **свой
интерпретатор и свой GIL**. Поэтому процессы дают **настоящий параллелизм**
CPU-bound кода на нескольких ядрах, в отличие от потоков.

```python
from multiprocessing import Pool

def crunch(n):
    return sum(i * i for i in range(n))

if __name__ == "__main__":
    with Pool(4) as pool:                  # 4 процесса на 4 ядра
        results = pool.map(crunch, [10**7] * 4)   # реально параллельно
```

API похож на потоки (`Process` ≈ `Thread`, `Pool` для распределения работы), но
семантика принципиально другая: процессы **не делят память**. Это и спасает от
гонок (нет общих данных), и создаёт главную сложность — обмен данными.

**Аналогия.** Если потоки — сотрудники в одном кабинете с общим столом, то
процессы — сотрудники в **разных зданиях**, у каждого свой кабинет. Они работают
по-настоящему параллельно, но чтобы передать документ, его надо скопировать и
отправить курьером.

## Цена: изоляция памяти и сериализация

Изоляция памяти означает, что данные между процессами нужно **сериализовать**
(через `pickle`) и копировать. Это главная цена multiprocessing:

- **Аргументы и результаты пиклятся** — передаются как копии. Большие объекты
  передавать дорого; непиклящиеся (лямбды, локальные функции, открытые сокеты)
  передать нельзя.
- **Накладные расходы на запуск** процесса и на сериализацию могут **съесть весь
  выигрыш**, если задача мелкая или данных много, а вычислений мало.
- Для общих данных есть `Value`/`Array` (разделяемая память), `Manager`
  (прокси-объекты), `Pipe`/`Queue` (передача сообщений), `shared_memory`.

```python
# плохая идея: данных много, счёта мало → сериализация дороже самой работы
pool.map(tiny_transform, huge_list_of_big_objects)
```

Правило: multiprocessing выгоден для «**много счёта, мало данных** на входе/
выходе». Если данных много — выигрыш может исчезнуть.

**Аналогия.** Переслать коллеге в другом здании толстую папку (большие данные)
ради того, чтобы он поставил одну печать (мелкая работа), — курьер потратит больше,
чем сэкономит. Процессы окупаются, когда работа тяжёлая, а пересылка лёгкая.

## __main__ и способы запуска

Критичный практический момент: на **Windows и macOS** (по умолчанию метод
**spawn**) дочерний процесс **заново импортирует** главный модуль. Без защиты
`if __name__ == "__main__"` код запуска процессов выполнится повторно в каждом
ребёнке → бесконечная рекурсия порождения процессов.

```python
def main():
    with Pool(4) as pool:
        pool.map(crunch, data)

if __name__ == "__main__":     # ОБЯЗАТЕЛЬНО при использовании процессов
    main()
```

Методы старта: **fork** (Linux по умолчанию — копирует процесс, быстро, но есть
тонкости с потоками/состоянием), **spawn** (Windows/macOS — чистый новый
интерпретатор, безопаснее, медленнее), **forkserver**. Понимание, что дочерний
процесс не наследует состояние «как поток», — частый источник багов.

**Аналогия.** spawn — это нанять нового сотрудника «с нуля», который сам прочитает
всю инструкцию (импортирует модуль). Если в инструкции написано «найми ещё
сотрудников» без пометки «только если ты главный», каждый новенький начнёт нанимать
новых — лавина. `if __name__ == "__main__"` и есть эта пометка.

## Памятка для собеседования

- `multiprocessing` — отдельные процессы, **у каждого свой GIL** → настоящий
  параллелизм CPU-bound. API похож на потоки (`Process`, `Pool`, `map`).
- Процессы **не делят память**: нет гонок, но данные надо **сериализовать
  (pickle)** и копировать — это главная цена.
- Накладные расходы (запуск + сериализация) могут съесть выигрыш → выгодно при
  «много счёта, мало данных»; непиклящееся (лямбды) передать нельзя.
- На Windows/macOS (**spawn**) нужен **`if __name__ == "__main__"`**, иначе
  рекурсивный запуск процессов. Методы: fork/spawn/forkserver.

## Частые ошибки в ответах

- Не упомянуть цену multiprocessing (сериализация, копирование, запуск процессов).
- Применять процессы для IO-bound (там хватит потоков/asyncio без накладных
  расходов).
- Забыть `if __name__ == "__main__"` и не знать про spawn vs fork.
- Думать, что процессы делят память как потоки (нет — нужна явная передача данных).
