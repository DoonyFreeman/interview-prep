## Читаем трейс сломанного запуска

Пользователь «Маяка» спросил: **«Можно вернуть заказ №42?»** Агент ответил: «Правила возврата не найдены». Посмотри шаги и найди **место, где впервые потерялся факт о сбое**.

```solution
Поисковый сервис сообщил о таймауте. Ошибка в **обёртке инструмента**, которая превратила таймаут в `[]`. Исправление сохраняет сбой как отдельный исход. После разрешённых повторов граф сообщает, что поиск временно недоступен.
```

**Трейс** — запись конкретного запуска. В LangSmith каждый вызов модели, инструмента или другой шаг записывается как отдельный `run`, а связанные шаги образуют `trace`. Смотри на вход и выход шага, его длительность, исключение и связь с родительским вызовом. **Checkpoint** сохраняет состояние и позицию, с которых можно продолжить граф. В примере выше таймаут виден в трейсе, хотя состояние его не сохранило.

В рабочем трейсе обычно достаточно ID запуска, имени узла, статуса, времени и безопасных диагностических полей. Перед отправкой данных скрывай токены, данные клиента и содержимое закрытых документов.

## Регрессионный тест узла

Первый шаг — воспроизвести проблему на маленькой функции. Тест передаёт ей подставной поиск, который выбрасывает исключение. Адаптер `fetch_policy` переводит таймаут клиента в `TemporarySearchError`. Узел `search_policy` вызывает этот адаптер, и политика повтора из дня 6 узнаёт нужное исключение.

```python
import pytest

class TemporarySearchError(Exception):
    pass

def fetch_policy(fetch):
    try:
        return fetch()
    except TimeoutError as exc:
        # Это исключение разрешено к повтору в RetryPolicy.
        raise TemporarySearchError("search timed out") from exc

def test_timeout_reaches_the_retry_layer():
    def slow_search():
        raise TimeoutError("search timed out")

    with pytest.raises(TemporarySearchError):
        fetch_policy(slow_search)

def test_successful_search_with_no_hits_returns_empty_list():
    assert fetch_policy(lambda: []) == []
```

На старой версии первый тест упадёт, второй пройдёт. После исправления пройдут оба. Причина сохраняется через `raise ... from exc`, поэтому разработчик может увидеть исходный таймаут в цепочке исключений.

## Маршрут графа и качество ответа

![Один и тот же граф под четырьмя проверками](/lesson-media/llm/agents-debugging.svg#1200x720 "Подсветка показывает область проверки: узел, участок, весь маршрут и прогон с настоящей моделью")

| Проверка | Что подставляем и что утверждаем |
| --- | --- |
| **Один узел** | Заменяем внешний поиск функцией с известным результатом. Проверяем `TemporarySearchError` при таймауте и нормальный `[]`. |
| **Участок** | Готовим состояние с уже найденными регламентами. Тестовый граф с `InMemorySaver` получает его через `update_state(..., as_node="search_policy")`. Запускаем тот же thread до `interrupt_after=["answer"]` и проверяем, какой регламент выбран и попал в ответ. |
| **Весь граф** | Модель-заглушка возвращает заданный tool call, а поиск имитирует таймаут. Проверяем, что после исчерпания попыток итоговый `policy_status` равен `unavailable`. В отдельном прогоне проверяем паузу, `Command(resume=42)` и продолжение с тем же `thread_id`. |
| **Оценка с настоящей моделью** | Даём несколько вопросов из golden set. Проверяем, выбрала ли модель нужный инструмент, нашла ли действующий документ и опирается ли ответ на него. Допускаем эквивалентные формулировки и допустимые маршруты. |

Проверки прав доступа и запрета записи до подтверждения можно выразить точными assertions. Для ответов на основе документов используем разметку источников и отдельно оцениваем соответствие ответа контексту. Больше примеров — в [уроке об оценке RAG](/courses/llm/lessons/rag-evaluation "Как измерять поиск и оценивать ответ по источникам").

## Самостоятельное расследование

Пользователь спрашивает про тот же заказ. Агент отвечает: **«40 дней больше 30, вернуть нельзя»**.

| Шаг | Что записано в трейсе |
| --- | --- |
| `get_order` | `order_id=42`, `age_days=40`, `unused=True` |
| `search_policy` | Кандидаты: `policy_v1` — 30 дней, архивная. `policy_v2` — 45 дней, действующая. |
| `select_policy` | В контекст для ответа передана только `policy_v1`. |
| Модель | Ответила отказом и сослалась на `policy_v1`. |

Какой шаг исправить? Какими будут вход и ожидаемый результат одного регрессионного теста?

```solution
Первый неверный выбор случился в `select_policy`. Передай функции кандидатов в порядке `[policy_v1, policy_v2]` и проверь, что она возвращает `policy_v2` с 45 днями. Дополнительно можно проверить случай, где найден только архивный документ: агент сообщает, что не может подтвердить действующие правила. На этих учебных данных заказ удовлетворяет условиям, а создание заявки по-прежнему требует подтверждения.
```
