# Кортежи: неизменяемость и namedtuple

> Цель урока: понять, чем кортеж отличается от списка не только синтаксисом, но и
> смыслом, почему кортеж можно сделать ключом словаря, и когда вместо него брать
> `namedtuple`. На собесе любят спрашивать «list или tuple — в чём разница и что
> когда» — и ждут не «скобки разные», а понимания семантики.

## Неизменяемость и смысл кортежа

`tuple` — **неизменяемая** последовательность. После создания нельзя добавить,
удалить или заменить элементы. Но разница с `list` глубже синтаксиса — она
**семантическая**:

- **`list`** — однородная коллекция «многих одинаковых» вещей переменной длины
  (список пользователей, очередь задач).
- **`tuple`** — фиксированная запись «разнородных полей», где **позиция имеет
  смысл** (координата `(x, y)`, строка БД `(id, name, email)`, RGB-цвет).

```python
point = (3, 4)         # x=3, y=4 — позиции значимы
point[0] = 9           # TypeError — неизменяем
x, y = point           # распаковка — типичное использование
```

Плюсы неизменяемости: кортеж чуть компактнее и быстрее списка, потокобезопасен и
может быть **хэшируемым** (если все элементы хэшируемы).

**Важная тонкость:** неизменяемость кортежа **поверхностна**. Кортеж нельзя
переприсвоить, но если внутри лежит изменяемый объект (список), сам объект менять
можно: `t = (1, [2, 3]); t[1].append(4)` сработает — изменился список внутри, а не
сам кортеж.

**Аналогия.** Список — это тележка, куда докладывают однотипные товары. Кортеж —
заполненный бланк с фиксированными графами «имя / возраст / город»: граф ровно
столько, сколько надо, и каждая на своём месте.

## Кортеж как ключ словаря

Поскольку кортеж из хэшируемых элементов сам **хэшируем**, его можно использовать
как **ключ словаря** или элемент `set` — в отличие от списка. Это удобно для
составных ключей:

```python
prices = {("RU", "USD"): 75.0, ("RU", "EUR"): 80.0}
prices[("RU", "USD")]                # доступ по составному ключу
visited = set()
visited.add((row, col))              # координаты как элемент множества
```

Но если внутри кортежа есть изменяемый элемент, он становится **нехэшируемым**:
`{(1, [2]): "x"}` → `TypeError`, потому что хэш не может быть стабильным, если
содержимое может меняться.

**Аналогия.** Кортеж-ключ — как составной почтовый индекс «страна+город»: им можно
точно адресовать ячейку. Но если часть индекса «может поменяться» (список внутри),
почта откажется его принимать — адрес станет ненадёжным.

## namedtuple и именованные поля

Обычный кортеж читается по индексам (`row[0]`, `row[2]`), что непонятно.
**`collections.namedtuple`** даёт кортеж с **именованными полями** — те же
неизменяемость и компактность, но с читаемым доступом:

```python
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
p.x, p.y          # доступ по имени — читаемо
p[0]              # и по индексу тоже работает
x, y = p          # распаковывается как обычный кортеж
```

`namedtuple` — лёгкая замена классу для простых неизменяемых записей: меньше кода,
есть `_replace()` (вернуть копию с изменённым полем), `_asdict()`. Современная
альтернатива с типами — `typing.NamedTuple` (с аннотациями) или
`@dataclass(frozen=True)` (если нужны методы и большая гибкость).

**Аналогия.** Обычный кортеж — это анкета без подписей граф, где надо помнить «во
второй ячейке — возраст». `namedtuple` — та же анкета, но графы подписаны, и можно
писать `person.age` вместо `person[1]`.

## Памятка для собеседования

- `tuple` — **неизменяемая** последовательность; семантически — фиксированная
  запись разнородных полей (позиция значима), а `list` — однородная коллекция
  переменной длины.
- Неизменяемость **поверхностна**: изменяемый объект внутри кортежа менять можно.
- Кортеж из хэшируемых элементов **хэшируем** → годится в ключи `dict` / элементы
  `set` (составные ключи). С изменяемым элементом внутри — нехэшируем.
- `namedtuple` — кортеж с именованными полями: читаемость + неизменяемость;
  `_replace`, `_asdict`. Альтернативы: `typing.NamedTuple`,
  `@dataclass(frozen=True)`.

## Частые ошибки в ответах

- Объяснять разницу list/tuple только «скобки разные», без семантики
  (однородность vs фиксированная запись) и хэшируемости.
- Считать, что кортеж «полностью неизменяем» — забыть про изменяемые объекты
  внутри.
- Не знать, что кортеж можно использовать как ключ словаря (а список — нет).
- Не упомянуть `namedtuple`/`NamedTuple` как читаемую замену индексам.
