# Словари: хэш-таблица внутри

> Цель урока: понять, как устроен `dict` (хэш-таблица), почему доступ по ключу —
> O(1), как разрешаются коллизии и почему с Python 3.7 словари сохраняют порядок
> вставки. Это один из самых частых и глубоких вопросов: «как работает словарь
> внутри» отделяет тех, кто понимает структуры данных, от тех, кто их просто
> использует.

## Хэш-таблица и сложность O(1)

`dict` реализован как **хэш-таблица**. При сохранении пары ключ-значение Python:
1) вычисляет `hash(key)`, 2) превращает хэш в **индекс ячейки** (по модулю
размера таблицы), 3) кладёт туда запись. Поиск повторяет шаги 1–2 и сразу
попадает в нужную ячейку — поэтому доступ, вставка и удаление по ключу —
**в среднем O(1)**, независимо от размера словаря.

```python
d = {"a": 1, "b": 2}
d["a"]            # O(1) — хэш ключа → ячейка
d["c"] = 3        # O(1) вставка
"b" in d          # O(1) проверка наличия (в отличие от list — O(n))
del d["a"]        # O(1) удаление
```

Цена скорости — память (таблица держит запас пустых ячеек ради низкой плотности
заполнения) и требование к ключам: они должны быть **хэшируемыми** (неизменяемый
`hash` + `eq`), поэтому ключом не может быть `list` или `dict`.

**Аналогия.** Хэш-таблица — это гардероб с нумерованными крючками, где номер
крючка вычисляется из самой вещи (по её «хэшу»). Не нужно обходить весь гардероб
— вы сразу идёте к нужному крючку. Поэтому поиск мгновенный.

## Коллизии

**Коллизия** — когда разные ключи дают один и тот же индекс ячейки. Это
неизбежно (ключей больше, чем ячеек), и хэш-таблица обязана их разрешать. CPython
использует **открытую адресацию** (open addressing): если ячейка занята,
по детерминированному правилу пробуются другие ячейки, пока не найдётся свободная
(или искомый ключ).

Из-за коллизий O(1) — это **средний** случай. В вырожденном (все ключи в одну
ячейку, плохой хэш) операции деградируют к O(n). Поэтому важно, чтобы `__hash__`
хорошо «разбрасывал» значения. Когда таблица заполняется выше порога, она
**увеличивается** (rehash) — все элементы перераскладываются по новой, большей
таблице.

```python
# равные объекты обязаны иметь равный хэш — иначе словарь «потеряет» ключ:
class Bad:
    def __eq__(self, o): return True
    # __hash__ не согласован → ключи ведут себя непредсказуемо
```

**Аналогия.** Коллизия — два человека, которым выпал один номер крючка. Правило
разрешения — «занято? иди к следующему свободному крючку по списку». Если плохой
способ нумерации свалил всех в один угол, искать снова приходится перебором.

## Порядок вставки (3.7+)

С **Python 3.7** словари **гарантированно сохраняют порядок вставки** (в 3.6 это
была деталь реализации CPython, с 3.7 — часть спецификации языка). Раньше порядок
был «случайным», и для упорядоченности использовали `OrderedDict`.

```python
d = {}
d["c"] = 1; d["a"] = 2; d["b"] = 3
list(d)            # ['c', 'a', 'b'] — порядок вставки, не сортировка!
```

Важно: это **порядок вставки**, а не сортировка по ключам. `OrderedDict` всё ещё
полезен, когда нужна семантика порядка в равенстве (`==` учитывает порядок) или
методы вроде `move_to_end()`. Достигается это «компактным» представлением:
отдельный плотный массив записей в порядке вставки + хэш-таблица индексов на него
(это же сэкономило память).

**Аналогия.** Современный словарь — гардероб с быстрым поиском по крючкам ПЛЮС
журнал, в котором по порядку записано, кто и когда сдал вещь. Поиск — мгновенный,
а обход — в порядке поступления.

## Полезные методы и подтипы

Минимум для собеса: `get(key, default)` (без `KeyError`), `setdefault`,
`update`, `keys/values/items` (это **представления**, отражающие изменения
словаря), `pop`, dict comprehension `{k: v for ...}`. Из `collections`:

- **`defaultdict(factory)`** — автоматически создаёт значение по умолчанию для
  отсутствующего ключа (`defaultdict(list)` для группировки — частый приём).
- **`Counter`** — подсчёт частот: `Counter(words).most_common(3)`.
- **`OrderedDict`** — когда важны порядок в равенстве и `move_to_end`.

```python
from collections import defaultdict
groups = defaultdict(list)
for user in users:
    groups[user.city].append(user)   # не нужен if city in groups
```

**Аналогия.** `defaultdict` — гардеробщик, который сам вешает новую вешалку, если
крючка ещё нет; не нужно каждый раз проверять «а есть ли уже место».

## Памятка для собеседования

- `dict` — **хэш-таблица**: hash(key) → индекс ячейки → доступ/вставка/удаление в
  среднем **O(1)**; `in` тоже O(1) (против O(n) у списка).
- Ключи должны быть **хэшируемыми** (неизменяемыми); `list`/`dict` ключом быть не
  могут.
- **Коллизии** разрешаются открытой адресацией; в среднем O(1), в худшем (плохой
  хэш) — O(n); при заполнении — rehash в большую таблицу.
- С **Python 3.7** сохраняется **порядок вставки** (часть спецификации), но это не
  сортировка.
- `get/setdefault/update/items`-представления; `defaultdict`, `Counter`,
  `OrderedDict` из `collections`.

## Частые ошибки в ответах

- Не уметь объяснить, почему доступ O(1) (через хэш → индекс ячейки).
- Говорить, что dict «всегда O(1)» без оговорки про средний/худший случай и
  коллизии.
- Путать «порядок вставки» (3.7+) с «сортировкой по ключам».
- Использовать `list`/`dict` как ключ и не понимать `TypeError: unhashable`.
- Писать `if k in d: d[k].append(...)` вместо `defaultdict`/`setdefault`.
