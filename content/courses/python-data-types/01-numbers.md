# Числа: int, float, Decimal и точность

> Цель урока: понять, почему `0.1 + 0.2 != 0.3`, чем `int` в Python отличается от
> чисел в C, и когда вместо `float` нужен `Decimal`. Вопрос про точность
> `float` — классика собеседований, особенно для тех, кто работает с деньгами.

## int произвольной точности

В Python `int` имеет **произвольную точность** — он ограничен только памятью, а не
размером машинного слова (нет «64-битного предела», нет переполнения). Большие
числа просто работают:

```python
2 ** 1000        # огромное число, считается точно, без переполнения
factorial = 1
for i in range(1, 100): factorial *= i   # 100! целиком, без потери цифр
```

Под капотом большое число хранится как массив «цифр» по основанию 2^30, и
арифметика над маленькими числами быстрая, а над большими — медленнее (но
корректная). Это отличает Python от C/Java, где `int` переполняется. `bool` —
**подтип `int`**: `True == 1`, `False == 0`, и их можно складывать
(`sum([True, True, False]) == 2`) — удобно для подсчёта.

**Аналогия.** Машинный `int` — это спидометр с фиксированным числом разрядов:
доехал до предела — обнулился (переполнение). Python-`int` — это лист бумаги, на
котором всегда можно дописать ещё цифру.

## float и ошибки точности (IEEE-754)

`float` в Python — это 64-битное число с плавающей точкой по стандарту
**IEEE-754** (double). Главное следствие: дробные числа хранятся в **двоичной**
системе, а многие привычные десятичные дроби (0.1, 0.2) в двоичной —
**бесконечные периодические**, поэтому хранятся приближённо.

```python
0.1 + 0.2            # 0.30000000000000004
0.1 + 0.2 == 0.3     # False!
```

Это **не баг Python**, а свойство IEEE-754 (так же ведут себя C, Java, JS).
Практические правила:

- **Не сравнивайте float через `==`.** Используйте `math.isclose(a, b)` (с
  допуском) или работайте с округлением.
- Помните про потерю точности при сложении многих чисел и про «поглощение»
  маленьких слагаемых большими.
- Для денег и точных десятичных вычислений `float` **не подходит**.

**Аналогия.** Float — это как перевести 1/3 в десятичную дробь и записать только
несколько знаков: 0.333. Сложите три таких — получите 0.999, а не 1. Двоичная
система не может точно записать 0.1 ровно так же, как десятичная не может 1/3.

## Decimal, Fraction, complex

Когда точность критична, в стандартной библиотеке есть специальные типы:

- **`Decimal`** (модуль `decimal`) — десятичная арифметика с **контролируемой
  точностью**. Хранит числа в десятичной системе, поэтому `Decimal('0.1') +
  Decimal('0.2') == Decimal('0.3')`. **Обязателен для денег**, финансов,
  бухгалтерии. Важно создавать из **строки** (`Decimal('0.1')`), а не из float
  (`Decimal(0.1)` унаследует ошибку float).
- **`Fraction`** (модуль `fractions`) — точные **рациональные** числа (дроби
  «числитель/знаменатель»): `Fraction(1, 3) + Fraction(1, 3) ==
  Fraction(2, 3)` без потери точности.
- **`complex`** — встроенные комплексные числа: `3 + 4j`, с `.real` и `.imag`.

```python
from decimal import Decimal
Decimal('0.1') + Decimal('0.2')   # Decimal('0.3') — точно!
0.1 + 0.2                          # 0.30000000000000004 — float
```

**Аналогия.** Float — быстрый, но «округляющий» калькулятор; Decimal — бухгалтер с
точными копейками; Fraction — математик, держащий ответ в виде дроби, а не
десятичной записи.

## Памятка для собеседования

- `int` — **произвольная точность**, без переполнения (ограничен памятью), в
  отличие от C/Java. `bool` — подтип `int` (`True == 1`).
- `float` — IEEE-754 double; десятичные дроби хранятся приближённо, поэтому
  `0.1 + 0.2 != 0.3`. Это не баг, а свойство двоичного представления.
- Не сравнивать float через `==` — использовать `math.isclose`.
- Для денег — **`Decimal`** (создавать из строки!); для точных дробей —
  `Fraction`; для комплексных — `complex`.

## Частые ошибки в ответах

- Считать `0.1 + 0.2 != 0.3` багом Python (это IEEE-754, общий для всех языков).
- Использовать `float` для денежных расчётов.
- Создавать `Decimal(0.1)` из float вместо `Decimal('0.1')` (наследует ошибку).
- Не знать, что Python `int` не переполняется и имеет произвольную точность.
- Сравнивать float-результаты вычислений через `==` без допуска.
