# Множества: set и frozenset

> Цель урока: понять, что `set` — это та же хэш-таблица, что и `dict`, но без
> значений, какие операции он делает за O(1), и когда множество резко упрощает код
> (дедупликация, проверка принадлежности, операции над группами). Вопрос «чем set
> лучше list для проверки наличия» — быстрый способ проверить чувство сложности.

## Что такое set и почему он быстрый

`set` — **неупорядоченная коллекция уникальных хэшируемых элементов**, реализованная
как хэш-таблица (как `dict`, только хранятся ключи без значений). Отсюда главные
свойства:

- **Проверка принадлежности `x in s` — O(1)** (против O(n) у списка).
- **Добавление/удаление — O(1)**.
- Элементы **уникальны** (повторы автоматически отбрасываются) и должны быть
  **хэшируемыми** (нельзя положить `list`).
- Порядок **не гарантирован** (это не отсортированная и не упорядоченная по
  вставке структура).

```python
s = {1, 2, 3}
3 in s            # O(1) — мгновенно
s.add(4)          # O(1)
{1, 2, 2, 3}      # {1, 2, 3} — дубликаты ушли
{}                # это пустой dict! пустое множество — set()
```

Главный практический выигрыш — **дедупликация** (`set(my_list)`) и **быстрые
проверки наличия** в больших коллекциях. Если в коде есть `if x in big_list` в
цикле — почти всегда стоит превратить список в множество.

**Аналогия.** Set — это список гостей на входе: швейцар по фамилии мгновенно
находит, в списке вы или нет (O(1)), и одну фамилию дважды в список не впишут. А
искать в обычном «списке-простыне» (list) пришлось бы читать сверху вниз.

## Операции над множествами

Множества поддерживают математические операции — это их вторая суперсила,
позволяющая выражать логику «общие/разные/все» без циклов:

```python
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}
a | b      # {1,2,3,4,5,6}  объединение (union)
a & b      # {3, 4}         пересечение (intersection)
a - b      # {1, 2}         разность (difference)
a ^ b      # {1,2,5,6}      симметрическая разность
a <= b     # False          подмножество (issubset)
```

Типичные применения: найти общие теги у двух пользователей (`tags_a & tags_b`),
вычислить новых элементов (`new - old`), проверить, что все требуемые права
присутствуют (`required <= granted`). Это читаемее и быстрее, чем вложенные циклы.

**Аналогия.** Операции множеств — как диаграммы Венна: пересечение — «что общего у
двух кругов», разность — «что есть у первого, но нет у второго». Один оператор
вместо цикла с проверками.

## frozenset

**`frozenset`** — **неизменяемая** версия множества. Раз он неизменяем, он
**хэшируем**, поэтому его можно класть в другой `set` или использовать как **ключ
словаря** — то, что обычный `set` не умеет:

```python
s = {1, 2}
{s: "x"}              # TypeError: set нехэшируем
fs = frozenset({1, 2})
{fs: "x"}             # OK — frozenset хэшируем
{frozenset({1, 2}), frozenset({3, 4})}   # множество множеств
```

Применяют `frozenset` для неизменяемых наборов-констант, ключей-комбинаций и когда
нужно множество множеств. Соотношение `set`↔`frozenset` такое же, как `list`↔`tuple`
или изменяемый объект ↔ его неизменяемая хэшируемая форма.

**Аналогия.** `frozenset` — это запаянный набор: содержимое не поменять, зато его
можно использовать как «штамп» (ключ), потому что он гарантированно не изменится.

## Памятка для собеседования

- `set` — хэш-таблица без значений: `in`, `add`, `remove` — **O(1)**; элементы
  уникальны и хэшируемы; порядок не гарантирован.
- Главные применения: **дедупликация** (`set(lst)`) и **быстрые проверки
  наличия** вместо `x in list` (O(n) → O(1)).
- Операции: `|` объединение, `&` пересечение, `-` разность, `^` симм. разность,
  `<=` подмножество — заменяют циклы.
- `{}` — пустой **dict**; пустое множество — `set()`.
- **`frozenset`** — неизменяемый и потому **хэшируемый**: годится в ключи `dict` и
  во множество множеств.

## Частые ошибки в ответах

- Не знать, что `x in set` — O(1), а `x in list` — O(n); не предлагать set для
  частых проверок.
- Думать, что `{}` создаёт пустое множество (это пустой словарь).
- Пытаться положить `set` в ключ словаря (нужен `frozenset`).
- Класть в множество изменяемый/нехэшируемый объект (`list`) и не понимать ошибку.
- Решать задачи «общие/разные элементы» циклами вместо операций над множествами.
