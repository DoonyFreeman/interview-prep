# Сложность операций: шпаргалка Big-O

> Цель урока: собрать в одну ясную картину сложность операций встроенных типов и
> научиться **выбирать структуру данных под задачу**. На собесе часто дают код и
> спрашивают «какая здесь сложность» или «как ускорить» — и правильный ответ почти
> всегда «возьми другую структуру».

## Зачем знать сложность встроенных типов

**Big-O** описывает, как растёт время операции с размером данных `n`. Знать её для
встроенных типов нужно, чтобы не написать случайно квадратичный код. Самый частый
антипаттерн на ревью — **`if x in big_list` внутри цикла**: это O(n) внутри O(n) =
**O(n²)**. Замена списка на множество делает проверку O(1) и весь цикл — O(n).

```python
# O(n^2): для каждого из n элементов — линейный поиск по списку
seen_list = []
for x in data:
    if x not in seen_list:       # O(n) каждая проверка!
        seen_list.append(x)

# O(n): множество даёт O(1) на проверку
seen = set()
for x in data:
    if x not in seen:            # O(1)
        seen.add(x)
```

**Аналогия.** Big-O — это не «сколько секунд», а «как быстро становится хуже,
когда данных больше». O(1) — лифт (неважно, какой этаж), O(n) — лестница, O(n²) —
обходить каждый этаж ради каждого этажа.

## Списки и кортежи

| Операция | Сложность | Комментарий |
|---|---|---|
| индекс `lst[i]` | O(1) | прямой доступ (массив) |
| `append` / `pop()` (с конца) | O(1)* | амортизированно |
| `insert(0,x)` / `pop(0)` | O(n) | сдвиг всех элементов |
| `x in lst` | O(n) | линейный поиск |
| срез `lst[a:b]` | O(k) | копия из k элементов |
| `sort()` | O(n log n) | Timsort |
| `len(lst)` | O(1) | длина хранится |

Вывод: список хорош для доступа по индексу и добавления в конец; плох для вставок
в начало и поиска по значению. Нужны края с двух сторон — `deque`; нужен быстрый
поиск — `set`/`dict`.

## Словари и множества

| Операция | Сложность | Комментарий |
|---|---|---|
| `d[key]` / `key in d` | O(1) среднее | хэш → ячейка |
| `d[key] = v` / `del d[key]` | O(1) среднее | худший O(n) при коллизиях |
| `x in set` / `add` / `remove` | O(1) среднее | как dict |
| операции множеств `&`, `\|`, `-` | O(len) | по размеру операндов |
| `len(d)` | O(1) | |

Ключевое: dict и set дают **O(1) в среднем** для доступа и проверки наличия —
ценой памяти и требования хэшируемости ключей. Это причина, по которой их берут
для индексов, кэшей, дедупликации и проверок принадлежности.

**Аналогия.** Список — искать книгу, проходя вдоль полки (O(n)). Словарь —
библиотечный каталог: по шифру сразу к нужной полке (O(1)).

## Как выбирать структуру под задачу

Практический чек-лист — что спросить себя:

- **Нужен быстрый поиск «есть ли элемент»?** → `set` (O(1)), не `list`.
- **Нужно сопоставление ключ→значение, индекс, кэш?** → `dict` (O(1)).
- **Нужны уникальные элементы / убрать дубликаты?** → `set`.
- **Очередь FIFO, добавление с обоих концов?** → `deque` (O(1)), не `list`.
- **Порядок и доступ по индексу, добавление в конец?** → `list`.
- **Фиксированная неизменяемая запись, ключ словаря?** → `tuple`.
- **Подсчёт частот?** → `Counter`. **Группировка?** → `defaultdict(list)`.
- **Постоянно поддерживать отсортированность / брать минимум?** → куча
  (`heapq`), O(log n) на вставку/извлечение.

Главная мысль для собеседования: **сложность алгоритма часто определяется выбором
структуры данных**. Прежде чем оптимизировать код, спросите, та ли структура
выбрана — замена `list` на `set`/`dict` нередко превращает O(n²) в O(n).

**Аналогия.** Выбор структуры — как выбор транспорта под маршрут: на соседнюю
улицу — пешком (list), через весь город — метро (dict/set). Неправильный выбор не
чинится «более быстрой ходьбой».

## Памятка для собеседования

- Big-O — рост времени с размером данных; цель — не написать случайно O(n²).
- Классический антипаттерн: `x in list` в цикле = O(n²) → заменить на `set`
  (O(1)) = O(n).
- Список: индекс/append с конца O(1); вставка в начало и `in` — O(n); sort —
  O(n log n).
- dict/set: доступ, вставка, `in` — **O(1) в среднем** (худший O(n) при
  коллизиях); цена — память.
- Выбор структуры под задачу: поиск/уникальность → set; ключ→значение → dict;
  очередь/края → deque; частоты → Counter; min/sorted → heapq.

## Частые ошибки в ответах

- Не замечать квадратичность от `in list` / `insert(0)` в цикле.
- Говорить «dict всегда O(1)» без оговорки про средний/худший случай.
- Использовать список там, где по сложности нужны set/dict/deque.
- Путать O(1) амортизированное (`append`) с гарантированным O(1) на каждой
  операции.
- Оптимизировать код, не задумавшись, та ли вообще структура данных выбрана.
