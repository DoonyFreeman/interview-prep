# Строки: неизменяемость, Unicode, bytes

> Цель урока: понять, что строка — неизменяемая последовательность Unicode-кодовых
> точек, чем `str` отличается от `bytes`, и почему склейка строк в цикле через `+`
> — антипаттерн. Вопросы про кодировки и `bytes` vs `str` любят на бэкенд-собесах,
> потому что это ежедневная боль при работе с файлами, сетью и БД.

## Неизменяемость строк

`str` — **неизменяемый** тип. Любая «модификация» создаёт новую строку, а не
меняет существующую:

```python
s = "hello"
s[0] = "H"        # TypeError: строки не поддерживают присваивание по индексу
s = s.upper()     # создаётся новая строка "HELLO", имя s перепривязано
```

Главное практическое следствие — **склейка строк в цикле через `+` неэффективна**:
каждая операция создаёт новую строку и копирует всё накопленное, давая O(n²).
Правильно — собрать части в список и склеить один раз через `str.join`:

```python
# плохо: O(n^2) — каждый += копирует всю строку
result = ""
for chunk in chunks:
    result += chunk

# хорошо: O(n) — одна склейка
result = "".join(chunks)
```

Неизменяемость даёт и плюсы: строки **хэшируемы** (можно класть в `set`, ключи
`dict`), потокобезопасны и могут интернироваться.

**Аналогия.** Строка — надпись, выгравированная на табличке: «исправить» букву
нельзя, только заказать новую табличку. Клеить строки в цикле через `+` — как
каждый раз перегравировывать всю табличку ради одной буквы.

## Unicode, bytes и кодировки

Критически важное различие для бэкенда:

- **`str`** — последовательность **Unicode-кодовых точек** (абстрактные символы:
  буквы, иероглифы, эмодзи). Это «текст».
- **`bytes`** — последовательность **байтов** (числа 0–255). Это «сырые данные»:
  то, что реально летит по сети, лежит в файле, приходит из сокета.

Между ними — **кодировка** (чаще всего **UTF-8**): `encode` превращает текст в
байты, `decode` — байты в текст.

```python
text = "привет"
data = text.encode("utf-8")     # b'\xd0\xbf\xd1\x80...' — bytes
back = data.decode("utf-8")     # "привет" — str снова
len("café")                      # 4 символа (str)
len("café".encode("utf-8"))      # 5 байтов (é = 2 байта в UTF-8)
```

Правило «сэндвича Unicode»: **декодируй на входе, работай с `str` внутри, кодируй
на выходе**. Самые частые баги — `UnicodeDecodeError` (неверная кодировка при
чтении) и путаница «символы против байтов» (для не-ASCII `len(str)` ≠
`len(bytes)`).

**Аналогия.** `str` — это смысл текста («мысль»), `bytes` — его запись конкретным
алфавитом на бумаге. Кодировка — правила, какими значками записать мысль. Прочитать
запись чужим алфавитом (неверной кодировкой) — получить кракозябры.

## Форматирование строк

Три способа, но предпочтителен один:

```python
name, age = "Аня", 30
f"{name} — {age}"            # f-strings — современный стандарт (быстро, читаемо)
"{} — {}".format(name, age)  # .format() — до f-strings / для отложенных шаблонов
"%s — %d" % (name, age)      # %-стиль — старый, в логировании ещё встречается
```

**f-strings** (с Python 3.6) — самый быстрый и читаемый вариант: выражения прямо в
строке, есть мини-язык форматирования (`f"{x:.2f}"`, `f"{n:>10}"`, `f"{x=}"` для
отладки). `.format()` полезен, когда шаблон задаётся отдельно от данных.
`%`-форматирование оставляют для совместимости и в `logging` (там оно
«ленивое» — подстановка только если запись реально пишется).

**Аналогия.** f-string — это бланк с вписанными прямо в текст полями: видно сразу,
где что подставится. `.format()` — бланк с пронумерованными пропусками и
отдельным списком значений.

## Частые методы и интернирование

Строковые методы возвращают **новые** строки (исходная неизменна). Полезный
минимум для собеса: `strip/lstrip/rstrip`, `split/rsplit/splitlines`, `join`,
`replace`, `startswith/endswith`, `find/index`, `lower/upper/title`,
`isdigit/isalpha`, `format`, `encode`.

**Интернирование строк** — оптимизация CPython: некоторые строки (короткие,
похожие на идентификаторы, строковые литералы) кэшируются и переиспользуются, так
что они ссылаются на один объект. Поэтому иногда `a is b` для одинаковых строк
даёт `True` — но это **деталь реализации**, и сравнивать строки нужно через `==`,
а не `is`.

```python
a = "hello"; b = "hello"
a is b        # часто True (интернирование литералов), но НЕ полагаться
a == b        # True — правильный способ сравнения значений
```

**Аналогия.** Интернирование — как один общий экземпляр часто употребляемого слова
в типографии: вместо набора заново берут готовую литеру. Полезно для скорости, но
полагаться на «это та же литера» (`is`) в логике нельзя.

## Памятка для собеседования

- `str` — **неизменяемый**; «изменение» создаёт новую строку. Склейка в цикле
  через `+` — O(n²), правильно `"".join(parts)` — O(n).
- `str` = Unicode-кодовые точки (текст); `bytes` = сырые байты. Между ними —
  кодировка (`encode`/`decode`, обычно UTF-8). Для не-ASCII `len(str) != len(bytes)`.
- «Сэндвич Unicode»: декодируй на входе, работай со `str`, кодируй на выходе.
- Форматирование: **f-strings** — стандарт; `.format()` для отдельных шаблонов;
  `%` — legacy/logging.
- Интернирование строк — оптимизация CPython; сравнивать строки через `==`, не
  `is`.

## Частые ошибки в ответах

- Пытаться изменить строку по индексу или считать её изменяемой.
- Склеивать строки в цикле через `+=` (квадратичная сложность).
- Путать `str` и `bytes`, не уметь объяснить роль кодировки и `encode/decode`.
- Считать, что `len(str)` всегда равно числу байтов (неверно для UTF-8 не-ASCII).
- Сравнивать строки через `is`, полагаясь на интернирование.
