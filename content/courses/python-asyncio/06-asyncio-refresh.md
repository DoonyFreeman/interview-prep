# Asyncio под нагрузкой: быстрый практикум

> **13 минут вместе с практикой.** Ты отправляешь документы к API эмбеддингов. Проследи, что происходит при ожидании, ошибке и переполнении очереди.

## Прочитай шкалу двух запросов

Вызов `async def` создаёт объект корутины. `await` выполняет или ждёт операцию. Если ей действительно нужно ждать, событийный цикл может продвинуть другую задачу. `create_task()` планирует корутину как отдельную задачу. Два последовательных `await` в одной корутине сами по себе конкурентный запуск не создают.

Представь независимые запросы A на 300 мс и Б на 100 мс. Для простоты накладные расходы равны нулю.

| Как запустили | Что видно на шкале | Время |
| --- | --- | --- |
| `await a(); await b()` | A от 0 до 300 → Б от 300 до 400 | ≈ 400 мс |
| `await asyncio.gather(a(), b())` | A от 0 до 300 · Б от 0 до 100 | ≈ 300 мс |
| A внутри делает `time.sleep(0.3)` первым | A держит поток цикла до 300 → Б может начать после 300 | ≈ 400 мс |

**Проверь себя.** В конкурентном запуске Б готов раньше. Каким будет порядок результатов `gather(a(), b())`? Что взять, если нужен первый готовый результат?

```solution
`gather` вернёт результаты **[A, Б]** в порядке аргументов. `as_completed()` позволяет забирать результаты по готовности. `asyncio.wait()` отдаёт множества завершённых и ещё ожидающих задач. Если запускаешь задачу через `asyncio.create_task()`, сохрани ссылку и забери результат. Для группы запускай корутины сразу через `group.create_task()`.
```

Для синхронного SDK в `async def` используй `to_thread()` или явный потоковый пул через `run_in_executor()`. Для тяжёлого чистого Python подойдёт пул процессов. Если цикл неожиданно замирает, `PYTHONASYNCIODEBUG=1` и `loop.slow_callback_duration` помогают увидеть, какой шаг долго удерживал цикл. [Отладка asyncio](https://docs.python.org/3/library/asyncio-dev.html)

## Реши, что делать при сбое

A падает с обычным исключением через 100 мс. Б успешно закончил бы через 300 мс. Поведение зависит от того, нужен ли тебе частичный результат.

| Механизм | Что увидит вызывающий код |
| --- | --- |
| `gather(a(), b())` | Ошибка A сразу передаётся вызывающему коду. Сам `gather` не отменяет Б из-за этой ошибки. Б может продолжить, пока цикл работает. |
| `gather(a(), b(), return_exceptions=True)` | После обеих задач получим `[исключение A, результат Б]`. Каждый элемент нужно проверить. |
| `async with asyncio.TaskGroup()` | Группа запрашивает отмену Б, ждёт завершения задач и поднимает `ExceptionGroup` для обычных ошибок. |

Независимые документы можно обрабатывать с частичным успехом. Если для результата обязательны оба шага, подходит `TaskGroup` (Python 3.11+). У отмены есть время на очистку. После неё уже записанные данные остаются, поэтому повтор операции планируй с учётом побочных эффектов.

Этот пример показывает, что группа ждёт очистки. `Event` задаёт порядок: задача `fail()` падает после того, как `slow()` вошла в работу.

```python
import asyncio

async def main():
    started = asyncio.Event()

    async def slow():
        try:
            started.set()
            await asyncio.sleep(10)
        finally:
            print("Ресурс освобождён")

    async def fail():
        await started.wait()
        raise ValueError("Ошибочный документ")

    try:
        async with asyncio.TaskGroup() as group:
            group.create_task(slow())
            group.create_task(fail())
    except* ValueError:
        print("Ошибка обработана")

asyncio.run(main())
```

**Таймаут.** `asyncio.timeout(1)` задаёт срок для блока, `asyncio.wait_for(operation(), 1)` — для одного ожидания. При отмене освобождай ресурсы через `async with` или `finally` и пропускай `CancelledError` выше. `wait_for` ждёт обработки отмены, поэтому фактическая длительность может превысить срок. Синхронная функция, уже запущенная через `to_thread()`, может продолжить работу после отмены ожидания. Для сетевого SDK выставляй и его собственный таймаут.

**Проверь себя.** Где поставить `asyncio.timeout(1)`, если пользователь должен ждать не больше секунды и ожидание свободного слота тоже входит в бюджет?

```solution
Поставь таймаут **снаружи семафора**, чтобы в него вошли ожидание слота и вызов API. Таймаут внутри семафора отсчитывал бы только время после получения слота. Сам таймаут инициирует отмену, а фактический выход зависит от того, как быстро операция на неё реагирует.
```

[Группы задач, таймауты и отмена](https://docs.python.org/3/library/asyncio-task.html)

## Ограничи очередь и нагрузку

В примере один воркер занят, а очередь вмещает две ожидающие заявки. Очередь задаёт, сколько можно поставить в ожидание. Когда места нет, производитель притормаживает. Это **backpressure**.

| Чем ограничиваем | Что контролируем |
| --- | --- |
| `asyncio.Queue(maxsize=N)` | Сколько заявок ждёт воркера. Если входящий HTTP-поток нельзя бесконечно держать открытым, ограничь ожидание места или явно сообщи о перегрузке. |
| Воркеры / `Semaphore(N)` | Сколько операций одновременно выполняется. При фиксированном числе воркеров, каждый из которых делает один вызов, они уже ограничивают одновременность. |
| Пул HTTP-соединений | Сколько соединений держит клиент. У HTTP/2 несколько запросов могут использовать одно соединение. |
| Ограничитель квоты API | Сколько запросов и токенов допускается за окно времени. Для нескольких процессов с общей квотой нужен общий учёт или выделенный бюджет каждому. |

**Посчитай.** Два слота загружены постоянно, ответ приходит через 0,5 секунды. Квота — 60 запросов в минуту. Хватит ли двух слотов для соблюдения квоты?

```solution
Один слот успевает выполнить 2 запроса в секунду, два — 4. Это **240 в минуту** при постоянной загрузке и без накладных расходов. Чтобы уложиться в 60, нужен отдельный ограничитель частоты. Квоту по токенам учитывают отдельно. При 429 учитывай `Retry-After`, если сервер его прислал, и укладывай число повторов в общий срок.
```

На собеседовании проверь четыре вещи: **что блокирует цикл, где обрабатывается ошибка, сколько работы может ждать и как соблюдается квота**.
