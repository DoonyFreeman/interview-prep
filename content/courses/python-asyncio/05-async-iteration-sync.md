# Async-итерация, контекст-менеджеры и синхронизация

> Цель урока: освоить асинхронные аналоги привычных конструкций — `async with`,
> `async for`, асинхронные генераторы, `asyncio.Queue` и примитивы синхронизации
> (`Lock`, `Semaphore`). Без них реальный async-код не пишется, и на собесе
> спрашивают «как ограничить число одновременных запросов» и «что такое async for».

## Async context manager: async with

Обычный `with` (см. курс про идиомы) не годится, если вход/выход в контекст
требуют **ожидания** (открыть async-соединение, взять async-блокировку, начать
транзакцию). Для этого — **`async with`** и протокол **`__aenter__`/`__aexit__`**
(их async-версии), где вход и выход можно `await`-ить.

```python
async with aiohttp.ClientSession() as session:     # __aenter__ — await
    async with session.get(url) as resp:           # вложенные async-контексты
        data = await resp.json()
# __aexit__ — await: корректно закрыть соединение, даже при исключении
```

Свой async-контекст-менеджер делают через `__aenter__`/`__aexit__` или, проще,
через **`@asynccontextmanager`** (из `contextlib`) — async-генератор с одним
`yield`:

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def db_transaction(conn):
    tx = await conn.begin()           # вход (await)
    try:
        yield tx
        await tx.commit()             # выход при успехе (await)
    except Exception:
        await tx.rollback()           # откат при ошибке
        raise
```

Именно так в FastAPI устроен `lifespan` и async-сессии БД: ресурс с гарантированной
async-очисткой. `async with` нужен везде, где **закрытие ресурса само асинхронно**.

**Аналогия.** `async with` — та же «расписка на инструмент» (как `with`), но и
выдача, и сдача требуют похода на склад, который отвечает не сразу: вы ждёте на
входе и на выходе, не блокируя при этом весь офис (цикл).

## Async-генераторы и async for

Когда источник данных отдаёт элементы **с ожиданием** (страницы API, строки из
async-курсора БД, поток сообщений), нужен **асинхронный генератор** — `async def` с
`yield` — и обход через **`async for`** (протокол `__aiter__`/`__anext__`).

```python
async def fetch_pages(url):
    page = url
    while page:
        resp = await http_get(page)       # ждём каждую страницу
        yield resp.items                  # лениво отдаём
        page = resp.next_page

async for items in fetch_pages(start_url):    # async for — ждёт каждый элемент
    process(items)
```

Это ленивый конвейер, как обычные генераторы (см. идиомы), но **на каждом шаге
возможно ожидание IO**, и цикл не блокируется — пока ждём следующую порцию, событийный
цикл обслуживает другие задачи. Есть и **async-comprehension**: `[x async for x in
agen()]`. Ключевое: обычный `for`/генератор не умеет `await` внутри — для async-
источников нужны `async for` и async-генераторы.

**Аналогия.** Async-генератор — официант, подающий блюда по одному (генератор), но
между подачами он не стоит столбом, а обслуживает другие столики (await на ожидании
кухни). `async for` — вы едите по мере готовности, не блокируя ресторан.

## asyncio.Queue

**`asyncio.Queue`** — асинхронная очередь для обмена данными **между корутинами**
(паттерн producer/consumer) внутри одного цикла. Её `put`/`get` — **корутины**:
`await queue.get()` **не блокирует** цикл, а уступает управление, пока в очереди
пусто.

```python
queue = asyncio.Queue(maxsize=100)

async def producer():
    for item in source:
        await queue.put(item)          # ждёт, если очередь полна (backpressure)

async def consumer():
    while True:
        item = await queue.get()       # ждёт, если пусто, не блокируя цикл
        await handle(item)
        queue.task_done()
```

Зачем: развязать производство и потребление, сгладить скорость, сделать **пул
воркеров-корутин**. `maxsize` даёт **backpressure** — производитель притормаживает,
если потребители не успевают. Это не `queue.Queue` из `threading` (та для потоков,
с блокировками) — `asyncio.Queue` работает в кооперативной модели одного потока.

**Аналогия.** `asyncio.Queue` — лента-конвейер между двумя работниками, которые
«засыпают», когда им нечего делать (пусто) или некуда класть (полно), освобождая
руки для другого. Никто не стоит и не блокирует цех.

## Синхронизация: Lock и Semaphore

Хотя asyncio однопоточный, синхронизация всё равно нужна: между точками `await`
другая задача может вклиниться и нарушить инвариант, а ещё нужно **ограничивать
конкурентность**.

- **`asyncio.Lock`** — взаимное исключение для критической секции, охватывающей
  `await` (нельзя двум корутинам быть в ней одновременно).
- **`asyncio.Semaphore(n)`** — самый частый практический инструмент: **ограничить
  число одновременных** операций (например, не больше N параллельных HTTP-запросов/
  соединений к API), чтобы не перегрузить ресурс.

```python
sem = asyncio.Semaphore(10)            # максимум 10 одновременных запросов

async def fetch(url):
    async with sem:                    # ждёт, если уже 10 в работе
        return await http_get(url)

# запускаем 1000 задач, но в любой момент активно не больше 10
await asyncio.gather(*(fetch(u) for u in urls))
```

Это типичный ответ на «как сделать 1000 запросов, но не больше 10 одновременно» —
**семафор**. Без него `gather` запустил бы все 1000 разом и положил бы сервер/API.
Есть также `asyncio.Event` (сигнал) и `Condition`.

**Аналогия.** Semaphore — это N пропусков на вход в зал: 1000 желающих, но внутри
одновременно только 10; остальные ждут у двери, пока кто-то выйдет. Так нагрузка не
сносит зал (внешний сервис).

## Памятка для собеседования

- **`async with`** + `__aenter__`/`__aexit__` (или **`@asynccontextmanager`**) —
  для ресурсов с **async-входом/выходом** (соединения, транзакции, lifespan).
- **Async-генератор** (`async def` + `yield`) + **`async for`**
  (`__aiter__`/`__anext__`) — ленивый поток с **ожиданием на каждом шаге** (страницы
  API, async-курсор). Есть async-comprehension.
- **`asyncio.Queue`** — producer/consumer между корутинами; `put`/`get` —
  **корутины** (не блокируют цикл), `maxsize` даёт backpressure. Не путать с
  `queue.Queue` (потоки).
- Синхронизация: **`asyncio.Lock`** (критическая секция вокруг `await`),
  **`asyncio.Semaphore(n)`** — **ограничить число одновременных** операций (частый
  ответ про «N параллельных запросов»).

## Частые ошибки в ответах

- Использовать обычный `with`/`for` для async-ресурсов/источников (нужны `async
  with`/`async for`).
- Не знать про `asyncio.Semaphore` для ограничения конкурентности (запустить всё
  разом через `gather` и перегрузить).
- Путать `asyncio.Queue` (корутины, один поток) и `queue.Queue` (потоки,
  блокировки).
- Думать, что в однопоточном asyncio синхронизация не нужна вовсе (между `await`
  задачи чередуются).
