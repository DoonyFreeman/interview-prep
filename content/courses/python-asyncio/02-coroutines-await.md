# Корутины и await

> Цель урока: понять, что `async def` создаёт корутину, которая **ничего не делает
> до `await`**, и что именно можно ожидать. Самая частая ошибка новичков в
> asyncio — «забыл await» — растёт из непонимания этой механики. Вопрос «что
> вернёт вызов async-функции без await» — хороший фильтр.

## async def и корутины

Функция, объявленная через **`async def`**, — это **корутинная функция**. Её
вызов **не выполняет тело**, а возвращает объект-**корутину**, который нужно
запустить через `await` или планировщик. Это похоже на генераторы: вызов сам по
себе ничего не считает.

```python
async def fetch(url):
    print("fetching")
    return await get(url)

coro = fetch("...")     # тело НЕ выполнилось! coro — объект-корутина
# print("fetching") ещё не случился

result = await coro     # вот теперь корутина исполняется
```

Отсюда вырастает **главная ошибка** новичков: вызвать корутину и **забыть
`await`** — тело не выполнится, а вы получите предупреждение «coroutine was never
awaited». Корутину обязательно нужно либо `await`-ить, либо обернуть в задачу
(`create_task`).

**Аналогия.** Корутинная функция — это рецепт. Вызвать `fetch(...)` — взять рецепт
в руки (получить корутину), но готовка ещё не началась. `await` — собственно
готовить по рецепту. Взять рецепт и не готовить — еды не будет (тело не
выполнится).

## await и awaitable

**`await`** приостанавливает текущую корутину до готовности результата и **уступает
управление событийному циклу**. Ожидать (`await`) можно только **awaitable**
объекты: корутины, **задачи (Task)** и **future**. Обычные функции и значения
ожидать нельзя.

```python
async def main():
    data = await fetch(url)        # ждём корутину, цикл пока занят другим
    await asyncio.sleep(1)         # sleep — awaitable, уступает цикл
    # await 42                     # ошибка: int не awaitable
```

Принципиально важно: `await` уступает цикл **только если операция действительно
асинхронная** (внутри доходит до настоящего ожидания IO). `await` на чём-то, что
синхронно считает, цикл не освободит. Поэтому асинхронность «заразна»: чтобы
функция могла `await`-ить, она сама должна быть `async`, и так по всей цепочке
вызовов — отсюда правило «async всё или ничего».

**Аналогия.** `await` — это сказать «я подожду здесь ответа, а вы пока займитесь
другими». Но ждать можно только то, что умеет «позвать обратно, когда готово»
(awaitable). Попросить подождать у обычного числа бессмысленно.

## Корутина против обычной функции

Сведём отличия, которые любят на собесе:

| | Обычная функция | Корутина (`async def`) |
|---|---|---|
| Вызов `f()` | выполняет тело, возвращает результат | возвращает корутину, тело **не** выполнено |
| Запуск | сразу | через `await` / `create_task` |
| Может `await` | нет | да |
| Блокирует поток | да (пока считает) | уступает цикл на `await` |

Главная мысль: корутина — это **приостанавливаемая** функция, встроенная в
кооперативную модель. Нельзя вызвать `async`-функцию из обычной синхронной и
«просто получить результат» — нужен либо `await` (в async-контексте), либо
`asyncio.run()` на верхнем уровне. Смешивать sync и async бездумно нельзя:
блокирующий вызов внутри корутины заморозит цикл, а корутина без `await` не
выполнится.

**Аналогия.** Обычная функция — работник, который делает дело и сразу отдаёт
результат, занимая ваше время целиком. Корутина — работник, который в моменты
ожидания отходит, освобождая вас, но и «запустить» его надо особым образом
(`await`), а не просто окликнуть.

## Памятка для собеседования

- `async def` — корутинная функция; её вызов **возвращает корутину и не выполняет
  тело**. Запуск — через `await` или `create_task`.
- Забыть `await` — частая ошибка: тело не выполнится («coroutine was never
  awaited»).
- `await` приостанавливает корутину и **уступает цикл**; ожидать можно только
  **awaitable** (корутина/Task/Future), не обычные значения.
- Асинхронность «заразна»: чтобы `await`-ить, функция сама должна быть `async`
  (правило «async всё или ничего»). Нельзя просто вызвать корутину из sync-кода.

## Частые ошибки в ответах

- Думать, что вызов `async`-функции сразу выполняет её тело.
- Забывать `await` и не понимать, почему «ничего не произошло».
- Пытаться `await` несуществующее (обычное значение/функцию) или вызвать корутину
  из синхронного кода без `asyncio.run`.
- Не понимать «заразности» async и пытаться смешивать с блокирующим кодом.
