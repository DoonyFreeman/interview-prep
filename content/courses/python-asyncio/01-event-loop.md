# Событийный цикл и кооперативная многозадачность

> Цель урока: понять, что asyncio — это **однопоточная** кооперативная
> многозадачность вокруг событийного цикла, и чем она принципиально отличается от
> потоков. Без этой модели ответы про `await`, `gather` и «почему нельзя
> блокировать цикл» звучат заученно. Это фундамент всей асинхронности.

## Что такое событийный цикл

В основе asyncio лежит **событийный цикл (event loop)** — один поток, который
крутится в цикле и **переключается между задачами в точках ожидания**. Когда
задача доходит до операции, требующей ожидания (сеть, таймер), она **добровольно
уступает управление** циклу, а тот запускает другую готовую задачу. Когда
ожидаемое событие наступает (пришёл ответ), цикл возвращается к приостановленной
задаче.

```python
import asyncio

async def main():
    print("start")
    await asyncio.sleep(1)      # уступаем управление циклу на 1 секунду
    print("done")

asyncio.run(main())             # создаёт цикл, выполняет main, закрывает цикл
```

Всё происходит в **одном потоке**: нет переключения потоков ОС, нет GIL-борьбы,
нет гонок данных в привычном смысле (между точками `await` код выполняется
неделимо). `asyncio.run()` — стандартная точка входа: поднимает цикл, гоняет
корутину, корректно закрывает.

**Аналогия.** Событийный цикл — это один официант на много столиков. Он не стоит
без дела у столика, где гости читают меню (ждут IO), а идёт обслуживать другой
столик. Один работник, но за счёт переключений в моменты ожидания успевает многое.

## Кооперативная против вытесняющей многозадачности

Ключевое отличие от потоков — **кто решает, когда переключиться**:

- **Вытесняющая (preemptive)** многозадачность (потоки): **ОС** в любой момент
  может прервать поток и переключить на другой. Программист не контролирует
  моменты переключения → нужны блокировки от гонок.
- **Кооперативная (cooperative)** многозадачность (asyncio): задача переключается
  **только добровольно**, в явных точках `await`. Между `await` код выполняется
  без прерываний.

```python
async def task():
    x = shared + 1       # между await прерывания НЕТ — атомарно для логики
    await something()    # ВОТ здесь может переключиться на другую задачу
    shared = x
```

Плюс кооперативной модели — **предсказуемость** (точки переключения видны как
`await`, меньше гонок) и **дешевизна** (переключение задач намного легче
переключения потоков ОС, можно держать тысячи корутин). Минус — **одна
«жадная» задача, не делающая `await`, блокирует весь цикл** (об этом отдельный
урок).

**Аналогия.** Вытесняющая — начальник, который может в любой момент выдернуть
сотрудника на другое дело (непредсказуемо). Кооперативная — сотрудники сами
говорят «я освобождаюсь, передаю эстафету» в удобных точках. Порядок понятнее, но
если один заболтается и не передаст эстафету — встанут все.

## Где asyncio выигрывает и где нет

asyncio блестит на **IO-bound задачах с высокой конкурентностью**: тысячи
сетевых соединений, веб-серверы, прокси, чаты, скрейперы. Один поток с событийным
циклом обслуживает огромное число одновременных ожиданий с минимальными
накладными расходами — там, где тысячи потоков ОС были бы слишком дороги.

Но asyncio **бесполезен для CPU-bound**: тяжёлое вычисление не делает `await`,
держит единственный поток и **замораживает весь цикл** — остальные задачи стоят.
Для CPU-нагрузки по-прежнему нужны **процессы** (или вынос счёта в executor).

```text
asyncio хорош:  10000 одновременных HTTP-запросов (всё ждёт сеть)
asyncio плох:   перемножение больших матриц (держит поток, цикл стоит)
```

Поэтому asyncio — не «ускоритель кода», а **модель эффективного ожидания**: он не
делает вычисления быстрее, он позволяет **не простаивать**, пока идёт ввод-вывод.

**Аналогия.** Один официант (event loop) гениально обслуживает зал, где гости
много думают над меню (IO). Но если один гость попросит официанта лично почистить
ему мешок картошки (CPU-работа), официант застрянет, и весь зал останется без
обслуживания.

## Памятка для собеседования

- asyncio — **однопоточная** кооперативная многозадачность вокруг **событийного
  цикла**: задачи уступают управление в точках ожидания, цикл запускает другие
  готовые. `asyncio.run(main())` — точка входа.
- **Кооперативная** (переключение только на `await`, предсказуемо, дёшево, тысячи
  корутин) против **вытесняющей** (ОС прерывает потоки в любой момент → гонки).
- Между `await` код не прерывается — меньше гонок, чем в потоках.
- asyncio для **IO-bound с высокой конкурентностью**; для **CPU-bound бесполезен**
  (заморозит цикл) — нужны процессы. Это модель эффективного ожидания, а не
  ускорения вычислений.

## Частые ошибки в ответах

- Думать, что asyncio — многопоточность или что он ускоряет вычисления.
- Не понимать, что всё крутится в одном потоке и переключение только на `await`.
- Применять asyncio к CPU-bound и удивляться, что всё «висит».
- Не отличать кооперативную модель от вытесняющей (кто решает момент
  переключения).
