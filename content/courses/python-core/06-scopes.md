# Области видимости: LEGB, замыкания, late binding

> Цель урока: понять, как Python находит, к какому объекту относится имя, и почему
> это иногда удивляет. Правило LEGB, ключевые слова `global`/`nonlocal`,
> замыкания и коварный «late binding» в циклах — всё это растёт из одной модели
> разрешения имён. На собесе любят давать код с замыканием в цикле и спрашивать,
> что он напечатает.

## Правило LEGB

Когда Python встречает имя, он ищет его по областям видимости в строгом порядке
**LEGB**:

1. **L (Local)** — локальная область текущей функции.
2. **E (Enclosing)** — области охватывающих функций (для вложенных функций).
3. **G (Global)** — область модуля (имена на верхнем уровне файла).
4. **B (Built-in)** — встроенные имена (`len`, `print`, `range`).

Поиск идёт изнутри наружу и **останавливается на первом совпадении**:

```python
x = "global"

def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)      # local — нашли сразу в L
    inner()

outer()
print(x)              # global — снаружи видно только модульное x
```

Важный нюанс: **присваивание имени внутри функции делает его локальным для всей
функции**. Поэтому попытка прочитать переменную до присваивания, если где-то ниже
в той же функции есть присваивание этого имени, даёт `UnboundLocalError`.

**Аналогия.** LEGB — это как искать вещь: сначала в своём кармане (L), потом в
рюкзаке (E), потом в шкафу дома (G), потом в магазине (B). Нашли в кармане — дальше
не идём.

## global и nonlocal

По умолчанию присваивание создаёт **локальное** имя. Чтобы **изменить** имя из
внешней области, нужно явно объявить намерение:

- **`global x`** — «присваивания к `x` относятся к глобальной (модульной)
  области», а не создают локальную переменную.
- **`nonlocal x`** — «присваивания к `x` относятся к ближайшей **охватывающей
  функции**» (не глобальной). Нужен для вложенных функций, меняющих переменную
  родителя.

```python
counter = 0
def bump():
    global counter
    counter += 1        # без global → UnboundLocalError

def make_counter():
    count = 0
    def inc():
        nonlocal count  # меняем переменную внешней функции
        count += 1
        return count
    return inc
```

Замечание о стиле: `global` обычно признак плохого дизайна (скрытое разделяемое
состояние). `nonlocal` уместен в замыканиях и фабриках функций.

**Аналогия.** `global`/`nonlocal` — это разрешение «писать в чужую тетрадь». Без
него вы по умолчанию заводите свой черновик (локальную переменную); с ним —
правите оригинал во внешней области.

## Замыкания

**Замыкание (closure)** — это вложенная функция, которая «запоминает» переменные
из охватывающей области и продолжает иметь к ним доступ **даже после того, как
внешняя функция завершилась**. Замыкание захватывает не значение, а **саму
переменную** (ячейку).

```python
def make_multiplier(factor):
    def multiply(n):
        return n * factor    # factor захвачен из enclosing
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(10))   # 20
print(triple(10))   # 30 — каждый замкнул свой factor
```

Замыкания — основа декораторов, колбэков, фабрик функций. Захваченные переменные
живут, пока жива функция-замыкание (видны в `func.__closure__`).

**Аналогия.** Замыкание — это рюкзак, который функция уносит с собой: внутри лежат
переменные из «дома» (внешней функции). Даже когда дом «снесли» (функция
завершилась), рюкзак с вещами остаётся при функции.

## Late binding в циклах

Самая известная ловушка замыканий. Замыкание захватывает **переменную, а не её
значение на момент создания**. Если создавать замыкания в цикле, все они увидят
**финальное** значение переменной цикла:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])   # [2, 2, 2] — не [0, 1, 2]!
```

Все три лямбды замкнули одну и ту же `i`, а к моменту вызова `i == 2`. Это
называется **late binding** (позднее связывание): значение берётся в момент
**вызова**, а не определения.

Решение — «заморозить» значение через **аргумент по умолчанию** (он вычисляется
при определении) или через фабрику:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2] — каждый замкнул своё значение
```

**Аналогия.** Все лямбды держат не фотографию `i`, а ссылку на табло, которое
меняется. Когда вы наконец смотрите (вызываете), на табло уже последнее число.
`i=i` — это как переписать число с табло на свою бумажку в момент создания.

## Памятка для собеседования

- Разрешение имён по **LEGB**: Local → Enclosing → Global → Built-in, изнутри
  наружу, до первого совпадения.
- Присваивание делает имя **локальным** для всей функции → чтение до него даёт
  `UnboundLocalError`.
- **`global`** — писать в модульную область; **`nonlocal`** — в ближайшую
  охватывающую функцию.
- **Замыкание** запоминает переменные охватывающей области и переживает её; основа
  декораторов/фабрик. Захватывает **переменную (ячейку), не значение**.
- **Late binding**: замыкания в цикле видят финальное значение переменной цикла;
  фикс — аргумент по умолчанию `lambda x=x: ...`.

## Частые ошибки в ответах

- Ответить, что `[lambda: i for i in range(3)]` даст `[0,1,2]` (на деле
  `[2,2,2]`).
- Путать `global` и `nonlocal` (nonlocal — про enclosing-функцию, не про модуль).
- Не объяснить `UnboundLocalError`: «переменная же есть снаружи» — но присваивание
  ниже сделало её локальной.
- Думать, что замыкание копирует значение переменной (оно держит ссылку на
  ячейку).
