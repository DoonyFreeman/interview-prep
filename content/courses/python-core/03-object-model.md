# Объектная модель: всё — объект

> Цель урока: понять, что в Python **буквально всё** — объект, и какие свойства из
> этого следуют: изменяемость, хэшируемость, истинность. Эти три свойства
> объясняют, почему список нельзя положить в `set`, почему `def f(x=[])` —
> ловушка, и что на самом деле проверяет `if my_list:`. Тема всплывает на собесе
> постоянно, часто в виде «почему так себя ведёт код».

## Всё — объект: данные, функции, классы, типы

В Python **всё является объектом**: числа, строки, списки — да, но также
**функции, классы, модули и даже типы**. У каждого объекта есть три вещи:
**идентичность** (адрес, `id()`), **тип** (`type()`) и **значение**.

Раз функции и классы — объекты, их можно присваивать переменным, передавать в
другие функции, возвращать, складывать в списки и словари. Это и называется
**«функции — объекты первого класса»**.

```python
def shout(text):
    return text.upper()

f = shout            # имя f теперь ссылается на ту же функцию
funcs = [shout, str.lower]
print(f("hi"))       # HI
print(type(shout))   # <class 'function'>
print(type(int))     # <class 'type'> — даже у типа есть тип
```

**Аналогия.** В некоторых языках есть «обычные граждане» (данные) и «чиновники»
(функции, классы) с особыми правами. В Python все — равноправные граждане:
функцию можно передать так же легко, как число. Это снимает кучу ограничений и
делает возможными декораторы, колбэки, реестры функций.

## Изменяемость: mutable и immutable

Каждый тип либо **изменяемый (mutable)**, либо **неизменяемый (immutable)**.

- **Immutable**: `int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`.
  Объект нельзя изменить после создания — любая «модификация» создаёт **новый
  объект**.
- **Mutable**: `list`, `dict`, `set`, `bytearray`, большинство своих классов.
  Объект меняется на месте, его `id()` остаётся прежним.

```python
s = "abc"
print(id(s))
s += "d"            # не меняет строку, создаёт новую
print(id(s))        # другой id — это новый объект

lst = [1, 2]
print(id(lst))
lst.append(3)       # меняет тот же список на месте
print(id(lst))      # тот же id
```

Почему это критично: при передаче mutable-объекта в функцию вы передаёте ссылку
на **тот же** объект, и функция может его изменить — это видно снаружи. С
immutable такого не бывает.

**Аналогия.** Immutable — это надпись, выгравированная на камне: «изменить» можно
только взяв новый камень. Mutable — доска для записей маркером: стираешь и пишешь
на той же доске, и все, кто на неё смотрит, видят изменения.

## Хэшируемость: что можно класть в set и ключи dict

**Хэшируемый** объект — тот, у которого есть неизменный за время жизни хэш
(`__hash__`) и который умеет сравниваться (`__eq__`). Только хэшируемые объекты
можно класть в `set` и использовать как **ключи словаря**, потому что эти
структуры — хэш-таблицы.

Правило большого пальца: **неизменяемые объекты обычно хэшируемы, изменяемые —
нет**. Поэтому `list` и `dict` нельзя сделать ключами, а `tuple` (если внутри
тоже всё хэшируемо) и `frozenset` — можно.

```python
{[1, 2]: "x"}        # TypeError: unhashable type: 'list'
{(1, 2): "x"}        # OK — кортеж хэшируем
{(1, [2]): "x"}      # TypeError — внутри кортежа изменяемый список
```

Почему mutable нельзя хэшировать: если бы хэш списка зависел от содержимого, то
после `lst.append(...)` он бы изменился — и объект «потерялся» бы в хэш-таблице
(лежит в старом ведре, ищется в новом). Поэтому изменяемым типам хэш запрещён
намеренно.

**Связь `__hash__` и `__eq__`**: если переопределяете `__eq__` у своего класса,
обязательно следите за `__hash__`. Контракт: **равные объекты обязаны иметь
равный хэш**. По умолчанию объекты хэшируются по `id()`; стоит определить
`__eq__` — Python сбрасывает `__hash__` в `None` (объект становится
нехэшируемым), пока вы не зададите его явно (`@dataclass(frozen=True)` делает это
за вас).

**Аналогия.** Хэш — это номер полки в камере хранения, вычисленный по содержимому
сумки. Если содержимое (а значит и номер полки) может меняться, вы не найдёте
сумку потом. Поэтому на хэш-полку кладут только «запечатанные» (неизменяемые)
вещи.

## Истинность: truthiness и __bool__

В условиях (`if`, `while`, `and`, `or`) Python приводит объект к булеву значению
по правилам **truthiness**, а не только для `True`/`False`. Объект считается
**ложным**, если:

- это `None` или `False`;
- это ноль любого числового типа (`0`, `0.0`, `Decimal(0)`);
- это **пустая** коллекция/последовательность (`""`, `[]`, `{}`, `set()`,
  `()`).

Всё остальное — **истинно**. Под капотом Python вызывает `__bool__()`, а если его
нет — `__len__()` (пусто → ложь). Это позволяет писать идиоматично:

```python
items = []
if items:            # «если список не пуст», а не len(items) > 0
    process(items)

name = ""
if not name:         # «если имя пустое»
    name = "anon"
```

Подводный камень — **различать «пусто» и «None»**. Для чисел `if count:` ложно и
при `count == 0`, и при `count is None`. Если ноль — валидное значение, пишите
явно `if count is not None`.

**Аналогия.** Truthiness — как вопрос «есть ли вообще что-то?». Пустая коробка,
ноль рублей, отсутствие ответа — всё это «ничего» (ложь). Непустое — «что-то»
(истина). Но иногда «ноль рублей» — это важное число, а не «ничего»: тогда
спрашивайте явно `is not None`.

## Памятка для собеседования

- В Python **всё объект**: числа, строки, **функции, классы, типы**. Функции —
  объекты первого класса (передаются, возвращаются, хранятся).
- **Mutable** (list/dict/set) меняются на месте, `id()` сохраняется; **immutable**
  (int/str/tuple/frozenset) — «изменение» создаёт новый объект.
- **Хэшируемы** только объекты со стабильным `__hash__` (как правило immutable);
  только их можно класть в `set`/ключи `dict`. Контракт: равные → равный хэш.
- Переопределил `__eq__` — позаботься о `__hash__` (иначе объект нехэшируем).
- **Truthiness**: ложь = `None`, `False`, ноль, пустая коллекция. Под капотом
  `__bool__` → иначе `__len__`.
- Отличай пустоту от `None`: для чисел используй `is not None`, если `0` валиден.

## Частые ошибки в ответах

- «Хэшируемость = неизменяемость» как абсолют: связь есть, но точное правило —
  стабильный `__hash__` + `__eq__`; кортеж с list внутри нехэшируем.
- Положить `list`/`dict` в `set` или ключ словаря и не объяснить, почему
  `TypeError`.
- Переопределить `__eq__` и забыть про `__hash__` (объект «ломается» как ключ).
- `if value:` там, где `0`/`""` — валидные данные (теряется кейс нуля/пустой
  строки).
- Думать, что функции/классы — «не объекты»; на этом стоят декораторы и
  метапрограммирование.
