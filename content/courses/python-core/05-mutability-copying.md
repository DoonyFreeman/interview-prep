# Изменяемость и копирование

> Цель урока: разобрать практические ловушки, которые растут из модели «имена и
> объекты»: разница между поверхностным и глубоким копированием, знаменитая
> ловушка изменяемого аргумента по умолчанию и опасность мутации коллекции во
> время итерации. Эти три вопроса — классика собеседований, потому что почти
> каждый разработчик на них хоть раз обжёгся.

## Присваивание не копирует

Повторим фундамент: `b = a` **не копирует** объект, а добавляет второе имя на тот
же объект. Для изменяемых типов это значит, что изменение через одно имя видно
через другое:

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)        # [1, 2, 3, 4] — это один список
```

Чтобы получить **настоящую копию**, нужно явно её сделать: `list(a)`, `a[:]`,
`a.copy()` или модуль `copy`. И тут начинается различие поверхностного и
глубокого копирования.

**Аналогия.** `b = a` — это как дать второй ключ от одной квартиры. Оба ключа
открывают одно жильё; «ремонт» одним ключом видит и второй. Копия — это отдельная
квартира.

## Поверхностное против глубокого копирования

- **Поверхностная (shallow) копия** создаёт **новый внешний контейнер**, но
  **вложенные объекты остаются общими** (копируются ссылки на них). Делается
  через `copy.copy(x)`, `x.copy()`, `list(x)`, `x[:]`.
- **Глубокая (deep) копия** рекурсивно копирует **всё дерево** объектов: и
  контейнер, и всё, что внутри. Делается через `copy.deepcopy(x)`.

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
shallow[0].append(99)
print(original)   # [[1, 2, 99], [3, 4]] — внутренний список общий!

deep = copy.deepcopy(original)
deep[0].append(0)
print(original)   # без изменений — внутренние списки скопированы
```

Когда что: shallow дешевле и достаточно, если внутри только неизменяемые объекты
(числа, строки) или вы намеренно хотите делить вложенные структуры. Deep нужен,
когда есть вложенные изменяемые объекты и важна полная независимость. Цена deep —
скорость и память; `deepcopy` ещё и корректно обрабатывает циклы (запоминает уже
скопированные объекты).

**Аналогия.** Shallow copy — сделать копию оглавления книги: новый лист, но
страницы те же (ссылаются на тот же текст). Deep copy — переписать всю книгу
целиком, включая каждую страницу.

## Ловушка изменяемого аргумента по умолчанию

Один из самых частых вопросов-«подстав». Значение по умолчанию вычисляется
**один раз — в момент определения функции**, а не при каждом вызове. Если
по умолчанию стоит изменяемый объект, он **разделяется между всеми вызовами**:

```python
def add_item(item, basket=[]):     # ловушка!
    basket.append(item)
    return basket

print(add_item("a"))   # ['a']
print(add_item("b"))   # ['a', 'b'] — тот же список, накопил!
```

Список `basket` создан единожды и живёт между вызовами. Правильный паттерн —
**`None` как маркер** и создание объекта внутри:

```python
def add_item(item, basket=None):
    if basket is None:
        basket = []
    basket.append(item)
    return basket
```

То же касается `{}`, `set()`, и вообще любого мутабельного значения по умолчанию,
включая результат вызова функции (`def f(t=datetime.now())` «замораживает» время
определения).

**Аналогия.** Значение по умолчанию — это общая корзина у входа в магазин,
прикреплённая к двери при открытии. Все, кто не взял свою, кладут в одну и ту же —
и она копит чужое. Решение: на входе проверять «нет корзины? возьми новую».

## Мутация во время итерации

Изменять коллекцию (особенно удалять из неё), пока вы по ней итерируетесь, —
**неопределённое поведение**: можно пропустить элементы или получить
`RuntimeError`.

```python
nums = [1, 2, 3, 4]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)    # пропустит элементы: сдвигаются индексы
print(nums)               # [1, 3] — но логика хрупкая, легко ошибиться

# для dict/set прямое изменразмера во время итерации → RuntimeError:
d = {"a": 1, "b": 2}
for k in d:
    del d[k]              # RuntimeError: dictionary changed size during iteration
```

Правильные приёмы: итерироваться по **копии** (`for n in nums[:]`), строить
**новый** объект через comprehension (`nums = [n for n in nums if n % 2]`), либо
собрать ключи на удаление и удалить **после** цикла.

**Аналогия.** Это как вычёркивать людей из списка очереди, одновременно считая их
по этому же списку пальцем: вычеркнули — следующий сдвинулся под палец, и вы его
проскочили. Сначала отметьте, кого убрать, потом убирайте.

## Памятка для собеседования

- `b = a` не копирует — два имени на один объект. Копия: `list(a)`, `a[:]`,
  `a.copy()`, `copy.copy/deepcopy`.
- **Shallow**: новый контейнер, вложенные объекты общие. **Deep**: рекурсивная
  копия всего дерева (дороже, обрабатывает циклы).
- Значение по умолчанию вычисляется **один раз при определении** функции →
  изменяемый дефолт копит состояние между вызовами. Решение: `=None` + создать
  внутри.
- Не менять размер коллекции во время итерации: dict/set → `RuntimeError`, list →
  пропуск элементов. Итерируйся по копии или строй новый объект.

## Частые ошибки в ответах

- «`copy()` делает полную копию» без различения shallow/deep — вложенные
  изменяемые объекты остаются общими при shallow.
- Не знать, что дефолтное значение создаётся один раз (думают «при каждом
  вызове»).
- Чинить ловушку дефолта через `basket = basket or []` — ломается, если передан
  валидный пустой/ложный аргумент; правильно `is None`.
- Удалять из списка/словаря прямо в цикле по нему и считать это надёжным.
