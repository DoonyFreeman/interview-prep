# Итераторы и генераторы

> Цель урока: понять протокол итерации (что на самом деле делает `for`),
> разницу между **итерируемым** и **итератором**, и как генераторы дают ленивые,
> экономные по памяти последовательности. Это одна из самых «питонических» тем:
> грамотный ответ про `yield` и ленивость сразу выделяет кандидата.

## Протокол итерации: iterable против iterator

Два понятия, которые путают:

- **Iterable (итерируемое)** — объект, по которому можно пройти; он умеет отдать
  итератор через `__iter__()`. Примеры: `list`, `str`, `dict`, `range`.
- **Iterator (итератор)** — объект, который помнит позицию и отдаёт следующий
  элемент через `__next__()`; когда элементы кончаются, бросает
  `StopIteration`. Итератор тоже итерируемый (его `__iter__` возвращает себя).

Цикл `for x in obj` под капотом делает именно это:

```python
it = iter(obj)            # obj.__iter__() — получаем итератор
while True:
    try:
        x = next(it)      # it.__next__() — следующий элемент
    except StopIteration:
        break
    ...                   # тело цикла
```

Важное следствие: **итератор одноразовый**. Пройдя его до конца, вы не начнёте
заново — нужно получить новый через `iter(...)`. Поэтому список можно перебирать
много раз (каждый `for` берёт свежий итератор), а итератор-генератор —
исчерпывается.

```python
nums = [1, 2, 3]
it = iter(nums)
list(it)     # [1, 2, 3]
list(it)     # []  — итератор исчерпан
list(nums)   # [1, 2, 3] — список даёт новый итератор каждый раз
```

**Аналогия.** Iterable — это плейлист (можно слушать сколько угодно раз).
Iterator — указатель «сейчас играет эта песня», который двигается вперёд и не
перематывается назад; кончился плейлист — нужен новый указатель.

## Генераторы и yield

**Генератор** — самый простой способ создать итератор: обычная функция, в которой
есть `yield`. Вызов такой функции **не выполняет тело**, а возвращает
объект-генератор. Тело выполняется по кусочкам: на каждом `yield` функция
**замораживается**, отдаёт значение и ждёт следующего `next()`, сохраняя всё
локальное состояние.

```python
def countdown(n):
    while n > 0:
        yield n          # отдать значение и «заморозиться» здесь
        n -= 1

g = countdown(3)
print(next(g))   # 3
print(next(g))   # 2
for x in g:      # продолжит с того места: 1
    print(x)
```

Ключевое отличие от обычной функции: обычная считает всё и возвращает результат
разом (`return`), генератор отдаёт значения **по одному, лениво**, сохраняя
состояние между вызовами. Это даёт огромную экономию памяти.

**Аналогия.** Обычная функция — повар, который готовит сразу весь банкет и ставит
на стол (всё в памяти). Генератор — повар, который готовит и подаёт блюда **по
одному, когда попросят**, и между подачами стоит «на паузе». Не нужно место под
весь банкет сразу.

## Ленивость и экономия памяти

Главная практическая ценность генераторов — **обработка больших или бесконечных
последовательностей без загрузки всего в память**. Сравните:

```python
# список: все 10 млн чисел в памяти разом
sum([x * x for x in range(10_000_000)])

# генераторное выражение: по одному числу за раз, память ~константа
sum(x * x for x in range(10_000_000))
```

Генераторное выражение `(x*x for x in ...)` выглядит как list comprehension, но в
круглых скобках и **ленивое**. Это же позволяет строить **конвейеры**: читать
файл построчно, фильтровать, преобразовывать — поток данных течёт по одной записи,
не материализуясь целиком.

```python
def read_large(path):
    with open(path) as f:
        for line in f:           # файл читается лениво, построчно
            yield line.strip()

lines = read_large("huge.log")
errors = (l for l in lines if "ERROR" in l)   # ещё ленивый шаг
first_ten = list(itertools.islice(errors, 10))
```

Бонус — можно описывать **бесконечные** последовательности (`while True: yield`),
беря из них ровно столько, сколько нужно.

**Аналогия.** Список — скачать весь сериал целиком перед просмотром (нужен диск
под всё). Генератор — стриминг: подгружается следующая сцена по мере просмотра,
память почти не занята, а «бесконечный эфир» вообще не скачать иначе.

## yield from и делегирование

`yield from iterable` делегирует итерацию другому генератору/итерируемому: отдаёт
все его значения, как будто они вшиты в текущий генератор. Это убирает ручной
цикл и корректно прокидывает значения (а в корутинах — и `send`/исключения).

```python
def chain(*iterables):
    for it in iterables:
        yield from it          # вместо: for x in it: yield x

list(chain([1, 2], [3, 4]))    # [1, 2, 3, 4]
```

Полезно для рекурсивных структур (обход дерева) и композиции генераторов.

**Аналогия.** `yield from` — это как конферансье, передающий микрофон гостю: пока
гость говорит, зал слышит его напрямую, а ведущий просто «прозрачно» транслирует,
не пересказывая каждое слово.

## Памятка для собеседования

- **Iterable** умеет отдать итератор (`__iter__`); **iterator** хранит позицию и
  отдаёт `__next__`, в конце — `StopIteration`. `for` = `iter()` + `next()` в
  цикле.
- Итератор **одноразовый**; iterable (список) даёт свежий итератор на каждый
  `for`.
- **Генератор** — функция с `yield`: вызов не выполняет тело, возвращает
  генератор; на `yield` замораживается, хранит состояние. Ленивая выдача по
  одному.
- Генераторы экономят память и позволяют **конвейеры** и **бесконечные**
  последовательности; `(x for x in ...)` — ленивое генераторное выражение.
- `yield from` делегирует итерацию вложенному генератору/итерируемому.

## Частые ошибки в ответах

- Путать iterable и iterator (например, считать, что список — это итератор; он
  iterable).
- Не знать, что генератор/итератор **исчерпывается** и не перематывается.
- Думать, что вызов генераторной функции сразу выполняет её тело (нет — до первого
  `next`).
- Использовать list comprehension там, где нужна ленивость, и держать в памяти
  миллионы элементов вместо генераторного выражения.
- Не уметь объяснить, чем `yield` отличается от `return` (пауза с сохранением
  состояния против завершения функции).
