# pytest: фикстуры, parametrize, маркеры

> Цель урока: освоить рабочие инструменты pytest — фикстуры (и их scope),
> параметризацию, маркеры и `conftest.py`. pytest — стандарт тестирования в Python,
> и на собесе спрашивают «как организованы ваши тесты» и «что такое фикстура».

## Основы pytest

pytest делает тесты минималистичными: тест — это **обычная функция** с именем
`test_*`, а проверки — через **простой `assert`** (pytest сам показывает понятный
diff при падении), без громоздких `assertEqual` из unittest.

```python
def test_addition():
    assert add(2, 3) == 5

def test_raises():
    with pytest.raises(ValueError):     # проверка, что бросается исключение
        parse("bad")
```

Запуск: `pytest` (находит тесты по соглашению), `pytest tests/test_x.py::test_y`
(один тест), `-k` (по имени), `-v` (подробно), `-x` (остановиться на первом
падении). Простота `assert` — фирменная черта pytest.

**Аналогия.** pytest — как лёгкий чек-лист: пишешь утверждение «должно быть так»
(`assert`), и если не так — инструмент сам подробно покажет, что именно разошлось.

## Фикстуры и scope

**Фикстура** — функция, **подготавливающая данные/ресурсы** для теста (БД, клиент,
тестовые объекты). Тест получает её, просто **объявив параметром** с тем же именем;
pytest сам её вызовет и подставит результат (это его форма dependency injection).

```python
import pytest

@pytest.fixture
def db_session():
    session = create_test_session()
    yield session          # отдаём в тест; код после yield — очистка
    session.close()

def test_user(db_session):     # фикстура подставится по имени параметра
    db_session.add(User(name="x"))
    assert db_session.query(User).count() == 1
```

Фикстура с **`yield`** даёт **setup/teardown**: до `yield` — подготовка, после —
очистка (как контекст-менеджер). **Scope** управляет, **как часто** фикстура
создаётся: `function` (по умолчанию — на каждый тест), `class`, `module`,
`session` (один раз на весь прогон). Дорогие ресурсы (поднять контейнер БД) делают
с широким scope ради скорости, изменяемое состояние — с `function` ради изоляции.

**Аналогия.** Фикстура — это подготовка рабочего места перед задачей: разложить
инструменты (setup), а после — убрать (teardown). Scope — как часто переставлять:
для каждого мелкого дела заново (function) или один раз на всю смену (session).

## parametrize

**`@pytest.mark.parametrize`** запускает **один тест на множестве входных данных** —
вместо копирования теста или цикла внутри. Каждый набор — **отдельный** тест-кейс
(своё имя, своё падение):

```python
@pytest.mark.parametrize("value, expected", [
    (0, False),
    (1, True),
    (-5, True),
    ("", False),
])
def test_truthiness(value, expected):
    assert bool(value) == expected
```

Преимущество перед циклом внутри теста: при падении видно **какой именно** кейс
упал (а не «тест упал»), и кейсы не прерывают друг друга. Это лучший способ
покрыть **граничные случаи** (0, пустота, отрицательные, None) компактно. Можно
параметризовать и фикстуры.

**Аналогия.** parametrize — как один и тот же экзаменационный билет, прогоняемый на
списке студентов: каждый получает индивидуальную оценку, и видно, кто конкретно не
сдал, а не «группа не сдала».

## conftest и маркеры

Два инструмента организации:

- **`conftest.py`** — файл с **общими фикстурами** (и хуками), которые pytest
  **автоматически** подхватывает для всех тестов в каталоге и подкаталогах, без
  импорта. Туда выносят `client`, `db_session`, настройку приложения (как в этом
  проекте — in-memory SQLite и override зависимостей).
- **Маркеры** (`@pytest.mark.slow`, `@pytest.mark.skip`,
  `@pytest.mark.xfail`) — метки для тестов: пропустить (`skip`/`skipif`), ожидать
  падения (`xfail`), сгруппировать (`-m slow` — запустить только помеченные).

```python
@pytest.mark.slow
def test_heavy(): ...

@pytest.mark.skipif(sys.platform == "win32", reason="posix only")
def test_unix(): ...
# запустить без медленных:  pytest -m "not slow"
```

`conftest.py` — ключ к **переиспользованию** фикстур и отсутствию дублирования
настройки в каждом файле. Маркеры дают **управление выбором** тестов (быстрые в
dev, всё — в CI).

**Аналогия.** `conftest.py` — общий склад инструментов для всей мастерской (берёт
любой стол, не таская своё). Маркеры — ярлыки на задачах: «долгая», «пропустить»,
«ожидаемо сломана» — чтобы фильтровать, что делать сейчас.

## Памятка для собеседования

- Тест — функция `test_*` + простой **`assert`** (pytest показывает diff);
  `pytest.raises` для исключений. Запуск: `-k`, `-x`, `-v`, `::test`.
- **Фикстура** — подготовка ресурса, подставляется **по имени параметра** (DI);
  `yield` даёт **setup/teardown**; **scope** (function/module/session) — частота
  создания (дорогое — шире, изменяемое — function).
- **`parametrize`** — один тест на наборе данных, каждый кейс отдельный (видно,
  какой упал); лучший способ покрыть границы.
- **`conftest.py`** — общие фикстуры авто-подхватом; **маркеры**
  (`skip`/`skipif`/`xfail`/свои) для пропуска/группировки (`-m`).

## Частые ошибки в ответах

- Не знать, что фикстуры подставляются по имени параметра, и зачем нужен scope.
- Писать цикл внутри теста вместо `parametrize` (теряется, какой кейс упал).
- Дублировать настройку в каждом файле вместо `conftest.py`.
- Не использовать `pytest.raises` для проверки исключений.
