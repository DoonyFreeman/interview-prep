# Типы данных и индексы PostgreSQL

> Цель урока: познакомиться с богатыми типами PostgreSQL (особенно JSONB) и
> специализированными индексами (B-tree, GIN, GiST, BRIN, частичные). Это то, чем
> PostgreSQL выделяется среди СУБД, и частый вопрос «когда JSONB, когда GIN-индекс».

## Богатые типы данных

PostgreSQL предлагает гораздо больше типов, чем «числа и строки»:

- **Числовые**: `integer`, `bigint`, `numeric` (точная десятичная — для денег),
  `real`/`double`.
- **Текст**: `text` (без ограничения длины, рекомендуется), `varchar(n)`.
- **`JSONB`** — бинарный JSON с **индексацией и операторами** (главная фича, ниже).
- **Массивы** — `integer[]`, `text[]`: хранить список прямо в колонке.
- **`UUID`** — для распределённых id.
- **`enum`** — перечисление фиксированных значений.
- **Диапазоны** (`int4range`, `tsrange`), **`inet`** (IP), `timestamptz` (время с
  таймзоной — рекомендуется вместо `timestamp`).

Богатство типов позволяет моделировать данные точнее и переносить логику в БД. Но
не злоупотреблять: массивы и JSONB удобны, но усложняют запросы и нормализацию.

**Аналогия.** Типы PostgreSQL — как набор специализированных контейнеров: для денег
точная мерная посуда (`numeric`), для гибких данных — универсальный ящик (`JSONB`),
для IP-адресов — специальный держатель (`inet`). Правильный контейнер бережёт данные
и упрощает работу.

## JSONB

**`JSONB`** хранит JSON в **бинарном, разобранном** виде (в отличие от `json` —
текстового). Это даёт **эффективные запросы по содержимому, операторы и
индексацию**. JSONB — способ хранить **полуструктурированные** данные (гибкие,
переменные поля) в реляционной БД, не плодя таблицы.

```sql
CREATE TABLE events (id bigserial, data jsonb);
SELECT * FROM events WHERE data->>'type' = 'click';      -- доступ к полю
SELECT * FROM events WHERE data @> '{"user": {"vip": true}}';  -- содержит
CREATE INDEX idx_data ON events USING gin (data);        -- GIN-индекс по JSONB
```

Операторы: `->` (получить поле как JSON), `->>` (как текст), `@>` (содержит),
`?` (есть ключ). Когда использовать: атрибуты, которые **меняются/необязательны**,
настройки, метаданные, данные внешних API. Когда **не** стоит: основные, часто
запрашиваемые и связанные поля — их лучше держать обычными колонками
(нормализованно), JSONB не заменяет нормальную схему.

**Аналогия.** JSONB — как карман «прочее» в органайзере: удобно для разнородной
мелочи, которую заранее не разложить по ячейкам. Но складывать туда всё подряд
(включая то, для чего есть отдельные ячейки-колонки) — потерять порядок и скорость.

## Типы индексов в PostgreSQL

Помимо стандартного **B-tree** (равенство, диапазоны, сортировка — основной),
PostgreSQL даёт специализированные индексы:

- **GIN (Generalized Inverted Index)** — для **составных значений**: JSONB,
  массивы, **полнотекстовый поиск**. «Обратный индекс»: по элементу → строки,
  которые его содержат.
- **GiST** — для **геоданных** (PostGIS), диапазонов, поиска ближайших, нечётких
  совпадений.
- **BRIN (Block Range Index)** — крошечный индекс для **очень больших** таблиц с
  естественным порядком (например, по времени): хранит диапазоны значений по
  блокам, экономит память.
- **Частичные** (`WHERE` в индексе) — индексировать **только подмножество** строк
  (`WHERE active = true`) — меньше и быстрее.
- **По выражению** — индекс по `lower(email)` для регистронезависимого поиска.

```sql
CREATE INDEX ON events USING gin (data);                       -- JSONB/массивы/FTS
CREATE INDEX ON orders (created_at) WHERE status = 'pending';   -- частичный
CREATE INDEX ON users (lower(email));                           -- по выражению
```

Выбор типа индекса под характер данных и запросов — то, чем оптимизация в
PostgreSQL глубже, чем «просто добавить индекс». GIN для JSONB/полнотекста —
самый частый «продвинутый» случай.

**Аналогия.** Типы индексов — как разные каталоги в библиотеке: алфавитный (B-tree)
для поиска по названию, тематический указатель внутри книг (GIN) для «где упоминается
слово», карта залов (GiST) для «что рядом». Под разные вопросы — разные каталоги.

## Памятка для собеседования

- Богатые типы: `numeric` (деньги), `text`, **`JSONB`**, массивы, `UUID`, `enum`,
  диапазоны, `timestamptz` (с таймзоной). Точнее моделируют данные, но не
  злоупотреблять.
- **JSONB** — бинарный JSON с операторами (`->`, `->>`, `@>`) и индексацией; для
  **полуструктурированных/гибких** данных, **не** замена нормальной схеме для
  основных полей.
- Индексы: **B-tree** (основной), **GIN** (JSONB/массивы/полнотекст), **GiST**
  (гео/диапазоны), **BRIN** (огромные таблицы по порядку), **частичные** (`WHERE`),
  **по выражению** (`lower(email)`).

## Частые ошибки в ответах

- Складывать в JSONB то, что должно быть обычными колонками (теряя нормализацию и
  скорость).
- Не знать про GIN-индекс для JSONB/массивов/полнотекста.
- Использовать `timestamp` вместо `timestamptz` (проблемы с таймзонами).
- Считать, что в PostgreSQL только B-tree индексы.
