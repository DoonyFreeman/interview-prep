# Аутентификация, lifespan и тестирование

> Цель урока: разобрать, как FastAPI работает с OAuth2/JWT, зачем нужен lifespan
> (startup/shutdown) и как тестировать приложение без поднятия сервера. Это
> завершает картину «как устроено реальное FastAPI-приложение» — ровно как в этом
> проекте.

## OAuth2 password flow и JWT

FastAPI даёт встроенную поддержку **схем безопасности**. Типичный для API подход —
**OAuth2 password flow + JWT** (как в этом проекте):

1. Клиент шлёт логин/пароль на `/token`; сервер проверяет и выдаёт **JWT**.
2. Клиент в каждом запросе шлёт `Authorization: Bearer <token>`.
3. Зависимость достаёт токен, проверяет подпись и срок, находит пользователя.

```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

def get_current_user(token: str = Depends(oauth2_scheme),
                     db: Session = Depends(get_db)) -> User:
    payload = jwt.decode(token, SECRET, algorithms=["HS256"])  # подпись + exp
    user = db.get(User, payload["sub"])
    if not user:
        raise HTTPException(401)
    return user

@app.get("/me")
def me(user: User = Depends(get_current_user)):
    return user
```

**JWT** — самоподписанный токен (`header.payload.signature`): сервер не хранит
сессию, а **проверяет подпись** секретом (детали — в курсе Web/HTTP). Security-схемы
FastAPI ещё и **попадают в OpenAPI** (кнопка Authorize в `/docs`). **Скоупы**
(scopes) позволяют выражать права (`read`/`write`) и проверять их в зависимостях.
Это ровно паттерн «auth через DI», который вы видели в уроке про Depends.

**Аналогия.** JWT — это подписанный пропуск с печатью: охрана (зависимость) на
каждом входе проверяет печать (подпись) и срок действия, не сверяясь с центральной
картотекой (нет хранения сессий на сервере).

## Lifespan: startup и shutdown

Приложению нужно выполнить код **при старте** (создать пул соединений, прогреть
кэш, засидировать контент) и **при остановке** (закрыть ресурсы). Для этого —
**lifespan** (современная замена устаревшим `@app.on_event`):

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    await init_db()            # startup: до приёма запросов
    seed_content()
    yield                      # здесь приложение принимает запросы
    await engine.dispose()     # shutdown: после остановки

app = FastAPI(lifespan=lifespan)
```

Код до `yield` выполняется **один раз при запуске** (до первого запроса), после
`yield` — **при завершении**. Это идеальное место для инициализации, которая должна
случиться единожды на процесс: подключения к БД/Redis, загрузка моделей, сидинг (в
этом проекте — `init_db` + `seed_content`). Это тот же паттерн контекст-менеджера,
но на уровне жизни приложения.

**Аналогия.** Lifespan — это «открытие и закрытие магазина»: до `yield` —
разложить товар и включить свет (startup), `yield` — рабочий день (приём
запросов), после — выключить свет и закрыть кассу (shutdown). Делается один раз за
смену, а не на каждого покупателя.

## Тестирование без сервера

FastAPI отлично тестируется **без реального сетевого сервера** — через
**`TestClient`** (синхронно, на основе httpx) или **`ASGITransport` + httpx
`AsyncClient`** (для async-тестов). Запросы идут прямо в приложение в памяти —
быстро и без портов:

```python
from fastapi.testclient import TestClient

client = TestClient(app)

def test_read_user():
    r = client.get("/users/1")
    assert r.status_code == 200
    assert r.json()["id"] == 1
```

Главный приём — **переопределение зависимостей** через
`app.dependency_overrides[get_db] = get_test_db`: в тестах подменяют сессию БД на
тестовую (in-memory SQLite), внешние сервисы — на заглушки. Это прямое следствие
DI: раз зависимости объявлены через `Depends`, их **тривиально подменить**, не меняя
код эндпоинтов.

Нюанс async-тестов (как в этом проекте): под `ASGITransport` **lifespan по
умолчанию не запускается**, поэтому инициализацию (сидинг, создание таблиц) делают
в фикстуре теста, а `get_session` переопределяют на тестовый движок.

**Аналогия.** Тестирование через TestClient — как проверять конвейер на стенде, не
запуская весь завод: подаёте детали (запросы) прямо на вход и смотрите выход.
Подмена зависимостей — поставить вместо настоящего станка (БД) макет, чтобы
проверять логику изолированно.

## Памятка для собеседования

- Аутентификация: **OAuth2 password flow + JWT** через **DI** (`get_current_user`
  как зависимость, проверка подписи/срока). Security-схемы попадают в OpenAPI;
  **скоупы** — для прав.
- **Lifespan** (`@asynccontextmanager`, `lifespan=`) — код **до `yield`** при
  старте (пул, кэш, сидинг), **после** — при остановке; один раз на процесс.
  Замена `on_event`.
- Тесты: **`TestClient`** / `ASGITransport`+`AsyncClient` — запросы в приложение
  **в памяти**, без сервера; **`dependency_overrides`** подменяет сессию/сервисы
  (благодаря DI).
- В async-тестах под ASGITransport **lifespan не запускается** — инициализация в
  фикстуре.

## Частые ошибки в ответах

- Не понимать, что JWT не хранится на сервере (проверка подписи, stateless).
- Использовать устаревшие `@app.on_event` вместо lifespan.
- Не знать про `dependency_overrides` и тестировать против реальной БД/сервисов.
- Забывать, что под ASGITransport lifespan не выполняется (нужна инициализация в
  фикстуре).
