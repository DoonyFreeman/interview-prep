# Async-эндпоинты, middleware и обработка ошибок

> Цель урока: понять разницу `def` и `async def` эндпоинтов (и связанную с ней
> ловушку блокировки), роль `BackgroundTasks`, middleware, CORS и обработчиков
> исключений. Вопрос «когда писать async def, а когда обычный def» в FastAPI —
> частый и коварный.

## sync против async эндпоинтов

FastAPI принимает эндпоинты **обоих видов**, и важно понимать разницу:

- **`async def`** — эндпоинт выполняется **в событийном цикле**. Внутри **обязательно
  использовать `await`** и async-библиотеки (async-драйвер БД, `httpx`). Если в
  `async def` вызвать **блокирующий** код (синхронный запрос, `time.sleep`,
  тяжёлый CPU) — он **заблокирует весь цикл** и все другие запросы (см. курс
  Asyncio).
- **`def`** (обычный) — FastAPI выполняет его в **отдельном потоке из пула**
  (threadpool), чтобы блокирующий код **не остановил цикл**. Поэтому синхронный код
  (sync-драйвер БД, обычные библиотеки) безопаснее класть в обычный `def`.

```python
@app.get("/async")
async def a():
    return await async_db_call()       # правильно: await async-операция

@app.get("/sync")
def s():
    return blocking_db_call()          # FastAPI запустит в threadpool — ок
```

Правило: **есть `await`/async-библиотеки → `async def`; синхронный/блокирующий код
→ обычный `def`** (FastAPI вынесет его в поток). Худший вариант — блокирующий вызов
внутри `async def`: это и есть причина «async-сервер тормозит».

**Аналогия.** `async def` — работать в общем зале (цикле), где нельзя застывать;
`def` — FastAPI отводит вам отдельную комнату (поток), где можно спокойно делать
медленную синхронную работу, не мешая залу. Ошибка — застыть прямо в общем зале.

## BackgroundTasks

Если после ответа нужно сделать что-то **не блокируя клиента** (отправить письмо,
записать лог, инвалидировать кэш), используют **`BackgroundTasks`** — задача
выполнится **после отправки ответа**:

```python
@app.post("/signup")
def signup(user: UserCreate, tasks: BackgroundTasks):
    saved = save(user)
    tasks.add_task(send_welcome_email, user.email)   # выполнится после ответа
    return saved        # клиент получает ответ сразу, письмо шлётся фоном
```

`BackgroundTasks` хорош для **лёгких** послезапросных действий в том же процессе.
Но это **не замена очереди задач**: для тяжёлой, надёжной, повторяемой работы
(ретраи, долгие задачи, отдельные воркеры) нужен **Celery/RQ** (см. курс Celery) —
фоновые задачи FastAPI живут в том же процессе и не переживут его перезапуск.

**Аналогия.** `BackgroundTasks` — попросить курьера «по пути занеси письмо»:
мелочь, которую сделают после основной доставки. Тяжёлый груз так не отправляют —
для этого есть отдельная логистическая служба (Celery).

## Middleware и CORS

**Middleware** — слой, **оборачивающий каждый запрос/ответ**: код выполняется до
передачи запроса в эндпоинт и после получения ответа. Применяется для сквозной
логики: логирование, замер времени, добавление заголовков, аутентификация,
сжатие.

```python
@app.middleware("http")
async def add_timing(request, call_next):
    start = time.perf_counter()
    response = await call_next(request)        # передаём дальше по цепочке
    response.headers["X-Time"] = str(time.perf_counter() - start)
    return response
```

**CORS (Cross-Origin Resource Sharing)** — частный, но важнейший случай:
браузер блокирует запросы фронтенда с другого origin (домена/порта), если сервер
не разрешил их CORS-заголовками. Настраивается `CORSMiddleware` со списком
разрешённых origins, методов, заголовков:

```python
app.add_middleware(CORSMiddleware, allow_origins=["http://localhost:5173"], ...)
```

Без правильного CORS фронтенд на другом порту получит ошибку в браузере — типичная
боль при разработке SPA + API (как в этом проекте). Middleware выполняются как
«луковица»: вход сверху вниз, выход снизу вверх.

**Аналогия.** Middleware — это охрана и ресепшен на входе/выходе здания: каждый
входящий и выходящий проходит через них (логирование, проверка). CORS — пропускной
режим «с каких улиц (origins) мы вообще пускаем посетителей».

## Обработка исключений

FastAPI даёт управляемую обработку ошибок:

- **`HTTPException`** — бросаете в коде, FastAPI превращает в HTTP-ответ с нужным
  статусом и телом (`raise HTTPException(404, "not found")`).
- **Обработчики исключений** (`@app.exception_handler(MyError)`) — глобально
  превращают **свои** доменные исключения в аккуратные HTTP-ответы, не загромождая
  эндпоинты `try/except`.

```python
@app.exception_handler(PaymentError)
async def payment_handler(request, exc):
    return JSONResponse(status_code=402, content={"detail": str(exc)})

@app.get("/pay")
def pay():
    raise PaymentError("insufficient")    # перехватится обработчиком → 402
```

Ошибки валидации Pydantic FastAPI и так превращает в 422 автоматически. Паттерн:
бизнес-логика бросает доменные исключения, а **единый обработчик** маппит их в
HTTP-коды — чисто и единообразно.

**Аналогия.** Обработчик исключений — единая «служба рекламаций»: вместо того
чтобы каждый сотрудник сам решал, как ответить на проблему, все жалобы
определённого типа идут в одно окно, которое выдаёт стандартный корректный ответ
(нужный статус).

## Памятка для собеседования

- **`async def`** — в цикле, только `await`/async-библиотеки (блокирующий код
  заморозит всё); обычный **`def`** — FastAPI выполнит в **threadpool**, безопасен
  для синхронного кода. Правило: await → async, блокирующее → def.
- **`BackgroundTasks`** — лёгкая работа **после ответа** в том же процессе; для
  тяжёлого/надёжного — **Celery** (BackgroundTasks не переживут перезапуск).
- **Middleware** оборачивает каждый запрос/ответ (логи, тайминг, заголовки);
  **CORS** (`CORSMiddleware`) разрешает запросы фронтенда с другого origin.
- Ошибки: **`HTTPException`** в коде; **`@app.exception_handler`** маппит доменные
  исключения в HTTP-ответы; Pydantic-ошибки → 422 авто.

## Частые ошибки в ответах

- Класть блокирующий код в `async def` (заморозка цикла) или, наоборот, не знать,
  что обычный `def` идёт в threadpool.
- Считать `BackgroundTasks` заменой Celery для тяжёлых/надёжных задач.
- Не уметь объяснить CORS и почему фронтенд на другом порту получает ошибку.
- Загромождать эндпоинты `try/except` вместо глобальных обработчиков исключений.
