# ASGI, Starlette и роутинг

> Цель урока: понять, на чём стоит FastAPI — стандарт ASGI (и чем он отличается от
> WSGI), роль Starlette и uvicorn, и как устроен роутинг с параметрами. Без
> понимания ASGI ответ «почему FastAPI асинхронный» звучит поверхностно.

## WSGI против ASGI

**WSGI (Web Server Gateway Interface)** — старый стандарт связи Python-веб-сервера
и приложения (Flask, Django до 3.0). Он **синхронный**: один запрос — один поток,
обрабатывается от начала до конца блокирующе. Для тысяч одновременных «ждущих»
соединений это дорого (поток на каждое).

**ASGI (Asynchronous Server Gateway Interface)** — современный **асинхронный**
стандарт. Он поддерживает `async`/`await`, а значит — **конкурентную обработку
многих соединений в одном потоке** через событийный цикл (см. курс Asyncio), а
также **WebSockets и долгоживущие соединения**, которые WSGI в принципе не умеет.

```text
WSGI:  синхронно, поток на запрос; нет WebSockets
ASGI:  асинхронно, событийный цикл; WebSockets, SSE, long-polling
```

FastAPI — это **ASGI-фреймворк**, поэтому он эффективен на IO-bound нагрузке
(много запросов, ждущих БД/сеть): один воркер обслуживает множество соединений,
пока они ждут. Это прямое следствие модели asyncio.

**Аналогия.** WSGI — кафе, где каждому гостю выделяют отдельного официанта на весь
визит (поток на запрос): много гостей — нужна толпа официантов. ASGI — один ловкий
официант, обслуживающий весь зал, переключаясь, пока гости думают над меню (ждут
IO).

## Starlette и uvicorn

FastAPI не реализует низкоуровневый веб с нуля — он стоит на двух китах:

- **Starlette** — лёгкий ASGI-**фреймворк**, который даёт FastAPI всю веб-механику:
  роутинг, запросы/ответы, middleware, WebSockets, background tasks. **FastAPI
  наследует Starlette** и добавляет поверх валидацию (Pydantic), DI и
  авто-документацию.
- **uvicorn** — ASGI-**сервер** (на основе uvloop/httptools), который принимает
  HTTP-соединения и вызывает ваше ASGI-приложение. Запуск:
  `uvicorn app.main:app`. В проде часто за процесс-менеджером (gunicorn с
  uvicorn-воркерами) и реверс-прокси.

```text
HTTP → uvicorn (ASGI-сервер) → Starlette (механика) → FastAPI (валидация, DI, доки)
```

Понимание этой связки — частый вопрос: FastAPI = Starlette (веб) + Pydantic
(данные) + сахар (DI, OpenAPI). uvicorn — то, что физически слушает порт.

**Аналогия.** uvicorn — это входная дверь и швейцар (принимает гостей с улицы),
Starlette — планировка здания и коридоры (как ходят запросы), FastAPI — сервис
внутри с ресепшеном, проверкой документов и справочной (валидация, DI, доки).

## Роутинг и параметры

**Эндпоинт** — функция, привязанная к пути и HTTP-методу декоратором
(`@app.get`, `@app.post`, …). FastAPI извлекает параметры из запроса **по
аннотациям типов**:

- **Path-параметры** — часть пути (`/items/{item_id}`); берутся из URL.
- **Query-параметры** — после `?` (`/items?skip=0&limit=10`); обычно параметры
  функции с дефолтами.
- **Body** — тело запроса (JSON), описывается **Pydantic-моделью**.

```python
@app.get("/items/{item_id}")
def read_item(item_id: int, q: str | None = None):   # path: item_id, query: q
    return {"item_id": item_id, "q": q}

@app.post("/items")
def create_item(item: ItemCreate):     # ItemCreate — Pydantic-модель из тела
    return item
```

FastAPI по типам **сам валидирует и приводит** данные (`item_id: int` — строка из
URL станет int или вернётся 422). **`APIRouter`** позволяет разбить приложение на
модули (роутеры по доменам) и подключить их через `app.include_router(...)` с общим
префиксом и тегами — так растут реальные приложения.

**Аналогия.** Роутинг — это адресная книга здания: декоратор говорит «запросы на
этот адрес и этим методом — сюда». Аннотации типов — бланк на входе, который
автоматически проверяет и раскладывает пришедшие данные по полям.

## Памятка для собеседования

- **WSGI** — синхронный, поток на запрос, без WebSockets; **ASGI** — асинхронный
  (`async`/`await`), конкурентность в одном потоке, WebSockets/SSE. FastAPI —
  **ASGI**-фреймворк → эффективен на IO-bound.
- Стек: **uvicorn** (ASGI-сервер, слушает порт) → **Starlette** (веб-механика,
  FastAPI её наследует) → **FastAPI** (Pydantic-валидация, DI, OpenAPI).
- Роутинг декораторами (`@app.get/post`); параметры по аннотациям: **path**
  (`{id}`), **query** (`?a=`), **body** (Pydantic). Авто-валидация/приведение
  типов. **`APIRouter`** — модульность.

## Частые ошибки в ответах

- Не уметь объяснить разницу WSGI/ASGI и почему FastAPI асинхронный.
- Думать, что FastAPI всё реализует сам (он на Starlette + Pydantic; сервер —
  uvicorn).
- Путать path/query/body параметры или не знать, что типы дают валидацию.
- Считать, что ASGI ускоряет CPU-bound (он про конкурентное ожидание IO).
