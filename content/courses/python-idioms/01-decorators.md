# Декораторы

> Цель урока: понять, что декоратор — это функция, которая принимает функцию и
> возвращает функцию, как пишутся декораторы с аргументами и зачем нужен
> `functools.wraps`. Декораторы — одна из самых частых тем на собесе: просят
> «напишите декоратор, измеряющий время выполнения» и ждут чистой реализации.

## Что такое декоратор

**Декоратор** — это функция (или класс), которая **принимает функцию и возвращает
другую функцию**, обычно расширяя поведение исходной, не меняя её код. Синтаксис
`@decorator` над функцией — это просто синтаксический сахар:

```python
@my_decorator
def greet(): ...

# полностью эквивалентно:
def greet(): ...
greet = my_decorator(greet)
```

Базовый шаблон декоратора — внутренняя функция-обёртка, которая делает что-то
до/после вызова оригинала:

```python
import functools

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)        # вызываем оригинал
        print(f"{func.__name__}: {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

@timed
def slow(): time.sleep(1)
```

`*args, **kwargs` в обёртке позволяют декоратору работать с **любой сигнатурой**.
Декораторы стоят на двух китах из курса Python Core: **функции — объекты первого
класса** и **замыкания** (обёртка помнит `func`).

**Аналогия.** Декоратор — это подарочная упаковка: внутри та же вещь (функция), но
снаружи добавлен бантик и открытка (новое поведение). Содержимое не меняется, а
получатель видит «обёрнутую» версию.

## functools.wraps

Когда обёртка заменяет оригинальную функцию, она **теряет её метаданные**: имя
(`__name__`), докстринг (`__doc__`), сигнатуру. Без починки `slow.__name__` станет
`"wrapper"`, что ломает отладку, интроспекцию, документацию и другие декораторы.

**`@functools.wraps(func)`** копирует метаданные оригинала на обёртку:

```python
def timed(func):
    @functools.wraps(func)         # без этого slow.__name__ == "wrapper"
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
# с wraps: slow.__name__ == "slow", докстринг и сигнатура сохранены
```

Это **обязательная** часть любого правильного декоратора. На собесе забыть `wraps`
— типичная ошибка, которую замечают.

**Аналогия.** `wraps` — это перенести этикетку с оригинальной коробки на
подарочную упаковку: снаружи всё ещё понятно, что внутри (имя, описание), а не
безликое «wrapper».

## Декоратор с аргументами

Если декоратору нужны параметры (`@retry(times=3)`), добавляется **ещё один уровень
вложенности**: внешняя функция принимает аргументы и возвращает сам декоратор.
Получается три уровня: параметры → функция → обёртка.

```python
def retry(times):                          # принимает аргумент
    def decorator(func):                   # принимает функцию
        @functools.wraps(func)
        def wrapper(*args, **kwargs):      # обёртка
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator

@retry(times=3)                            # retry(3) возвращает decorator
def fetch(): ...
```

Здесь `@retry(times=3)` сначала **вызывается** (возвращает `decorator`), а уже
`decorator` применяется к `fetch`. Понимание этих трёх уровней — частый
«отсеивающий» вопрос.

**Аналогия.** Декоратор с аргументами — это автомат, который сначала настраивают
(вставили монету `times=3`), и только потом он выдаёт упаковщик (decorator),
который и обернёт вашу вещь.

## Стек декораторов и классы-декораторы

Несколько декораторов **применяются снизу вверх** (ближайший к функции — первым), а
оборачивают **сверху вниз**:

```python
@a
@b
def f(): ...
# эквивалент: f = a(b(f)) — b применяется первым, a оборачивает снаружи
```

Порядок важен: `@app.route` + `@login_required` ведут себя по-разному в разном
порядке. Декоратором может быть и **класс** — если у него есть `__call__` (или он
использует `__init__` для захвата функции); это удобно, когда декоратору нужно
**хранить состояние** (счётчик вызовов, кэш). Типичные применения декораторов:
логирование, кэширование, проверка прав, ретраи, измерение времени, регистрация
обработчиков (роуты во Flask/FastAPI).

**Аналогия.** Стек декораторов — это слои упаковки: коробка в коробке. Разворачивают
снаружи внутрь, а заворачивали изнутри наружу — поэтому порядок слоёв имеет
значение.

## Памятка для собеседования

- Декоратор — функция, принимающая функцию и возвращающая функцию; `@d` над `f`
  это `f = d(f)`. Стоит на «функции — объекты» + замыкания.
- Обёртка использует `*args, **kwargs` → работает с любой сигнатурой; делает
  что-то до/после вызова оригинала.
- **`@functools.wraps(func)`** копирует метаданные (`__name__`, `__doc__`,
  сигнатуру) на обёртку — обязательно.
- Декоратор **с аргументами** = три уровня: параметры → функция → обёртка
  (`@retry(3)` сначала вызывается, потом применяется).
- Стек `@a @b` = `a(b(f))` (снизу вверх); классы-декораторы (`__call__`) удобны для
  состояния.

## Частые ошибки в ответах

- Забыть `functools.wraps` — теряются имя/докстринг/сигнатура функции.
- Не уметь объяснить три уровня вложенности у декоратора с аргументами.
- Перепутать порядок применения в стеке декораторов.
- Не использовать `*args, **kwargs` и тем самым ограничить декоратор одной
  сигнатурой.
