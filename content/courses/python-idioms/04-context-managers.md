# Контекст-менеджеры и with

> Цель урока: понять, что делает `with`, как реализовать свой контекст-менеджер
> двумя способами (`__enter__`/`__exit__` и `@contextmanager`), и почему это
> правильный способ управлять ресурсами. Вопрос «как гарантированно закрыть файл/
> соединение» проверяет, знаете ли вы про контекст-менеджеры, а не `try/finally`
> вручную.

## Зачем нужен with

`with` гарантирует, что ресурс будет **корректно освобождён** — даже если внутри
блока возникнет исключение или `return`. Это решает вечную проблему «забыли закрыть
файл/соединение/освободить блокировку».

```python
with open("data.txt") as f:
    process(f.read())
# файл закрыт автоматически — и при успехе, и при исключении внутри

# то, что with делает за вас, вручную выглядит так:
f = open("data.txt")
try:
    process(f.read())
finally:
    f.close()           # гарантированное закрытие
```

`with` — это и есть аккуратный `try/finally` под капотом, но короче, читаемее и
без шанса забыть `finally`. Применяется для файлов, сетевых соединений, блокировок
(`with lock:`), транзакций БД, временного изменения состояния.

**Аналогия.** `with` — как взять инструмент под расписку: что бы ни случилось во
время работы (даже если уроните), на выходе из помещения вы обязаны его сдать.
Система сама проследит за возвратом.

## __enter__ и __exit__

Контекст-менеджер — это объект с двумя методами:

- **`__enter__(self)`** — выполняется при входе в `with`; возвращаемое значение
  попадает в переменную после `as`.
- **`__exit__(self, exc_type, exc_val, exc_tb)`** — выполняется при выходе
  **всегда** (успех или исключение); получает информацию об исключении (или
  `None`, если его не было).

```python
class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                       # это значение получит `as t`
    def __exit__(self, exc_type, exc_val, exc_tb):
        print(f"elapsed: {time.perf_counter() - self.start:.3f}s")
        return False                      # False → исключение пробрасывается дальше

with Timer() as t:
    do_work()
```

Тонкость: если `__exit__` вернёт **`True`**, исключение будет **подавлено** (как
будто его не было); `False`/`None` — исключение **пробрасывается** дальше. Поэтому
случайный `return True` может «проглотить» ошибки — частая ловушка.

**Аналогия.** `__enter__` — войти в комнату и включить свет (захватить ресурс),
`__exit__` — обязательно выключить свет на выходе, что бы ни случилось внутри.
Вернуть `True` из `__exit__` — это «замять» инцидент, чтобы наружу о нём не узнали.

## contextlib.contextmanager

Писать класс с двумя методами ради простого случая многословно. Декоратор
**`@contextlib.contextmanager`** позволяет сделать контекст-менеджер из
**генератора с одним `yield`**: код до `yield` — это `__enter__`, код после — это
`__exit__`.

```python
from contextlib import contextmanager

@contextmanager
def opened(path):
    f = open(path)
    try:
        yield f                # значение для `as`; здесь выполняется тело with
    finally:
        f.close()              # гарантированная очистка (как __exit__)

with opened("data.txt") as f:
    process(f.read())
```

`yield` отдаёт ресурс в блок `with`; обернуть его в `try/finally` нужно, чтобы
очистка сработала и при исключении. Это самый частый и компактный способ написать
свой контекст-менеджер.

**Аналогия.** `@contextmanager` — это «свернуть» вход и выход в одну функцию, где
`yield` — момент «передаю ключи тебе, поработай», а `finally` — «вернул ключи,
прибрался».

## Готовые инструменты contextlib

`contextlib` содержит полезные готовые контекст-менеджеры:

- **`suppress(Exception)`** — подавить указанные исключения (`with
  suppress(FileNotFoundError): os.remove(path)` вместо `try/except: pass`).
- **`closing(obj)`** — гарантированно вызвать `obj.close()` для объектов без
  поддержки `with`.
- **`ExitStack`** — динамически управлять **переменным числом** контекст-менеджеров
  (например, открыть список файлов и гарантированно закрыть все).
- **`redirect_stdout`/`redirect_stderr`** — временно перенаправить вывод.

```python
from contextlib import suppress, ExitStack

with ExitStack() as stack:
    files = [stack.enter_context(open(p)) for p in paths]   # все закроются
    process(files)
```

Несколько контекст-менеджеров можно открывать и в одном `with` через запятую
(`with open(a) as fa, open(b) as fb:`).

**Аналогия.** `ExitStack` — это «список дел на выход»: сколько бы дверей вы ни
открыли по ходу, стек запомнит каждую и закроет все на выходе в обратном порядке.

## Памятка для собеседования

- `with` гарантирует освобождение ресурса при любом исходе (исключение/return) —
  это аккуратный `try/finally` под капотом; для файлов, соединений, блокировок,
  транзакций.
- Протокол: `__enter__` (вход, значение для `as`) и `__exit__` (выход **всегда**,
  получает инфо об исключении). `__exit__` вернул **True** → исключение
  **подавлено**; False/None → проброшено.
- `@contextlib.contextmanager` делает КМ из генератора с одним `yield` (до —
  enter, после в `finally` — exit) — компактный способ.
- Готовое: `suppress`, `closing`, `ExitStack` (переменное число КМ),
  `redirect_stdout`. Несколько КМ — через запятую в одном `with`.

## Частые ошибки в ответах

- Управлять ресурсами вручную через `try/finally` вместо `with`/контекст-менеджера.
- Не знать, что `__exit__` выполняется и при исключении, и что возврат `True`
  подавляет исключение (случайно проглотить ошибку).
- Не обернуть `yield` в `try/finally` в `@contextmanager` — очистка не сработает
  при исключении.
- Не знать про `ExitStack`/`suppress` и писать громоздкие конструкции вручную.
