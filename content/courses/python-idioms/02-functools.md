# functools: кэширование, partial, singledispatch

> Цель урока: освоить рабочую лошадку стандартной библиотеки — модуль `functools`.
> `lru_cache`, `partial`, `cached_property`, `singledispatch` — инструменты,
> которые часто всплывают в коде и на собесе («как закэшировать результат
> функции?» → `lru_cache`).

## lru_cache и cache: мемоизация

**`@functools.lru_cache`** автоматически **кэширует результаты** функции по её
аргументам: при повторном вызове с теми же аргументами возвращается сохранённый
результат, без пересчёта. Это **мемоизация** в одну строку.

```python
from functools import lru_cache

@lru_cache(maxsize=128)        # хранит до 128 последних результатов
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

fib(100)        # быстро: пересчёта нет, экспоненциальная рекурсия стала линейной
```

Ключевые нюансы: **аргументы должны быть хэшируемыми** (кэш — это словарь по
аргументам), поэтому `list`/`dict` передавать нельзя. `maxsize=None` (или
`@cache` в 3.9+) — неограниченный кэш (осторожно с памятью). LRU означает «least
recently used»: при переполнении вытесняется давно не используемое. Подходит для
**чистых функций** (результат зависит только от аргументов, нет побочных
эффектов); кэшировать функцию, читающую меняющиеся данные, опасно.

**Аналогия.** `lru_cache` — это блокнот, куда функция записывает «на вопрос X я уже
отвечал Y». Спросили то же — она просто читает из блокнота, а не считает заново.

## partial: фиксация аргументов

**`functools.partial`** создаёт новую функцию с **частично зафиксированными
аргументами** исходной. Удобно, когда нужно «специализировать» общую функцию или
передать функцию-колбэк с предзаданными параметрами.

```python
from functools import partial

def power(base, exp):
    return base ** exp

square = partial(power, exp=2)     # зафиксировали exp
cube = partial(power, exp=3)
square(5)     # 25 — вызов power(5, exp=2)

int2 = partial(int, base=2)        # парсер двоичных строк
int2("1010")  # 10
```

`partial` читаемее и эффективнее, чем `lambda` для той же цели, и сохраняет
информацию об оригинальной функции. Частое применение — колбэки, конфигурируемые
обработчики, адаптация сигнатур.

**Аналогия.** `partial` — это заранее настроенный инструмент: у дрели уже выставлена
нужная бита и скорость (фиксированные аргументы), осталось только нажать на курок с
оставшимися параметрами.

## cached_property и reduce

Ещё два полезных инструмента:

- **`@functools.cached_property`** — как `@property`, но результат **вычисляется
  один раз** и кэшируется в экземпляре; последующие обращения возвращают
  сохранённое значение. Идеально для **дорогих вычислений на основе неизменных
  данных объекта** (например, распарсить что-то один раз).

```python
from functools import cached_property

class Dataset:
    @cached_property
    def stats(self):               # тяжёлый расчёт — выполнится один раз
        return expensive_analysis(self.data)
```

- **`functools.reduce`** — сворачивает последовательность в одно значение,
  применяя функцию накопительно (`reduce(operator.add, nums)` = сумма). В Python
  им пользуются редко (явный цикл или `sum`/`math.prod` читаемее), но знать стоит:
  это классический «fold» из функционального программирования.

**Аналогия.** `cached_property` — посчитать что-то один раз и повесить результат на
стену объекта: следующий, кто спросит, просто читает табличку. `reduce` — как
снежный ком: катится по списку, накапливая результат.

## singledispatch: перегрузка по типу

В Python нет перегрузки функций по типам аргументов (как в Java), но
**`@functools.singledispatch`** даёт **диспетчеризацию по типу первого
аргумента** — разные реализации для разных типов:

```python
from functools import singledispatch

@singledispatch
def serialize(obj):
    raise TypeError(f"unsupported: {type(obj)}")

@serialize.register
def _(obj: dict):
    return json.dumps(obj)

@serialize.register
def _(obj: list):
    return ",".join(map(str, obj))

serialize({"a": 1})    # выберет реализацию для dict
serialize([1, 2, 3])   # выберет реализацию для list
```

Это чище, чем длинная цепочка `if isinstance(...)`, и расширяемо: новые типы
регистрируются отдельно, не трогая исходную функцию (соответствует Open/Closed).
Есть и `singledispatchmethod` для методов класса.

**Аналогия.** `singledispatch` — это диспетчер на входе, который смотрит на тип
«посетителя» (dict, list) и направляет к нужному специалисту, вместо одного
сотрудника с огромным списком «если это — то…».

## Памятка для собеседования

- **`@lru_cache`/`@cache`** — мемоизация по аргументам (должны быть хэшируемыми);
  для чистых функций; LRU-вытеснение при `maxsize`. Превращает экспоненциальную
  рекурсию в линейную.
- **`partial`** — фиксирует часть аргументов, создаёт специализированную функцию;
  читаемее `lambda` для колбэков.
- **`cached_property`** — `property`, вычисляемое один раз и кэшируемое в
  экземпляре; для дорогих расчётов по неизменным данным.
- **`reduce`** — накопительная свёртка (fold); в Python применяют редко.
- **`singledispatch`** — диспетчеризация по типу первого аргумента вместо цепочки
  `isinstance`; расширяема.

## Частые ошибки в ответах

- Кэшировать через `lru_cache` функцию с нехэшируемыми аргументами или с
  побочными эффектами/меняющимися данными.
- Не знать про `cached_property` и каждый раз пересчитывать дорогое свойство.
- Путать `partial` с обычным вызовом; не видеть его пользы для колбэков.
- Городить длинные `if isinstance` вместо `singledispatch`, где он уместен.
