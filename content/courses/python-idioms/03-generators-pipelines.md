# Генераторы, send и конвейеры

> Цель урока: углубить тему генераторов из Python Core — научиться строить
> ленивые **конвейеры обработки**, понять двусторонний `yield` (`send`) и где
> генераторы экономят память в реальных задачах (обработка логов, потоков,
> больших файлов). Это «питоничный» способ обрабатывать данные, который ценят на
> собесе.

## Конвейеры на генераторах

Генераторы можно **соединять в конвейер**: выход одного становится входом
другого. Поскольку каждый шаг ленивый, данные текут **по одному элементу** через
всю цепочку, не материализуясь целиком. Это позволяет обрабатывать огромные потоки
при почти константной памяти.

```python
def read_lines(path):
    with open(path) as f:
        for line in f:
            yield line.rstrip()

def grep(pattern, lines):
    for line in lines:
        if pattern in line:
            yield line

def parse(lines):
    for line in lines:
        yield line.split("\t")

# конвейер: читаем → фильтруем → парсим, всё лениво, построчно
rows = parse(grep("ERROR", read_lines("huge.log")))
for row in rows:           # данные текут по одной строке
    handle(row)
```

Каждый этап — маленькая, тестируемая функция; вместе они образуют пайплайн в стиле
Unix-пайпов (`cat | grep | cut`). Память не зависит от размера файла, потому что в
каждый момент «в работе» только одна строка.

**Аналогия.** Это конвейерная лента на заводе: деталь проходит станок за станком
(фильтр, парсер), и на ленте в каждый момент — одна деталь, а не весь склад. Не
нужно место под промежуточные горы заготовок.

## Экономия памяти на практике

Главная ценность генераторов — **обработка данных, не помещающихся в память**, и
**раннее получение результатов**. Сравните подходы:

```python
# плохо: materialize всё в память — упадём на большом файле
lines = open("10gb.log").readlines()      # весь файл в список
errors = [l for l in lines if "ERROR" in l]

# хорошо: ленивый поток, память ~константа
def errors(path):
    for line in open(path):
        if "ERROR" in line:
            yield line
```

Дополнительный плюс — **ленивость даёт ранний выход**: с генератором можно взять
первые N результатов (`itertools.islice`) или остановиться по условию, не
обрабатывая остальное. Со списком пришлось бы посчитать всё. Генераторы также
позволяют описывать **бесконечные** последовательности (поток событий, счётчик),
из которых берут ровно столько, сколько нужно.

**Аналогия.** Список — заказать самосвал щебня целиком (нужна площадка под всё);
генератор — лента, подающая щебень по ковшу: берёшь сколько надо и в любой момент
останавливаешь.

## Двусторонний yield: send и корутины

`yield` умеет не только **отдавать** значения, но и **принимать** их обратно через
метод `.send()`. Выражение `x = yield` приостанавливает генератор и при следующем
`gen.send(value)` присваивает `x` это `value`. Такой генератор называют
**(классической) корутиной** — он не только производит данные, но и потребляет.

```python
def averager():
    total, count = 0, 0
    average = None
    while True:
        value = yield average          # отдаём среднее, принимаем новое значение
        total += value
        count += 1
        average = total / count

avg = averager()
next(avg)            # «прокрутить» до первого yield (priming)
avg.send(10)         # 10.0
avg.send(20)         # 15.0 — генератор хранит состояние между send
```

Важно: перед первым `send` корутину нужно «запустить» (`next()` или `send(None)`).
Это исторический механизм — на нём строились ранние асинхронные библиотеки. В
современном коде для асинхронности используют `async`/`await` (см. курс Asyncio), а
`send`-корутины встречаются реже, но понимание двустороннего `yield` объясняет, как
вообще выросла модель корутин в Python.

**Аналогия.** Обычный генератор — кран, выдающий воду (значения). `send`-корутина —
двусторонняя труба: вы и получаете из неё, и заливаете обратно, а она помнит
накопленное между обменами.

## Памятка для собеседования

- Генераторы соединяются в **ленивые конвейеры**: данные текут по одному элементу
  через цепочку (read → filter → parse), память ~константа независимо от объёма.
- Главная польза — обработка данных, **не влезающих в память**, и **ранний выход**
  (взять первые N через `islice`, остановиться по условию); возможны бесконечные
  последовательности.
- `yield` двусторонний: `x = yield` + `gen.send(value)` делает **классическую
  корутину** (производит и потребляет), хранящую состояние; перед `send` нужен
  priming (`next`).
- Современная асинхронность — `async/await`; `send`-корутины — исторический корень
  этой модели.

## Частые ошибки в ответах

- Загружать большой файл целиком (`readlines`) вместо ленивой построчной
  обработки.
- Не видеть, что генераторы дают ранний выход и работают с бесконечными потоками.
- Забыть «запустить» корутину перед первым `send` (нужен `next`/`send(None)`).
- Путать классические `send`-корутины и современные `async`-корутины.
