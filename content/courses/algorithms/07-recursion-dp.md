# Рекурсия, динамическое программирование и паттерны

> Цель урока: понять рекурсию, как из неё вырастает динамическое программирование
> (DP), и обзор главных паттернов решения задач. DP пугает кандидатов больше
> всего, но за ним стоит простая идея «не считать одно и то же дважды».

## Рекурсия

**Рекурсия** — функция вызывает саму себя на **меньшей** подзадаче, пока не дойдёт
до **базового случая**. Два обязательных элемента:

- **Базовый случай** — условие остановки (без него — бесконечная рекурсия и
  `RecursionError`).
- **Рекурсивный шаг** — сведение задачи к меньшей.

```python
def factorial(n):
    if n <= 1:               # базовый случай
        return 1
    return n * factorial(n - 1)   # шаг к меньшей задаче
```

Рекурсия естественна для **самоподобных** структур: деревья, графы (DFS), задачи
«разделяй и властвуй». Важно помнить про **глубину**: Python ограничивает стек
(~1000 кадров по умолчанию), глубокая рекурсия даёт `RecursionError`; хвостовая
рекурсия в CPython **не оптимизируется**, поэтому глубокие случаи переписывают в
**итерацию с явным стеком**.

**Аналогия.** Рекурсия — как матрёшки: чтобы открыть большую, открываешь
вложенную, и так до самой маленькой (базовый случай), потом собираешь обратно. Без
самой маленькой матрёшки процесс не закончится.

## От рекурсии к DP

Наивная рекурсия часто **пересчитывает одни и те же подзадачи** экспоненциальное
число раз. Классика — числа Фибоначчи: `fib(n)` пересчитывает `fib(n-2)` много
раз, давая **O(2ⁿ)**.

**Динамическое программирование (DP)** применимо, когда задача обладает:

- **Перекрывающимися подзадачами** — одни и те же подзадачи встречаются много раз
  (их стоит запомнить).
- **Оптимальной подструктурой** — оптимум задачи строится из оптимумов подзадач.

Два подхода DP:

- **Мемоизация (top-down)** — обычная рекурсия + **кэш** результатов: каждую
  подзадачу считаем **один раз**. В Python — просто `@lru_cache`.
- **Табуляция (bottom-up)** — заполняем таблицу от базовых случаев к ответу, без
  рекурсии.

```python
from functools import lru_cache

@lru_cache(maxsize=None)         # мемоизация: O(2^n) → O(n)
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)

def fib_tab(n):                  # табуляция: O(n) время, O(1) память
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

DP превращает экспоненту в полином, **запоминая** уже посчитанное. Узнать «это DP»
по словам «сколько способов», «минимум/максимум при выборе», «оптимально» —
половина решения.

**Аналогия.** DP — как решать задачи со шпаргалкой ответов на подзадачи: посчитал
`fib(5)` раз — записал, и больше не пересчитываешь. Наивная рекурсия — решать одну и
ту же подзадачу заново каждый раз, как если бы каждый раз забывал ответ.

## Классические задачи DP

Полезно узнавать архетипы (на собесе варьируют их):

- **Рюкзак (knapsack)** — выбрать предметы с максимальной ценностью при
  ограничении веса.
- **LIS (longest increasing subsequence)** — длиннейшая возрастающая
  подпоследовательность.
- **Edit distance** — минимум операций превратить одну строку в другую.
- **Coin change** — минимум монет / число способов набрать сумму.
- **Пути в сетке** — число путей / минимальная стоимость пути.

Эти задачи объединяет: определить **состояние** (что описывает подзадачу) и
**переход** (как из меньших состояний получить большее). Сформулировать
рекуррентное соотношение — суть DP; код (мемоизация/таблица) уже механика.

**Аналогия.** Освоить архетипы DP — как выучить типовые шахматные комбинации:
встретив похожую позицию (формулировку), узнаёшь идею и применяешь, а не
изобретаешь с нуля под стрессом.

## Обзор паттернов решения

Сводка стратегий, которые стоит держать в голове, выбирая подход:

- **Жадные (greedy)** — на каждом шаге локально оптимальный выбор; работает, если
  у задачи есть «жадное свойство» (но не всегда — иногда даёт неоптимум, и тогда
  нужен DP).
- **Разделяй и властвуй (divide & conquer)** — разбить на независимые подзадачи,
  решить, объединить (merge sort, бинарный поиск).
- **Backtracking (перебор с возвратом)** — строим решение по шагам, **откатываемся**
  при тупике; для перестановок, комбинаций, судоку, N ферзей.
- **Two pointers / sliding window / хэширование** — для массивов и строк (отдельный
  урок).

Главный мета-навык — **распознать паттерн** по формулировке: «кратчайший путь» →
BFS/Dijkstra; «все комбинации» → backtracking; «сколько способов / оптимум при
выборе» → DP; «отсортировано» → бинарный поиск/два указателя. Распознавание важнее
зубрёжки конкретных решений.

**Аналогия.** Паттерны — как набор инструментов в ящике: опытный мастер по виду
задачи сразу тянется за нужным (DP, greedy, backtracking), а не пробует один и тот
же молоток на всё.

## Памятка для собеседования

- **Рекурсия** = базовый случай + шаг к меньшей задаче; естественна для
  деревьев/графов/«разделяй и властвуй». Python: лимит стека (~1000), нет
  оптимизации хвостовой рекурсии → глубокое в итерацию.
- **DP** при **перекрывающихся подзадачах** + **оптимальной подструктуре**:
  **мемоизация** (top-down, `@lru_cache`) или **табуляция** (bottom-up); превращает
  O(2ⁿ) в полином.
- Архетипы: рюкзак, LIS, edit distance, coin change, пути в сетке — определить
  **состояние** и **переход**.
- Паттерны: **greedy** (локальный оптимум), **divide & conquer**, **backtracking**
  (перебор с откатом). Главное — **распознать** паттерн по формулировке.

## Частые ошибки в ответах

- Забыть базовый случай (бесконечная рекурсия) или не знать про лимит стека в
  Python.
- Не видеть перекрывающиеся подзадачи и оставлять наивную экспоненциальную
  рекурсию.
- Путать мемоизацию (top-down) и табуляцию (bottom-up) или не уметь сформулировать
  состояние/переход.
- Применять жадный алгоритм там, где он даёт неоптимум (нужен DP), не проверив
  «жадное свойство».
