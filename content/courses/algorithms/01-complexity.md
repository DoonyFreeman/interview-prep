# Сложность: Big-O

> Цель урока: научиться оценивать сложность алгоритма по времени и памяти и
> говорить о ней на языке Big-O. Это первое, что спрашивают в алгоритмической
> секции: «какая сложность вашего решения» — и без уверенного ответа дальше не
> пускают.

## Что такое Big-O

**Big-O** описывает, как **растёт** время (или память) алгоритма с увеличением
размера входных данных `n`, **в худшем случае** и **асимптотически** (при больших
`n`, отбрасывая константы и младшие члены). Это про **скорость роста**, а не про
конкретные секунды.

Основные классы по возрастанию:

```text
O(1)        константная   — не зависит от n (доступ по индексу, hash-lookup)
O(log n)    логарифмическая — деление пополам (бинарный поиск)
O(n)        линейная      — один проход (перебор массива)
O(n log n)  — эффективные сортировки (Timsort, merge sort)
O(n^2)      квадратичная  — вложенные циклы (наивная сортировка, все пары)
O(2^n)      экспоненциальная — перебор подмножеств (наивная рекурсия)
O(n!)       факториальная — перестановки
```

Правила оценки: отбрасываем **константы** (`O(2n)` = `O(n)`) и **младшие члены**
(`O(n² + n)` = `O(n²)`); вложенные циклы **перемножаются**, последовательные —
**складываются** (берём больший). Цель — не написать случайно `O(n²)` или хуже там,
где можно `O(n)`/`O(n log n)`.

**Аналогия.** Big-O — это не «сколько ты бежишь», а «насколько хуже становится,
когда дистанция растёт». O(1) — телепорт (всё равно куда), O(n) — идти пешком,
O(n²) — обходить каждый дом ради каждого дома, O(2^n) — перебирать все маршруты.

## Время и память

Сложность бывает **по времени** (сколько операций) и **по памяти** (сколько
дополнительного места). Их часто **разменивают** друг на друга — классический
**trade-off время↔память**:

```python
# время O(n^2), память O(1): для каждого ищем пару перебором
def two_sum_slow(nums, target):
    for i in range(len(nums)):
        for j in range(i+1, len(nums)):
            if nums[i] + nums[j] == target:
                return (i, j)

# время O(n), память O(n): храним виденные в хэш-таблице
def two_sum_fast(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:        # O(1) поиск
            return (seen[target - x], i)
        seen[x] = i
```

Здесь хэш-таблица (доп. память O(n)) ускоряет поиск с O(n²) до O(n) — типичный
размен «памятью купить время». На собесе уточняют **обе** сложности; «O(n) по
времени и O(n) по памяти» — полный ответ.

**Аналогия.** Trade-off время↔память — как шпаргалка: записал ответы заранее
(потратил память) — отвечаешь мгновенно (сэкономил время). Без шпаргалки — считаешь
каждый раз заново (медленнее, но память не тратишь).

## Best, average, worst и амортизация

Сложность может различаться по случаям:

- **Worst case** — гарантия «не хуже чем»; обычно именно её называют в Big-O
  (надёжная верхняя граница).
- **Average case** — ожидаемая на типичных данных (например, hash-lookup в среднем
  O(1), но в худшем O(n) при коллизиях).
- **Best case** — лучший расклад (редко интересен).

Отдельно — **амортизированная** сложность: средняя стоимость операции **в серии**,
даже если отдельные операции дороги. Классика — `list.append`: обычно O(1), но
изредка массив переаллоцируется за O(n); **усреднённо по многим append'ам — O(1)
амортизированно**. Важно не путать «амортизированно O(1)» с «всегда O(1)»: отдельный
append может быть дорогим, но в среднем — дёшев.

**Аналогия.** Амортизация — как абонемент в спортзал: разовый платёж (переаллокация)
большой, но если разнести его на все посещения месяца, цена за visit мала. Так и
append: редкая дорогая операция «размазывается» на множество дешёвых.

## Памятка для собеседования

- **Big-O** — асимптотический рост в **худшем** случае; отбрасываем константы и
  младшие члены. Классы: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!).
- Вложенные циклы перемножаются, последовательные складываются (берём больший).
- Оценивать **и время, и память**; типичный размен **время↔память** (хэш-таблица:
  +O(n) памяти → O(n²)→O(n) по времени).
- **Worst/average/best**; **амортизированная** — средняя в серии (`append` — O(1)
  амортизированно, не «всегда O(1)»).

## Частые ошибки в ответах

- Называть только время, забывая про память (или наоборот).
- Не упрощать (`O(2n+5)` вместо `O(n)`) или, наоборот, терять старший член.
- Путать амортизированное O(1) с гарантированным O(1) на каждой операции.
- Давать сложность «в среднем», когда спрашивают про худший случай (или наоборот).
