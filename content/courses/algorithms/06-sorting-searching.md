# Сортировка и бинарный поиск

> Цель урока: понять сравнительные сортировки и их свойства (включая Timsort
> Python) и освоить бинарный поиск — один из самых частых и при этом коварных в
> реализации алгоритмов. «Реализуйте бинарный поиск» и «какая сложность сортировки»
> — почти гарантированные вопросы.

## Сравнительные сортировки

Сортировки **сравнением** не могут быть быстрее **O(n log n)** в худшем случае —
это доказанная нижняя граница. Знать ключевые:

- **Merge sort** — «разделяй и властвуй»: делим пополам, сортируем части, **сливаем**.
  **Всегда O(n log n)**, **стабильна**, но требует **O(n) доп. памяти**.
- **Quick sort** — выбираем опорный (pivot), разбиваем на «меньше/больше»,
  рекурсивно. В среднем **O(n log n)**, на месте, но **худший случай O(n²)** (при
  неудачном pivot); не стабильна.
- **Heap sort** — через кучу; O(n log n), на месте, не стабильна.
- Простые **O(n²)** (bubble, insertion, selection) — для обучения; insertion быстра
  на **почти отсортированных** малых данных.

Два свойства, о которых спрашивают: **стабильность** (равные элементы сохраняют
исходный порядок — нужно для многоключевой сортировки) и **на месте** (O(1) доп.
памяти).

**Аналогия.** Merge sort — разложить колоду на стопки, отсортировать и аккуратно
слить (надёжно, но нужен стол под копии). Quick sort — выбрать карту-эталон и быстро
раскидать остальные на «меньше/больше» (быстро, но если эталон неудачный — буксует).

## Timsort в Python

`sorted()` и `list.sort()` в Python используют **Timsort** — гибрид **merge sort +
insertion sort**, разработанный специально под реальные данные:

- **Стабильный** (важно для сортировки по нескольким ключам).
- **Адаптивный** — находит уже отсортированные участки («runs») и не сортирует их
  зря; на почти упорядоченных данных приближается к **O(n)**.
- Худший случай — **O(n log n)**.

```python
data.sort(key=lambda x: x.field)         # Timsort, стабильно, O(n log n)
sorted(data, key=len, reverse=True)
# многоключевая сортировка через стабильность:
data.sort(key=lambda x: x.secondary)     # сначала вторичный ключ
data.sort(key=lambda x: x.primary)       # потом первичный — порядок внутри сохранён
```

Практический вывод: **в Python почти всегда используют встроенный `sort`/`sorted`**
(Timsort), а не пишут свою сортировку. Понимание его стабильности и адаптивности —
то, что отличает знающего ответ.

**Аналогия.** Timsort — опытный сортировщик карт, который замечает уже разложенные
по порядку пачки и не трогает их, а лишь сливает; и при равных картах не меняет их
порядок (стабильность).

## Бинарный поиск

**Бинарный поиск** находит элемент в **отсортированном** массиве за **O(log n)**,
каждый раз **деля область поиска пополам**. Главное условие — данные
**отсортированы**.

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:                       # <= важно: границы включительно
        mid = (lo + hi) // 2              # в Python переполнения нет
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1                  # ищем в правой половине
        else:
            hi = mid - 1                  # в левой
    return -1
```

Коварство — **граничные условия**: `lo <= hi` vs `lo < hi`, `mid+1`/`mid-1` —
здесь делают ошибки (бесконечный цикл, пропуск элемента). Бинарный поиск шире, чем
«найти элемент»: **поиск по ответу** (минимальное значение, удовлетворяющее
условию — «binary search on the answer»), поиск левой/правой границы, `bisect` в
стандартной библиотеке. Признак «можно бинарным поиском» — **монотонность**:
свойство меняется один раз с «нет» на «да».

**Аналогия.** Бинарный поиск — как угадывать число «больше/меньше»: каждый вопрос
вдвое сужает диапазон, поэтому из миллиона вариантов хватает ~20 вопросов. Главное —
чтобы было «отсортировано» (ответы согласованы).

## Памятка для собеседования

- Сортировки сравнением — не быстрее **O(n log n)**. **Merge** (стабильна, O(n)
  память), **quick** (в среднем O(n log n), худший O(n²), на месте), **heap**.
  Свойства: **стабильность**, **на месте**.
- Python: `sort`/`sorted` = **Timsort** (merge+insertion): **стабильный**,
  **адаптивный** (≈O(n) на почти отсортированных), O(n log n). Многоключевая
  сортировка через стабильность.
- **Бинарный поиск** — O(log n) на **отсортированном**; следить за границами
  (`lo<=hi`, `mid±1`). Шире: **поиск по ответу**, левая/правая граница, `bisect`.
  Признак — **монотонность**.

## Частые ошибки в ответах

- Не знать нижнюю границу O(n log n) для сортировок сравнением или худший O(n²) у
  quicksort.
- Не знать, что Python использует Timsort, и его свойства (стабильность,
  адаптивность).
- Ошибаться в границах бинарного поиска (бесконечный цикл, off-by-one).
- Применять бинарный поиск к неотсортированным данным или не видеть «поиск по
  ответу».
