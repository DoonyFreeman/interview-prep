# Деревья, BST и кучи

> Цель урока: понять деревья, бинарные деревья поиска, их обходы и кучу (heap).
> Деревья — самая частая структура на алгоритмических собеседованиях после
> массивов; обходы и BST спрашивают почти всегда.

## Деревья и обходы

**Дерево** — иерархическая структура из узлов: корень, у каждого узла —
потомки, нет циклов. **Бинарное дерево** — у узла не более двух детей (left,
right). Главный навык — **обходы (traversal)**:

- **DFS (в глубину)**, три порядка по моменту посещения корня:
  - **pre-order** (корень → лево → право) — копирование дерева, префиксная запись.
  - **in-order** (лево → корень → право) — для **BST даёт отсортированный
    порядок**.
  - **post-order** (лево → право → корень) — удаление, вычисление снизу вверх.
- **BFS (в ширину, по уровням)** — обход уровень за уровнем через **очередь**
  (`deque`); нужен для «по уровням», кратчайший путь по числу рёбер.

```python
def inorder(node):
    if not node: return
    inorder(node.left)
    visit(node.val)          # между поддеревьями → для BST по возрастанию
    inorder(node.right)
```

DFS естественно пишется **рекурсией** (или явным стеком), BFS — **очередью**.
Узнавать, какой обход нужен под задачу, — ключевой навык.

**Аналогия.** Обход дерева — как осмотр организационной структуры: DFS — спускаться
по одной ветви до конца, потом возвращаться (вглубь по подчинённым); BFS — обойти
сначала всех топ-менеджеров, потом всех их замов (по уровням).

## Бинарное дерево поиска (BST)

**BST (Binary Search Tree)** — бинарное дерево с **инвариантом**: для любого узла
**все значения слева меньше**, **справа больше**. Это даёт **поиск, вставку,
удаление за O(log n)** — на каждом шаге отбрасываем половину дерева (как бинарный
поиск).

```python
def search(node, target):
    while node:
        if target == node.val: return node
        node = node.left if target < node.val else node.right   # отбрасываем половину
```

**Критичная оговорка**: O(log n) — только для **сбалансированного** дерева. Если
вставлять отсортированные данные в наивный BST, он **выродится в список** (каждый
узел — правый ребёнок), и операции станут **O(n)**. Поэтому на практике используют
**самобалансирующиеся** деревья (**AVL**, **красно-чёрное**), которые
поддерживают сбалансированность поворотами. `in-order` обход BST выдаёт значения
**по возрастанию** — частый трюк.

**Аналогия.** BST — как поиск слова в словаре: открыл посередине, понял, раньше или
позже, отбросил половину. Но если словарь «отсортирован» так, что все слова на одной
странице (вырожденное дерево), преимущество теряется — листаешь подряд (O(n)).

## Куча (heap) и trie

Две специализированные структуры:

- **Куча (heap)** — дерево с инвариантом **min-heap** (родитель ≤ детей) или
  **max-heap**: **минимум/максимум — в корне, доступ O(1)**; вставка и извлечение —
  **O(log n)**. Нужна, когда постоянно нужен **наименьший/наибольший** элемент:
  приоритетные очереди, **top-K**, слияние k списков, Dijkstra. В Python —
  **`heapq`** (min-heap на списке).

```python
import heapq
h = []
heapq.heappush(h, 5)         # O(log n)
heapq.heappush(h, 1)
smallest = heapq.heappop(h)  # 1 — минимум, O(log n)
# top-K: heapq.nlargest(k, data)
```

- **Trie (префиксное дерево)** — дерево, где путь от корня — это **префикс строки**;
  хранит набор строк с общими префиксами компактно. Поиск/вставка слова — **O(длины
  слова)**, не зависит от числа слов. Применения: автодополнение, словари,
  префиксный поиск.

**Аналогия.** Куча — как сортировочная корзина, которая всегда держит самый
лёгкий/тяжёлый элемент сверху, не сортируя всё целиком. Trie — как телефонный
справочник по буквам: общий префикс «Ива-» ведёт к «Иванов», «Иваненко» по одной
ветке.

## Памятка для собеседования

- **Обходы**: DFS (pre/in/post-order, рекурсия/стек) — **in-order BST = по
  возрастанию**; **BFS** (по уровням, **очередь**/`deque`).
- **BST**: слева меньше, справа больше → поиск/вставка/удаление **O(log n)**, но
  **только сбалансированное**; вырождается в O(n) на отсортированных вставках →
  AVL/красно-чёрные.
- **Куча (`heapq`)**: min/max в корне (O(1) доступ), push/pop **O(log n)**; для
  **top-K**, приоритетных очередей, Dijkstra. **Trie** — префиксы, поиск за O(длины
  слова).

## Частые ошибки в ответах

- Называть поиск в BST O(log n) без оговорки про балансировку (вырождение в O(n)).
- Не знать, что in-order обход BST даёт сортированный порядок.
- Писать BFS через рекурсию/стек (нужна очередь) или DFS через очередь.
- Сортировать весь массив ради top-K вместо кучи (`heapq.nlargest`, O(n log k)).
