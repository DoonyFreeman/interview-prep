# SQLAlchemy: Core против ORM

> Цель урока: понять двухуровневую архитектуру SQLAlchemy (Core и ORM), роль
> Engine и пула соединений, и когда что выбирать. Это вводный, но важный для собеса
> блок: многие используют ORM, не понимая, что под ним есть Core и Engine с пулом.

## Два уровня: Core и ORM

SQLAlchemy состоит из **двух слоёв**, и понимание их разделения — признак зрелости:

- **Core** — нижний уровень: работа с БД через **SQL Expression Language**
  (Python-конструкции, строящие SQL) и объекты `Table`/`Column`. Вы мыслите
  **таблицами и запросами**, без классов-сущностей. Близко к SQL, максимальный
  контроль.
- **ORM (Object-Relational Mapper)** — верхний уровень: **маппинг классов Python на
  таблицы**, работа с объектами-сущностями, Session, отношения, identity map.
  Вы мыслите **объектами**, а ORM транслирует это в SQL.

```python
# Core: мыслим таблицами и выражениями
stmt = select(users_table).where(users_table.c.age > 18)

# ORM: мыслим объектами-сущностями
stmt = select(User).where(User.age > 18)
user = session.get(User, 1)
```

Важно: **ORM построен поверх Core** — он использует тот же Engine, тот же
Expression Language. Это не два конкурента, а слои. На практике приложения чаще
используют ORM, опускаясь в Core для тяжёлых/нестандартных запросов и массовых
операций.

**Аналогия.** Core — это ручная коробка передач (полный контроль над SQL); ORM —
автомат (удобно мыслить объектами, рутина скрыта). Автомат построен на той же
механике; иногда переключаешься в ручной режим для сложного манёвра.

## Engine и пул соединений

**Engine** — центральная точка подключения к БД: он создаётся один раз на
приложение (`create_engine(url)` или `create_async_engine`) и **управляет пулом
соединений**. Engine — это не одно соединение, а **фабрика и пул** соединений.

```python
engine = create_engine("postgresql://user:pass@host/db", pool_size=5, max_overflow=10)
```

**Пул соединений** критичен для производительности: открытие нового TCP-соединения
к БД дорого (рукопожатие, аутентификация). Пул **переиспользует** уже открытые
соединения: запрос «берёт» соединение из пула на время работы и **возвращает**
его, а не закрывает. Параметры: `pool_size` (постоянные соединения), `max_overflow`
(временные сверх лимита), `pool_timeout`, `pool_recycle` (пересоздавать старые,
чтобы БД их не разорвала).

**Аналогия.** Пул соединений — как парк такси у вокзала: машины (соединения) уже
заведены и ждут. Пассажир (запрос) берёт свободную, едет и возвращает её в парк, а
не покупает новую машину под каждую поездку. Без пула каждый запрос «покупал бы
машину» — дорого и медленно.

## Когда Core, когда ORM

Практический выбор:

- **ORM** — для большинства прикладной логики: CRUD над сущностями, связи между
  объектами, бизнес-логика «в терминах объектов». Удобство, читаемость, identity
  map, отслеживание изменений.
- **Core** — для **массовых операций** (`bulk insert/update` без накладных расходов
  на объекты), сложной аналитики, нестандартного SQL, миграций данных, когда важна
  **скорость** и не нужны объекты-сущности.

```python
# Core для массовой вставки — быстро, без оверхеда ORM на каждый объект
conn.execute(insert(users_table), [{"name": n} for n in many_names])
```

Цена ORM — **накладные расходы**: создание объектов, отслеживание изменений,
identity map. Для десятка объектов это незаметно, для миллионов строк в одной
операции — существенно, и тогда спускаются в Core. Сильный ответ: «ORM по
умолчанию, Core — для bulk-операций и тяжёлых запросов, где оверхед объектов
неоправдан».

**Аналогия.** ORM — удобный личный помощник, который ведёт учёт каждого поручения
(хорошо для повседневных дел). Core — прямой доступ к складу: когда надо перевезти
тысячу коробок разом, помощник с его учётом каждой коробки только мешает.

## Памятка для собеседования

- SQLAlchemy = **два слоя**: **Core** (SQL Expression Language, таблицы/запросы,
  контроль) и **ORM** (маппинг классов на таблицы, объекты, Session). ORM построен
  **поверх** Core.
- **Engine** — фабрика и **пул соединений**, один на приложение
  (`create_engine`/`create_async_engine`).
- **Пул** переиспользует дорогие соединения (`pool_size`, `max_overflow`,
  `pool_recycle`) вместо открытия нового на каждый запрос.
- Выбор: **ORM по умолчанию**; **Core** — для bulk-операций, тяжёлого/нестандартного
  SQL, где оверхед объектов неоправдан.

## Частые ошибки в ответах

- Не знать, что ORM построен на Core, и считать их альтернативами.
- Думать, что Engine — это одно соединение (это пул/фабрика).
- Не понимать роль пула соединений и его параметров.
- Использовать ORM для массовых операций над миллионами строк вместо Core.
