# Glossary Quiz Plan — тесты на знание терминов (Фаза 5d)

План фичи: внутри раздела «Словарь» можно **пройти тест на знание терминов**,
сгруппированный **по областям знаний** (категориям глоссария). Это план, не
реализация.

Опирается на уже готовую Фазу 5c: 138 терминов P0 в `content/glossary.json`,
таблица `glossary_terms`, публичный `GET /api/glossary`, страница `/glossary`.

---

## Зачем

- Глоссарий сейчас «для чтения» — тест превращает его в **активную проверку**:
  пользователь не просто листает, а проверяет, что реально помнит.
- Естественное продолжение основной идеи сайта (квиз по теории) — но лёгкое,
  быстрое и без затрат на LLM.
- Группировка по категориям = «прокачать конкретную область» (БД, async, сети).

## Куда встаёт в роадмап

**Фаза 5d**, сразу после 5c (раздел уже есть — тест надстраивается над ним).
До Фазы 6 (контент) и Фазы 7 (Docker). Дробится на тонкие срезы (см. ниже):
сначала чисто клиентский MVP без бэкенда, прогресс/LLM — отдельными срезами позже.

## Куда встаёт в архитектуру

Ключевое наблюдение: страница `/glossary` **уже загружает все термины с
определениями**. Значит MVP-тест (multiple-choice) можно собрать **целиком на
клиенте** из этих данных — без новых таблиц, эндпоинтов и без LLM. Это самый
лёгкий и self-hosted-дружелюбный путь, в духе стека.

- Дистракторы (неверные варианты) берём из **других терминов той же категории** —
  они бесплатны и осмысленны (близкие по теме = сложнее и полезнее). Если в
  категории < 4 терминов — добираем из остального глоссария.
- Никакого авторинга вопросов: вопрос генерируется из пары «термин ↔ short_md».

## Рекомендуемый формат: multiple-choice (авто-проверка)

Два типа вопросов для разнообразия (микс):
1. **Определение → термин:** показываем `short_md`, выбрать правильный `term` из 4.
2. **Термин → определение:** показываем `term`, выбрать правильный `short_md` из 4.

Почему MCQ, а не открытый ответ с LLM (для MVP):
- мгновенно, без сети и без расхода квоты Gemini;
- работает офлайн и детерминированно (легко тестировать);
- 138 терминов сами дают качественные дистракторы.

Открытый ответ с оценкой LLM — отдельный **опциональный** срез позже (см. 5d-3):
переиспользует существующий `evaluate`-механизм, где `short_md` играет роль
`reference_answer` («оценивай по базе знаний сайта» — ровно как в уроках).

## Утверждённый дизайн (5d)

Решения по итогам обсуждения: **с сохранением прогресса** (бэкенд + auth),
**микс обоих типов** вопросов, **vitest** добавляем, тест **настраиваемый** с
**умными повторениями**. Работаем с зарегистрированными пользователями — у них
копится прогресс; гостевой режим не приоритетен (просто откат к «Случайно»).

### Система вопросов (ядро)
Единица — термин; из него 2 типа вопроса:
1. **определение → термин** (показываем `short_md`, выбрать имя из 4),
2. **термин → определение** (показываем имя, выбрать определение из 4; варианты-
   определения **усекаются** до первого предложения/~100 символов).

- **Внутри одного теста термин не повторяется** (каждый максимум 1 раз). Длина
  упирается в размер выбранного пула.
- **Дистракторы** — из выбранного пула, приоритет той же категории, добор из
  общего при нехватке.

### Умные повторения (по сохранённому прогрессу)
По каждому термину у юзера: `seen`, `correct`, `last_correct`, `last_seen_at`.
Корзины и веса взвешенного отбора (без повторов):

| Корзина | Условие | Вес |
|---|---|---|
| новый | `seen == 0` | 4 |
| слабый | `last_correct == false` или `correct/seen < 0.6` | 4 |
| учится | верно, но `correct < 2` | 2 |
| освоен | `correct >= 2` и последний ответ верный | 0.5 |

Плюс **штраф за недавность** (×0.3, если `last_seen_at` < ~10 мин назад).
«Освоен» = `correct >= 2` **и** последний ответ верный.

**Режимы отбора:** Умный (по умолчанию, веса) · Только новые/слабые ·
Работа над ошибками (термины с `last_correct == false`, между сессиями) ·
Случайно (равномерно).

### Конфигуратор (`/glossary/quiz` — экран настройки)
- Категории: мультивыбор (одна / несколько / все).
- Кол-во вопросов: 10 / 20 / 30 / Все (упор в размер пула).
- Типы вопросов: опр→термин / термин→опр / оба.
- Режим отбора: Умный / Только слабые / Ошибки / Случайно.
- Индикатор освоенности по выбранным категориям (прогресс-бары).

### Архитектура
- **Генерация и взвешивание — на клиенте** (`lib/glossaryQuiz.ts`, чистые
  функции под vitest, детерминизм через инъектируемый `rng`/seed): у клиента уже
  есть все термины + определения; он подмешивает статы и строит тест.
- **Бэкенд — хранение и агрегаты:**
  - user-state таблица `glossary_term_stats(user_id, term_slug, seen, correct,
    last_correct, last_seen_at)`, unique(user_id, term_slug).
  - `POST /api/glossary/quiz/result` (auth) — `[{term_slug, correct}]`, один
    upsert-транзакцией.
  - `GET /api/glossary/progress` (auth) — per-term статы + агрегаты по категориям.

### Файлы
**Backend:** модель `GlossaryTermStat`; `GlossaryStatsRepository`;
`services/glossary_progress.py` (record_results / get_progress); 2 эндпоинта в
`api/endpoints/glossary.py`; схемы; `tests/test_glossary_progress.py`.
**Frontend:** `lib/glossaryQuiz.ts` (+ `glossaryQuiz.test.ts`); хуки
`useGlossaryProgress` / `useRecordQuizResult`; страницы `GlossaryQuizSetupPage` и
`GlossaryQuizRunPage`; точки входа на `/glossary`; i18n ru/en; vitest-инфра
(devDep + `test`-скрипт + конфиг).

## Открытые вопросы (отложены — «потом подумаем»)
- Расширение конфигуратора, режим открытого ответа с LLM (бывш. 5d-3),
  интеграция слабых терминов в общую очередь повторений (`services/sm2.py`).

## Definition of done (5d)
- Бэкенд: таблица + 2 эндпоинта (auth), upsert идемпотентно агрегирует попытки;
  тесты `test_glossary_progress.py` зелёные, общий набор не падает.
- Фронтенд: экран настройки (категории/кол-во/типы/режим) → прогон → результат;
  умный отбор по прогрессу; «работа над ошибками»; индикатор освоенности на
  `/glossary`; генератор покрыт vitest (детерминизм с seed); `tsc` чисто.
- Проверено в браузере (прогон + запись результата + обновление прогресса).
