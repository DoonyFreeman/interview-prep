## 1. Что это и зачем

В уроке есть два способа проверки: «собеседование с ИИ» (открытые вопросы,
грейдит LLM) и **тест** — вопросы с 4 вариантами, проверяется мгновенно на
клиенте, без LLM. Ты пишешь контент для второго. Это закрытые вопросы, которые
должны проверять понимание материала **этого** урока.

Принцип проекта: грейдинг идёт «по базе знаний сайта». Поэтому MCQ должны
проверять то, что реально написано в уроке и в эталонном ответе концепта, а не
абстрактную эрудицию.

## 3. Формат `tests.json`

Структура: `lesson_slug → concept_slug → [массив MCQ]`. Ключи `lesson_slug` и
`concept_slug` **обязаны точно совпадать** со slug'ами из `metadata.json` этого
курса (иначе вопросы потеряются / тест целостности упадёт).

```jsonc
{
  "<lesson_slug>": {
    "<concept_slug>": [
      {
        "type": "single",            // "single" (4 варианта) | "boolean" (2: Верно/Неверно)
        "text": "Текст вопроса?",
        "options": ["...", "...", "...", "..."],
        "correct": 0,                 // 0-based индекс правильного варианта в options
        "explanation_md": "Короткое пояснение, можно `inline-code` и **markdown**.",
        "difficulty": 2               // 2..4, примерно как у концепта
      },
      { "...второй MCQ этого концепта..." }
    ]
  }
}
```

### Поля
- `type`: почти всегда `"single"` (4 варианта). `"boolean"` — изредка, для
  утверждений-ловушек; тогда `options` = `["Верно", "Неверно"]`.
- `text`: самодостаточный вопрос. Не раскрывает ответ. Без «выберите все верные»
  (мультивыбор не поддерживаем). По-русски (термины можно англ.: GIL, dict, JWT).
- `options`: для `single` — ровно **4** строки, **уникальные**, непустые.
- `correct`: индекс правильного в `options` (0..len-1). Позиция роли не играет —
  клиент **перемешивает** варианты при показе, — но для читаемости варьируй её,
  не ставь всегда `0`.
- `explanation_md`: **1 короткое предложение**, почему верно (показывается после
  ответа). Можно markdown/`код`.
- `difficulty`: 2 (база) … 4 (сложно). Ориентируйся на `difficulty` концепта в
  `questions.json`.

### Чего НЕ делать в формате
- **Не указывай `id`/`slug`** у MCQ — стабильный id (`course:lesson:concept:i`)
  выводит загрузчик автоматически по позиции в массиве. Твоё дело — порядок.
- Не добавляй ключи для несуществующих уроков/концептов (orphan-ключи).
- JSON с **литеральной кириллицей** (не `\uXXXX`), UTF-8.

## 4. Источник фактов (строго)

1. **Первично:** `questions.json` → `reference_answer` концепта. Там сжато
   сформулированы ключевые факты — почти всегда этого хватает на 2 MCQ.
2. **Если мало:** открой markdown-урок (`NN-<lesson>.md`) и возьми факты из
   секции этого концепта (H2-заголовок ≈ заголовок концепта).
3. **Не выдумывай** факты, версии, числа, API, которых нет в материале. Если в
   уроке нет точной детали — задай вопрос на то, что есть.

## 5. Правила качества (это главное)

На каждый концепт — **2 MCQ разного типа мышления**:
- **#1 «вспомнить/определение»** — что это / что верно по определению.
- **#2 «применить/отличить»** — выбрать верное утверждение среди похожих,
  следствие, типичную ошибку, «что произойдёт».

Качество вопроса:
- **Ровно один** однозначно правильный вариант. Остальные — однозначно неверные.
- **Дистракторы правдоподобны** и взяты из **типичных заблуждений** по теме (то,
  во что новичок реально верит), а не абсурд. Они должны быть «соблазнительны».
- Варианты **параллельны**: похожая длина, форма и уровень детализации (нельзя,
  чтобы правильный был заметно длиннее/«умнее» остальных — это подсказка).
- **Запрещено:** «всё перечисленное», «ничего из перечисленного», «оба варианта»,
  шуточные/очевидно-мусорные варианты, дубли по смыслу.
- Вопрос **не должен содержать ответ** и не должен зависеть от формулировки урока
  дословно — проверяем понимание, не память текста.
- Отрицания («что НЕ является…») — изредка и выделяй слово НЕ заглавными.
- `explanation_md` объясняет суть, а не просто повторяет «потому что вариант А».

Язык/стиль: как в `python-core/tests.json` — по-русски, лаконично, по делу.

### Мини-шаблон концепта (скопируй форму)
```jsonc
"<concept_slug>": [
  {
    "type": "single",
    "text": "<recall-вопрос>",
    "options": ["<верный>", "<правдоподобный неверный>", "<...>", "<...>"],
    "correct": 0,
    "explanation_md": "<1 фраза почему>",
    "difficulty": 2
  },
  {
    "type": "single",
    "text": "<apply/distinguish-вопрос>",
    "options": ["<...>", "<верный>", "<...>", "<...>"],
    "correct": 1,
    "explanation_md": "<1 фраза почему>",
    "difficulty": 3
  }
]
```

## 6. Процесс на один курс

1. Прочитай `metadata.json` курса → выпиши порядок уроков и concept-slug'и.
2. Прочитай `questions.json` курса → на каждый концепт есть `reference_answer`
   (источник фактов). Читай markdown-урок только если фактов не хватает.
3. Напиши `tests.json`: для каждого урока — объект, в нём на каждый концепт —
   массив из 2 MCQ. Сохраняй порядок концептов как в `metadata.json`.
4. Прогони валидатор (§7). Почини, если красный.
5. Переходи к следующему курсу. **Не перечитывай** этот гайд и `python-core`
   заново — экономь токены.

## 7. Валидация (после КАЖДОГО курса)

Из каталога `backend/` с активированным venv (`. .venv/bin/activate`) запусти,
подставив slug курса:

```bash
python3 -c "
from app.content.loader import load_content
C='python-data-types'   # <- slug проверяемого курса
b=load_content('../content')
c=next(x for x in b.courses if x.slug==C)
bad=[]; n=0
for l in c.lessons:
  for con in l.concepts:
    if len(con.mcqs)!=2: bad.append(f'{l.slug}/{con.slug}: {len(con.mcqs)} MCQ (нужно 2)')
    for m in con.mcqs:
      n+=1
      if m.type not in ('single','boolean'): bad.append(f'{m.slug}: тип {m.type}')
      if m.type=='single' and len(m.options)!=4: bad.append(f'{m.slug}: {len(m.options)} вариантов')
      if len(m.options)!=len(set(m.options)): bad.append(f'{m.slug}: дубли вариантов')
      if not (0<=m.correct_index<len(m.options)): bad.append(f'{m.slug}: correct вне диапазона')
      if not m.text.strip() or not m.options: bad.append(f'{m.slug}: пусто')
print('MCQ:',n,'| проблемы:', bad or 'нет')
"
```
Должно быть `проблемы: нет` и `MCQ = 2 × число концептов курса` (см. §9).
Если загрузчик бросил исключение — это битый JSON или неверные ключи: чини.

- Не дублируй пояснения и не «размышляй» в выводе сверх необходимого — основной
  бюджет на сами формулировки вопросов.

## 11. Частые ошибки (избегай)

- `concept_slug` / `lesson_slug` не совпали с `metadata.json` → вопросы
  «исчезают». Сверяйся со списком из §6.1.
- Прописал `id`/`slug` у вопроса — не нужно, удали (id выводится автоматически).
- 3 или 5 вариантов вместо 4 у `single`; дубликаты вариантов.
- `correct` указывает не на тот вариант (перепроверь индекс 0-based).
- Правильный вариант заметно длиннее/детальнее — выдаёт ответ.
- Дистракторы абсурдны → вопрос слишком лёгкий и не учит.
- Факт, которого нет в уроке/эталоне (выдумка).
- Битый JSON (висячие запятые, кавычки внутри строк не экранированы).
